验证 Agent 包自身提供一致的虚拟文件系统、Shell、VCS、Patch、Search 和 Coding Loop；验证宿主只通过最小 Bridge 即可运行；验证真实 Toolchain Provider 可选接入；验证 macOS TUI、Chrome、恢复、状态空间和生产质量。

1. 测试策略

核心问题

  • 同一 Workspace 契约是否被所有 VFS 后端正确实现。
  • Virtual Shell 是否足够稳定且不依赖宿主 Bash。
  • Snapshot VCS 是否能支持恢复、Diff、隔离和合并。
  • 宿主极简 Bridge 是否足以运行 Agent。
  • 真实工具链 Provider 是否可插拔。

测试原则

  • 先验证虚拟环境，再验证 Agent 行为。
  • 所有副作用可注入、可回放、可取消。
  • 不把 E2E 当成唯一证据。
  • Host Bridge 测试使用真实最小实现，不 mock 掉核心语义。
分层：Contract → Unit → Integration → State Space → TUI/Chrome E2E → Real Repository Benchmark → Fault/Soak → Release。

9.11 导航状态空间与穷举模型

TuiRoute =
  conversation | sessions | agents | review | status | commands | help
Focus =
  composer | transcript | overlay
Session =
  activeA | activeB | deleted-target
TaskStatus =
  queued | running | waiting | completed | failed
Children =
  none | running-tree | failed-tree
Connection =
  online | reconnecting | offline
Width =
  full | normal | narrow | emergency

有界动作：
  Ctrl+K / Ctrl+G / Ctrl+I / Ctrl+O / Ctrl+P
  Enter / Esc / PageUp / PageDown
  switch(A,B,deleted) / stop / delete / resize / disconnect / reconnect

主不变量：
  同一时刻只有一个 active route 和一个 overlay
  activeSessionId 与 ProjectionCache 的 sessionId 一致
  logEpoch + subscriptionGeneration 不匹配的帧不改变 UI
  导航和订阅变化不调用 stopSession
  Session 草稿、附件、选择和滚动按 ID 隔离
  P0/P1 状态在任何宽度都可见
  永久状态栏 1 行；不存在永久侧栏
  扩展贡献不超过状态栏预算
  危险操作未收到 ACK 前不显示成功
  后台完成不抢 Composer 焦点
  Overlay 关闭后草稿和滚动锚点不丢

对 7 routes × 3 focus × 3 sessions × 5 task statuses × 3 child states × 3 connection states × 4 widths 做有界 BFS/组合枚举（约 11k 个离散状态，实际用 pairwise 降维并保留关键三元组），每个 Action 生成前后状态和 UI invariant 断言；随机测试由 fast-check 补充序列与 seed。失败保存完整按键序列、Projection trace、Session ID、宽度、生成状态和最终终端网格。

9.12 PTY、Golden 与无障碍测试实现

PTY Harness

Node/macOS 测试通过真实 PTY 启动 TUI，注入按键和 resize；测试进程退出时清理 PTY、子进程和临时存储。

终端网格

使用 headless terminal emulator 解析 ANSI 输出为 rows×columns，再断言 cursor、空白、截断、颜色关闭和滚动区域。

Golden

固定 Session 名、时间和 Agent 结果；归一化非确定性 ID/耗时后比较 80×24、60×20、120×40 网格。

14. CI 与发布门禁

层级内容阻断
PR FastCore boundary、VFS Contract、Shell Unit、VCS Unit、state short是
PR TUITUI smoke、恢复、Diff、取消是
PR ChromeChrome E2E 核心与竞态是
Nightlydeep state、多环境 Host、Provider、Benchmark 子集报告趋势
Release完整 Benchmark、8h soak、迁移、故障和资源泄漏是

正式发布必须满足

  • MemoryFS、OverlayFS 和 PersistentFS 通过同一 Contract。
  • Virtual Shell 支持子集稳定，不依赖宿主 Bash。
  • Snapshot VCS 支持 Diff、恢复、Fork 和 Merge Preview。
  • 无 FileSystem/Git/Bash 的宿主也能运行 Agent Core 和虚拟编辑。
  • 真实 Toolchain Provider 可选接入且失败不损坏 Workspace。
  • TUI 与 Chrome 主流程通过；Session/Workspace 可恢复。
  • 所有完成声明都有 Verification Gate。
  • 无密钥泄露、未审阅自动提交或未授权网络写入。
  • 大仓库、长任务和 Provider 故障通过 Soak。
生产的定义：Agent 自己拥有稳定的开发环境语义，宿主可极简；复杂项目通过可选 Provider 获得真实工具链能力；用户始终可以审阅、恢复和导出变更。
