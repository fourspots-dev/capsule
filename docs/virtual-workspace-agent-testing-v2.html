1. 测试策略

核心问题

  • 同一 Workspace 契约是否被所有 VFS 后端正确实现。
  • Virtual Shell 是否足够稳定且不依赖宿主 Bash。
  • Snapshot VCS 是否能支持恢复、Diff、隔离和合并。
  • 宿主极简 Bridge 是否足以运行 Agent。
  • 真实工具链 Provider 是否可插拔。

测试原则

  • 先验证虚拟环境，再验证 Agent 行为。
  • 所有副作用可注入、可回放、可取消。
  • 不把 E2E 当成唯一证据。
  • Host Bridge 测试使用真实最小实现，不 mock 掉核心语义。
分层：Contract → Unit → Integration → State Space → TUI/Chrome E2E → Real Repository Benchmark → Fault/Soak → Release。

12. 状态空间与并发

Workspace:
  files ≤ 4
  revisions ≤ 3
  providers ≤ 2
  task status
  command status
Tabs:
  tabs ≤ 3
  groups ≤ 2
  sessions ≤ 2
Events:
  edit / command / checkpoint / restore
  fork / merge / close / provider-fail
不变量:
  文件写入原子且 Hash 一致
  一个 Tab 一个 Binding
  一个 Group 一个 Session
  Workspace revision 单调
  Command 结果不被重复应用
  子 Agent 不越界写

使用有界穷举、fast-check 参考模型、故障注入和真实 TUI/Chrome E2E。失败导出 seed、事件 trace、前后 Workspace Manifest、Session revision 和 Provider 结果。

13. 生产评测、性能与 Soak

Benchmark

Bug Fix、Feature、Test Addition、Refactor、Repo Understanding、多语言和大型仓库任务。

质量指标

任务完成率、测试通过率、误完成率、回归率、平均修复轮次、人工干预和成本。

性能

10k 文件搜索、1GB Workspace、10 万行日志、大 Diff、启动和流式渲染。

Soak

8 小时多任务、反复恢复、Provider 重启、内存、句柄和进程泄漏。

14. CI 与发布门禁

层级内容阻断
PR FastCore boundary、VFS Contract、Shell Unit、VCS Unit、state short是
PR TUITUI smoke、恢复、Diff、取消是
PR ChromeChrome E2E 核心与竞态是
Nightlydeep state、多环境 Host、Provider、Benchmark 子集报告趋势
Release完整 Benchmark、8h soak、迁移、故障和资源泄漏是

正式发布必须满足

  • MemoryFS、OverlayFS 和 PersistentFS 通过同一 Contract。
  • Virtual Shell 支持子集稳定，不依赖宿主 Bash。
  • Snapshot VCS 支持 Diff、恢复、Fork 和 Merge Preview。
  • 无 FileSystem/Git/Bash 的宿主也能运行 Agent Core 和虚拟编辑。
  • 真实 Toolchain Provider 可选接入且失败不损坏 Workspace。
  • TUI 与 Chrome 主流程通过；Session/Workspace 可恢复。
  • 所有完成声明都有 Verification Gate。
  • 无密钥泄露、未审阅自动提交或未授权网络写入。
  • 大仓库、长任务和 Provider 故障通过 Soak。
生产的定义：Agent 自己拥有稳定的开发环境语义，宿主可极简；复杂项目通过可选 Provider 获得真实工具链能力；用户始终可以审阅、恢复和导出变更。
