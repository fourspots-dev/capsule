Workspace 资源路径与宿主交互

把 Workspace 作用域、相对路径、资源身份、宿主打开/导出能力和应用验证拆成独立契约。Chrome 只实现自己的 Adapter，其他宿主共享同一套语义。

1. 问题、范围与需求

当前 Chrome 所有标签共用一个扩展级 VFS，但 UI 和 Session 暴露标签组/独立标签作用域。Agent 又只能看到相对路径和“virtual workspace”工具描述，无法预先知道该路径不是宿主路径。因此会出现跨任务文件泄漏、file:// 尝试、把源码注入无关页面验证以及写入成功但任务 Failed。

需求目标优先级
REQ-WORKSPACE-003稳定 Workspace Scope、Generation、相对路径和 ResourceRef。P0
REQ-HOST-004宿主无关的 Open/Export Port、能力发现和生命周期。P1
REQ-CHROME-002Chrome 标签组/独立标签 Workspace、预览和下载实现。P0
REQ-VERIFY-002打开资源与验证应用分离，按宿主生成可审计 Evidence。P0
非目标：不把 Chrome tab/group/download 抽象塞进 Core；不实现任意宿主机写权限；不保证所有宿主支持交互式预览；不把成功打开页面等同于应用验证通过。

3. 路径与资源身份

type WorkspacePath = string & { readonly __workspacePath: unique symbol };

interface WorkspaceScope {
  workspaceId: string;
  kind: 'group' | 'tab' | 'session' | 'global';
  displayName: string;
  generation: number;
}

interface WorkspaceResourceRef {
  workspaceId: string;
  path: WorkspacePath;
  generation: number;
}

interface WorkspaceResourceDescriptor extends WorkspaceResourceRef {
  resourceUri: `workspace://${string}/${string}`; // opaque, never navigable
  mimeType: string;
  size: number;
  version: number;
  openable: boolean;
  exportable: boolean;
}

Agent 可见规则

  • path 始终相对当前 Workspace，使用 POSIX /。
  • 根目录仅在列举工具中表示为空字符串或 .。
  • 拒绝绝对路径、scheme、各类 drive prefix、..、NUL/控制字符和 URI 编码逃逸。
  • 大小写保留且敏感；Unicode 统一 NFC；保留空格和合法 Unicode 文件名。
  • workspace:// 仅作内部资源标识，禁止传给 Browser navigate。
  • write_file 返回 Descriptor，而非裸路径。
兼容：首轮保留工具参数 path: string，解析后转换为 branded path；不要求模型发送 workspaceId。workspaceId 和 generation 由当前 Session 自动绑定。

4. REQ-WORKSPACE-003：Scope 与 Path

P0 Design review

Scope 模型

Chrome 标签组成员共享一个 Workspace；组外独立标签拥有自己的 Workspace。Workspace 身份用持久 UUID，Chrome windowId/groupId/tabId 只存在于 Binding Adapter。

interface ChromeWorkspaceBinding {
  workspaceId: string;
  scope: 'group' | 'tab';
  windowId: number;
  groupId?: number;
  rootTabId: string;
  memberTabIds: string[];
  revision: number;
}

生命周期

事件行为
首次激活组/独立标签惰性创建 Workspace 与 binding
组内切标签Workspace 和 Session 不变，只更新 active target
标签加入/移出组重新解析 Scope；禁止静默复制或合并文件
groupId 失效/重启依据 root/member 快照恢复或创建新 scope，不猜测已删除 scope
关闭最后成员binding 失效，Workspace 进入可恢复历史，不立即删除

模块影响

  • 修改 src/virtual/path.ts 与 VFS 路径入口，集中路径验证。
  • 新增 src/platform/workspace-scope.ts 和 workspace-resource.ts。
  • 拆分 chrome-runtime.ts 的单例 VFS 创建，改由 binding 惰性获取。
  • Session Snapshot 只保存 workspaceId，不保存 Chrome 身份。

验收

  • 两个无关 Workspace 相互不可 list/read/write。
  • 组内标签看到同一资源；独立标签看不到组资源。
  • 所有工具结果包含 workspaceId、path 和 generation。
  • 旧全局 Workspace 有迁移计划，不静默丢弃文件。

5. REQ-HOST-004：Workspace Interaction Ports

P1 Design review

interface WorkspaceInteractionCapabilities {
  open: {
    available: boolean;
    modes: Array<'embedded-preview'|'external-window'|'native-app'|'handoff'>;
    mimeTypes?: string[];
  };
  export: {
    available: boolean;
    destinations: Array<'download'|'host-path'|'share'>;
  };
}

interface WorkspaceOpenPort {
  capabilities(): Promise<WorkspaceInteractionCapabilities['open']>;
  open(input: {
    resource: WorkspaceResourceRef;
    intent: 'preview'|'edit'|'debug';
    ephemeral: boolean;
  }, signal?: AbortSignal): Promise<{
    mode: string;
    targetId?: string;
    resource: WorkspaceResourceRef;
  }>;
  close?(targetId: string): Promise<void>;
}

interface WorkspaceExportPort {
  capabilities(): Promise<WorkspaceInteractionCapabilities['export']>;
  export(resource: WorkspaceResourceRef, signal?: AbortSignal): Promise<{
    artifactId: string;
    displayName: string;
    bytes: number;
  }>;
}
HostOpenExport必需约束
Chrome隔离扩展预览标签Downloads不暴露扩展存储或宿主路径
TUI内置 viewer / OS editorHost FS bridgeHost FS 必须显式授权
Headless不可用Artifact/output sink不注册交互工具
iOSWKWebView/Quick LookFile Picker/Share Sheet无 Process、无绝对路径
SandboxHost UI bridgeTransfer Artifact不突破沙箱边界

能力由 Provider Registry 探测，ToolPack 和 Prompt 只消费结果。Open/Export 不授予权限；风险与审批仍由现有 Policy 处理。

错误码

WORKSPACE_RESOURCE_NOT_FOUND
WORKSPACE_SCOPE_MISMATCH
WORKSPACE_OPEN_UNSUPPORTED
WORKSPACE_EXPORT_UNSUPPORTED
WORKSPACE_OPEN_CANCELLED
WORKSPACE_EXPORT_COLLISION
WORKSPACE_RESOURCE_STALE

验收

  • 相同接口可由至少 Chrome 与一个非 Chrome fake/host 实现。
  • 未注册能力的 Host 不暴露对应工具或 Prompt 文案。
  • 取消后不留下预览 target 或部分下载。
  • 低层结果不包含 Chrome 专属字段。

6. REQ-CHROME-002：Chrome Scope、Preview 和 Download

P0 Design review

引导与预览

Agent path: minesweeper.html
  → current Workspace resolver
  → ResourceRef
  → ChromeWorkspaceOpenPort
  → chrome-extension://<id>/workspace-preview.html?token=...
  → isolated preview tab

Agent: open_workspace_file({path:"minesweeper.html", intent:"preview"})
  → {mode:"embedded-preview", targetId:"123", resource:{...}}

预览页必须通过 runtime token/resource id 读取 VFS，不把用户源码注入无关标签，不接受模型构造的绝对扩展 URL。HTML/JS/CSS 按 MIME 和隔离策略加载。

导出

export_workspace_file 读取 ResourceRef、校验 generation、生成 Blob，并通过 chrome.downloads 下载。只有导出完成后 Agent 才能说“可在本机打开”。

Workspace 生命周期

  • 绑定 TabSessionRegistry 的 group/tab scope，不再使用单例全局 VFS。
  • 组内成员共享 Workspace；独立标签完全隔离。
  • 迁移旧 tinyai:virtual-workspace:v1 时创建 Legacy Workspace，并让首个绑定显式接管；不自动复制到多个组。
  • 预览 target 是 ephemeral workspace target，不改变 executionTabId，除非用户/Action 显式切换。

UI

复用现有 Side Panel workspace 行和 Tool row，不增加卡片。显示 `workspace name · group/standalone`；资源打开和导出以普通 Tool row 展示，文件名可点击但链接由 Runtime 生成。

验收

  • file:// 尝试被明确拒绝并提示使用 preview tool。
  • 真实预览加载的字节与 read_file 一致。
  • 两个标签组无法看到对方文件。
  • 导出文件可由 OS 打开；虚拟文件不再被描述为宿主文件。

7. REQ-VERIFY-002：宿主感知应用验证

P0 Design review

Open 只证明资源被宿主加载，不证明应用正确。新增通用 Observation 和 Verifier，而 CompletionGuard 根据 capability 选择验证策略。

interface WorkspaceAppObservation {
  kind: 'browser-app'|'process-test'|'native-smoke'|'manual';
  resource?: WorkspaceResourceRef;
  workspaceGeneration: number;
  loaded: boolean;
  consoleErrors: string[];
  assertions: Array<{name:string; passed:boolean; detail?:string}>;
  screenshotArtifactId?: string;
  createdAt: number;
}

interface WorkspaceVerificationGuard {
  verify(context: CompletionGuardContext): Promise<{
    ok: boolean;
    reason?: string;
    evidenceId?: string;
  }>;
}
Host/工作类型所需证据
Chrome HTML/JS 应用预览 loaded、无未解释 console error、关键 DOM/交互断言、截图
Chrome 普通文档编辑读取回写 hash 或资源预览，不要求 TestReport
TUI/Headless 代码Application Action TestEvidence
iOSNative smoke/handoff observation
无验证能力任务可结束为 completed-with-limitations，不得伪造 passed
禁止：用 evaluate 把源码注入任意用户页面作为验证；用 open 成功替代全部断言；使用写入前 generation；Open 后再修改文件仍判 current。

验收

  • 独立应用只在真实 ResourceRef 预览与断言通过后完成。
  • stale generation、console error、失败 assertion 阻断 completed。
  • TUI Portable Action 验证行为不回归。
  • 任务回答明确引用实际 evidence，不声称“双击可用”而未经 export。

9. 失败、取消、恢复与兼容

  • Scope 在操作中变化：返回 WORKSPACE_SCOPE_MISMATCH，不猜测新 scope。
  • 文件 generation 变化：Open/Export/Evidence 返回 stale。
  • 预览 target 关闭：资源仍在 VFS，可重新 open；不视为文件删除。
  • 下载取消：删除临时 Blob/Artifact，Task 显示 cancelled。
  • Service Worker 重启：从 binding store 恢复 scope；ephemeral preview 允许失效。
  • 旧全局 Workspace：迁移前备份；由用户选择接管 scope，无法自动归属时进入 Legacy Workspace。
  • Capsule 导入：workspaceId 映射为新的稳定 ID，Host binding 不入 Capsule。
