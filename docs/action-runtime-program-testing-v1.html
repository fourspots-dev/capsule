1. 测试策略

必须证明

  • Action 来自受信 Provider 且 Probe 成功。
  • 模型只看到已启用 Action。
  • ask/deny 无法绕过。
  • 本机/Remote/Native 协议结果一致。
  • TestReport 与当前 Workspace/environment 绑定。
  • 失败、取消、宿主断连不会产生假成功。

拒绝的假成功

  • 只看进程 exitCode。
  • Provider 返回 exit 0 但 TestReport 无效。
  • ask 被拒绝后换 exec 完成。
  • Remote 重连后重复执行危险 Action。
  • 历史 Action 验证新文件。
P0：未受信代码执行、审批绕过、进程树残留、Secret 泄漏、无 TestReport 却 completed 任一发生即阻止发布。

12. 端到端用户旅程

TUI 启动
→ 加载受信 Provider
→ 显示 available Actions
→ 模型写文件
→ 请求 app.*.check
→ 用户批准
→ 本机/Remote 执行
→ TestReport current
→ TUI 显示 pass/fail
→ 导出 Capsule
→ Chrome 导入
→ Remote Provider 版本和环境变化
→ Evidence stale
→ Node 回导并重新验证

13. 发布门禁

  • npm run check 包含 Action policy/protocol 测试。
  • 真实 Node Action E2E：Python 或 npm 选一个具体应用。
  • TUI ask/approve/deny 伪终端 E2E。
  • Remote cancel/reconnect E2E。
  • Chrome 无 Action 时无 shell fallback。
  • TestReport/Evidence/Artifact 完整性门禁。
  • 安全用例零失败。
