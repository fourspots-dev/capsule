TINYAI / TEST INFRASTRUCTURE / DESIGN

Chrome for Testing E2E 基线

统一浏览器选择、可复现 CI、headed 本地验证和 Stable Chrome 发布冒烟。

1. 问题与目标

此前每个 E2E 文件重复查找硬编码 CfT 路径，并在缺失时静默使用 Stable Chrome，导致无法从结果判断实际浏览器。目标是让 CfT 成为唯一默认基线。

2. Architecture impact

Production Runtimenone
E2E Harnessadd shared tests/harness/chrome-e2e.ts
All E2E specsmodify launcher usage
package scriptsCfT, headed, stable and auto profiles
CI gatetest:e2e strictly CfT

3. Browser profiles

npm run test:e2e          CfT + headless
npm run test:e2e:headed   CfT + visible window
npm run test:e2e:stable   Stable Chrome + headless smoke
npm run test:e2e:auto     diagnostic only: CfT then Stable

CHROME_FOR_TESTING_PATH、TINYAI_CHROME_EXECUTABLE 可覆盖路径；默认缺少 CfT 时直接失败，不回退 Stable。

4. Resolution and lifecycle

显式路径优先；否则读取 Playwright 期望路径，然后扫描 ms-playwright/chromium-* 最新版本，支持 macOS arm64/x64、Linux 和 Windows。每个 E2E 使用同一扩展启动参数和临时 profile。

5. Acceptance

  • 所有 E2E 使用共享 launcher。
  • 默认门禁运行 CfT headless。
  • headed 模式可用。
  • Stable Chrome 独立运行。
  • 文档和 scripts 可发现。
