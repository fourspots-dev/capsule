1. 问题与目标

Side Panel 曾通过局部模板字符串新增视觉控件，导致原生边框、重复卡片、表单圆角不一致和子页返回路径不统一。用户明确要求不在 AGENTS.md 中直接添加项目 UI 约束。

目标

  • 建立可版本化的 Side Panel UI Contract。
  • 提供 Settings 专用组件原语。
  • 用静态、单元和真实 Chrome E2E 检查构成与计算样式。
  • 在需求和架构模板中加入 UI 影响面。
  • 不修改 AGENTS.md。

非目标

  • 重做整个 Side Panel。
  • 改变会话、Action、Capsule 或 Runtime 协议。
  • 引入新的 CSS 框架或构建链。
  • 只依赖像素截图判断正确性。
  • 让所有 UI 组件都进入通用设计系统；本需求只覆盖 Side Panel Settings。

settings-components.tsSide Panel presentation layer集中拥有 Settings class、转义、button/div 选择和 header 结构。
kernel-panel.tsPage orchestration只提供页面数据、action id、control markup 和状态，不直接拼粗粒度设置卡片。
check:uiEngineering gate发现 kernel-panel.ts 重新出现 raw settings primitives 时失败并指向 Contract。
Requirement templatesEngineering process任何 UI 需求记录复用组件、新增原语、响应式和证据。

5. 模块交互

Settings action
  → kernel-panel computes view model/control markup
  → settings-components emits canonical HTML
  → settings CSS tokens determine interaction
  → E2E checks structure + computed style + navigation

New UI requirement
  → requirement template asks for UI impact
  → design links this Contract
  → developer reuses components
  → check:ui fails on raw primitives
  → Chrome E2E fails on style/navigation drift

组件接受已构造的 control HTML，用于 select、stepper、hidden file input 等现有控件；label、value、aria 等文本由组件转义。

6. 生命周期与导航状态

HomeSettings 首页，只显示分组和入口。
Connections / History / Capabilities / Remote Actions设置子页；back 到 Settings。
Settings Back关闭 page layer，返回会话。
Action failure保持当前子页和已输入状态，显示 wb-notice-error。
Runtime reload保留 pageView；完成后重绘当前页面。

7. 失败行为与兼容

  • 缺少组件参数时 TypeScript 在构建期失败。
  • 原始 settings class 出现在 kernel-panel.ts 时 check:ui 失败，并输出 Contract 路径。
  • E2E 计算样式偏差会指出具体 selector 和期望 token。
  • 组件迁移不改变 action id、DOM 文本、页面状态和持久化 schema。
  • 构建后只保留 canonical component 路径，不保留 feature flag 或旧页面模板。

8. 实施顺序

  1. 登记 DEC-010、ADR-016、REQ-UI-001 和 Contract。
  2. 添加 Settings 组件与单元测试。

  5. 更新需求/架构/测试模板。
  6. 执行全量检查、截图审阅、发布 0.11.0。

9. 验收

  • AGENTS.md 无改动。
  • Settings 页面不存在 raw wb-set-card/group/row 拼接。
  • 所有子页经过 Settings 返回。
  • 导航按钮无原生边框，表单输入风格一致。
  • 420px 和 320px 无横向溢出。
  • npm run check 437 passed / 3 skipped，npm run test:e2e 7 passed，人工截图审阅通过。
