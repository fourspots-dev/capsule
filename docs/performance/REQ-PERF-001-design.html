Agent 内存有界化

修复长任务中 token 触发的全量 Projection、全量 DOM、全量持久化和无界缓存叠加，建立可验证的内存不变量。

REQ-PERF-001P0 verifiedTarget 0.12.0ADR-018

1. 事故与证据

实测一个 Chrome extension renderer 达到约 2.58GB RSS，用户报告任务累计至约 11GB。代码审查确认多条放大路径同时存在：每个 reasoning/message delta 触发完整 Projection，Side Panel 重建完整 DOM，持久化周期性复制完整 Snapshot，Event Log/network/debug 缓存缺少完整边界。

判定：不是单一页面快照问题，而是流式 token × 全历史复制 × 全 DOM × 全量持久化的组合放大。

3. 核心设计

Session mutation
  → mark dirty row (only changed row snapshot)
  → touch
  → emitChanges
      state.updated (small)
      row.appended | row.delta | row.upserted | row.removed
  → RuntimeGateway port frame directly
  → ProjectionStore mutates current row
  → Side Panel coalesced render

SessionProjectionChange

interface SessionProjectionChange {
  sessionId, logEpoch;
  baseRevision, revision, eventSeq;
  deltas: ProjectionDelta[];
}

初始订阅仍返回一次完整 Projection。此后流式 token 只携带本 revision 的增量。若没有 change/full listener，不构造 Projection。

Dirty row 语义

  • 新增 Row 只 clone 新 Row。
  • 文本追加且其他字段不变时发送 row.delta。
  • 状态、tool metadata 或非前缀文本变化时发送一次 row.upserted。
  • 每条 change 后清空 dirty set。

5. 生命周期与交互

  1. Session 创建时建立一个 projection state baseline。
  2. 每次 mutation 只标脏相关 Row。
  3. touch 后生成 change，更新 runtime revision/eventSeq。
  4. Gateway 转发 delta；客户端原地更新当前 Projection。
  5. Side Panel 合并 50ms 内的变化，只渲染最近窗口。
  6. 完成、停止、切换 Session 时仍立即同步关键 UI 和最终持久化。

6. 失败与兼容

  • Delta gap：客户端重新获取完整 Projection。
  • 旧客户端仍可通过 full subscribe 使用完整 Projection。
  • Session 被淘汰后从 SessionStore 冷恢复。
  • Event retention 不影响 row/message 内容或 SessionTree。
  • Debug 日志文本不完整时以 cursor gap/truncation 明示。
  • 未知或无法应用的 delta 触发 resync，不静默污染 UI。

7. 验收

  • 流式更新不再构造每秒多次完整历史 Projection。
  • 所有长任务缓存有明确上限。
  • 功能 E2E 与 Capsule 恢复保持兼容。
  • 压力测试中内存增长在固定窗口后趋于稳定。
  • Debug、UI、持久化和历史行为无回归。

Observed evidence: 2,000 组真实 Chrome 流式 reasoning/answer delta 完成后，GC 后 renderer heap 增量为 0 MB；458 deterministic tests、10 Chrome E2E、TUI verification 通过。
