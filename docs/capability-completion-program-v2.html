1. 总原则

底座不是 Action

Storage、FileSystem、Clock、Scheduler、Crypto、Session、Artifact、Network policy 和 Secret broker 属于 Host/Portable 基础，不允许通过 Action 提供。

Action 是叶子能力

Python test、Xcode build、Playwright、数据库迁移、部署等应用特有操作才通过 Action 接入。

需求独立验收

Host Baseline、TestEvidence、Capsule v2、LSP、子 Agent、Chrome 和评测分别建设计与测试，不合并成巨型需求。

共享组合

TUI、Headless、Chrome 使用同一 CapabilityGraph、ToolPackComposer、Action Schema 和 Evidence 规则。

缺能力显式降级

无 Execution Action 时仍可 Portable Coding，但不得运行或声称测试通过。

先证据后完成

没有当前 Workspace generation、environment fingerprint 和 TestReport 的任务不能标 completed。

本 Program 不新增通用 exec。每一层只解决自己的问题，Host Baseline 必须先于 Action 执行平台落地。

4. REQ-HOST-002：Host Baseline Matrix

Target 0.5.0 P0 Infrastructure

目标

明确每个平台的强制最小能力、Portable 补充能力、可选执行能力和启动失败/降级条件；避免把所有底座都 Action 化。

Baseline

Tier强制能力
A. Core BootStorage、Clock、Scheduler、Crypto、JS runtime primitives
B. WorkspaceFileSystemPort 或 Storage-backed Persistent VFS；WorkspacePath；原子写；迁移时的 Blob transport
C. Portable CodingVFS、Patch、Search、Diff、Portable Git、Session、Artifact、Capsule
D. Real Execution至少一个 Application Action、Native Action 或 Remote Action；非通用 shell

Profile matrix

Profile必需可选
TUI LocalA+B+CLocal Actions、Git CLI、PTY、Network、Secrets
ChromeA+B+CBrowserProvider、Remote Actions
iOSA+B+CNative Actions、Remote Actions、WebView Provider
SandboxA+B+CExecution Actions、Git、Tests、PTY
MemoryA+B+C无真实执行

禁止

  • Action 提供 Storage、FileSystem、Clock、Session 等基础能力。
  • 没有 Process 就禁止 Portable Coding。
  • 没有 Action 就注册通用 exec。
  • 平台 Adapter 把自身类型泄漏进 Core。

5. REQ-TEST-001：TestEvidence

Target 0.6.0 P0

建立 TestDiscovery、TestPlan、TestReport、Evidence Store 和当前环境验证门禁。ActionResult 只负责调用结果，Verifier 必须检查报告、文件 hash、Action 版本、environment fingerprint 和 Workspace generation。

  • 标准 TestReport：suites、passed/failed/skipped、失败 Artifact。
  • 证据状态：current/stale/failed/invalid。
  • TUI 显示失败用例和 Artifact。
  • 0 tests、报告 malformed、旧报告均不能证明完成。

6. REQ-WORKSPACE-002：Capsule Import 与流式 v2

Target 0.6.0 P0

TUI 增加导入、预览、冲突处理和恢复 Session。Capsule v2 使用流式分区、压缩、内容寻址、blob 去重和可恢复 staging，避免大 Workspace 的完整 JSON/base64 峰值。

  • 导入计划：环境、Action、路径和 Git 冲突。
  • 原子切换与崩溃 journal。
  • Evidence/Action 版本 rebind 或 stale。
  • TUI 导入后自动打开恢复 Session。

7. REQ-LSP-001：Code Intelligence

Target 0.7.0 P1

定义语言无关的 CodeIntelligencePort 和工具：diagnostics、document/workspace symbols、definition、references、hover、code actions。宿主可通过 LSP Action 注册，无 LSP 时回退到可移植文本/符号索引。

  • 首期 TypeScript/JavaScript/Python。
  • 索引按文件 hash 增量更新。
  • Rename 先生成 WorkspaceEdit，由 PatchToolPack 应用。
  • 诊断结果进入 Evidence/Review。

8. REQ-SUBAGENT-001：子 Agent Action 隔离

Target 0.8.0 P0

Action Descriptor 声明 root/fork/remote binding。子 Agent 只能调用与自身 Workspace generation 兼容的 Action；Provider 必须能针对 fork 或 remote Workspace 执行。

  • 并行子 Workspace 验证。
  • 父 Workspace 变化与子改动冲突检测。
  • 合并时绑定 child evidence。
  • 父取消向下传播并清理进程/Artifact/staging。

9. REQ-CHROME-001：Chrome Shared Composition

Target 0.9.0 P1

Chrome Runtime 改用共享 WorkspaceCapabilityComposition，移除旧工具拼接；增加 Action Board、RemoteActionProvider、Capsule UI 和 Remote execution 状态展示。

  • Chrome Browser ToolPack 与 Coding ToolPack 分离。
  • 默认无 exec/job。
  • TUI/Headless/Chrome Tool Schema Golden。
  • Action unavailable/denied/stale 一致显示。

10. REQ-PLATFORM-001：Windows/Linux/iOS Adapter

Target 0.9.0 P1

实现 Host Baseline 对应的平台 Adapter：Windows/Linux FileSystem、Action Provider 和路径语义，iOS Native File/Blob、Keychain、Action Bridge。默认 Portable Coding 不依赖原生 Process。

  • 路径大小写、盘符、保留名、symlink/junction。
  • 可执行 Action 映射与 cwd fence。
  • iOS 无本地进程时 Remote/Native Actions。
  • 跨平台 Capsule round-trip。

11. REQ-EVAL-001：生产评测与加固

Target 1.0.0 P1

建立多语言、复杂应用的 Benchmark、故障注入和 Soak。指标包括任务完成率、误完成率、首次验证通过率、修复轮数、回归率、Token/时间/Action 成本、人工接管次数。

  • Bug Fix、Feature、Test、Refactor、3D/Canvas、大型仓库。
  • Action/Remote/Capsule/Git 故障注入。
  • 进程、FD、timer、内存泄漏。
  • 发布门禁以真实证据为准。

13. Program 验收

模块化Core/TUI/Chrome不得依赖 Local Node Action Adapter
Host 底座每个 Profile 的 Baseline 有矩阵、Probe 和测试
真实执行具名 Action 可本机/Native/Remote 执行，无通用 shell
验证只有当前 TestReport/Evidence 允许 completed
迁移Capsule 双向、流式、原子并可恢复
智能LSP/符号工具提升跨文件定位与重构
并行子 Agent Action 与 Workspace generation 隔离
跨端TUI/Headless/Chrome/平台 Adapter Schema 和证据一致
生产Benchmark、Fault、Soak 达到发布门禁
