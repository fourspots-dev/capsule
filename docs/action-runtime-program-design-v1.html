REQ-ACTION-001 / APPLICATION ACTION RUNTIME / DESIGN V1

应用 Action 执行平台
与能力补全路线

把“真实执行”统一成可信 Provider 注册的具名 Action：可发现、可探测、可审批、可取消、可远程执行，并返回 TestReport、Artifact 和当前宿主 Evidence。不提供模型可直接调用的通用 shell。

2. 目标与非目标

目标

  • 应用通过可信模块或嵌入 API 注册具体 Action。
  • Action 生命周期、版本和 Probe 可观察。
  • 本机、原生桥和远程后端共享同一调用协议。
  • 所有执行都可审批、取消、幂等和回收。
  • ActionResult 与 TestEvidence 成为完成门禁的权威证据。
  • TUI、Headless、Chrome 使用同一 Action ToolPack。

非目标

  • 不提供默认通用 exec/Python/Bash 工具。
  • 不允许从不可信 Workspace 自动 import 并执行 Provider 代码。
  • 本需求不实现完整 LSP、Capsule v2、子 Agent fork Action 隔离；这些使用后续独立需求。
  • 不保证任意命令跨平台完全相同。

6. 核心对象

interface ActionProviderModule {
  apiVersion: 1;
  id: string;
  create(context: ProviderHostContext): Promise<HostActionProvider>;
}

interface HostActionDescriptor {
  id: string;
  version: string;
  title: string;
  description: string;
  inputSchema: JsonValue;
  outputSchema?: JsonValue;
  effects: Array<'read' | 'write' | 'execute' | 'network'>;
  risk: 'read' | 'write' | 'dangerous';
  timeoutMs?: number;
  workspaceBinding: 'root' | 'fork' | 'remote';
  limitations?: string[];
  probe(): Promise<ActionProbe>;
}

interface ActionResult {
  status: 'succeeded' | 'failed' | 'cancelled';
  value: JsonValue;
  exitCode?: number;
  artifactIds?: string[];
  testReport?: TestReport;
  environmentId: string;
  metrics?: {
    durationMs?: number;
    queueMs?: number;
    cpuMs?: number;
    peakMemoryBytes?: number;
  };
}
对象责任
ActionProviderModule受信模块入口，创建 Provider；不能被 Workspace 自动加载
HostActionRegistry合并 Provider、检测冲突、Probe、合并版本和限额
ActionToolPackDescriptor 到 ToolDefinition/UI/Prompt 的唯一转换
ApprovalBroker创建绑定 Session/task/generation 的批准票据
ActionInvoker校验输入、选择执行后端、发布流事件、取消
TestEvidence验证报告与当前文件/环境/generation 的关系
RemoteActionExecutor远程调用、流、取消、重连和结果验证

7. 可信注册与加载

来源规则
嵌入 API桌面/iOS 应用直接创建 Provider 并注入 Runtime；最高优先级
受信模块例如 --action-provider /opt/app/actions.mjs；路径由宿主配置或 allowlist 固定
Workspace 模块默认禁止自动加载。开发模式需显式 --allow-workspace-action-modules 并逐次审批
Remote只注册 endpoint 和允许的 action IDs；Provider 不能把任意 URL/Tool Schema 注入模型
Package scripts只能通过宿主显式映射成 Action ID，不能自动枚举后全部注册
禁止把“项目目录存在 actions.js”当成自动加载依据。项目内容不可信，加载其中代码等同于通用代码执行。

8. 执行后端

Local

Node Host 使用 argv 启动进程；cwd 必须 WorkspacePath；env allowlist；进程组取消；输出 Artifact。

Native Bridge

iOS/macOS App 根据 actionId 调用原生实现；requestId、stream、cancel、result 均 JSON 化。

Remote

Chrome/Web 通过 HTTPS Action endpoint；携带 workspace ID/generation/hash；支持上传和结果同步。

远程协议

POST /v1/actions/invoke
{
  requestId, actionId, actionVersion,
  workspace: { id, generation, manifestHash },
  input, deadlineMs
}

events:
  accepted | log | artifact | test_progress | result | error
POST /v1/actions/cancel { requestId }
GET  /v1/actions/{requestId}

远程 Action 不接受裸 command 字符串。取消和重连使用 requestId；非幂等 Action 不能自动重试。

9. 审批

Invocation requested
  → validate schema
  → policy: allow | ask | deny
  → ask: Approval Ticket
      sessionId + taskId + generation + actionId/version
      normalized input preview
      effects + risk + workspace binding + network/secret scopes
  → approve once | deny | cancel
  → invoke
  • 批准不能扩展到不同 Action、不同 generation 或不同输入 digest。
  • auto 模式仍然执行 PolicyEngine；network/secret 可单独要求审批。
  • 宿主迁移、Capsule 导入和版本变化使旧批准失效。
  • TUI 审批弹层不阻塞其他 Session 的只读观察，但该 Task 进入 waiting。

10. TestReport 与 Evidence

interface TestReport {
  runner: string;
  total: number;
  passed: number;
  failed: number;
  skipped: number;
  durationMs: number;
  failures: Array<{
    suite?: string;
    test: string;
    message: string;
    artifactId?: string;
  }>;
  fileHashes: Record<string, string>;
}
状态条件
currentAction 成功、报告有效、文件 hash 与 environmentId 匹配
staleWorkspace、Action 版本、环境或文件 hash 已变化
failedAction 失败、TestReport 有 failure 或退出异常
invalid报告缺字段、数量不一致或 Artifact 缺失
exitCode=0 不等于测试通过；必须存在有效 TestReport，且 0 个测试默认不能证明完成。

12. 失败、取消、重试与恢复

场景行为
Probe 失败Action unavailable；Prompt/UI/ToolRegistry 同步隐藏或标记
Schema 不合法不调用 Provider；返回 ACTION_INPUT_INVALID
审批拒绝返回 denied；可重新规划，不得换工具绕过
Timeout/Abort发送 cancel，等待资源回收；结果 cancelled
进程/远端崩溃状态 unknown；危险 Action 不自动重试
宿主断连requestId 可查询；重连后重新 Probe；旧审批失效
报告 malformedEvidence invalid；Verifier 阻止完成
版本变化旧 Schema/批准/证据标 stale；重新发现 Action

13. 能力补全路线

本需求只交付 Action Runtime。后续能力独立登记，避免巨型需求无法验收。

  • ask/auto/deny 审批。

14. 确认项与完成定义

DECISION-01

真实执行只通过具名 Provider Action；不新增通用 exec。

DECISION-02

Provider 模块必须来自受信来源；Workspace 代码默认不可自动加载。

DECISION-03

本地、Native、Remote 后端共享 ActionResult 和 TestReport。

DECISION-04

后续 LSP、Capsule v2、子 Agent 隔离拆成独立需求。

维度完成标准
Provider生命周期、版本、Probe、重连和 dispose 有测试
执行Local/Native/Remote 统一协议，取消和输出上限通过
审批ask/auto/deny 与 generation 绑定，旧批准失效
证据TestReport、Artifact、environmentId、file hash 可用
跨端TUI/Headless/Chrome 使用同一 Action ToolPack
安全不可信模块、Secret、网络和路径边界通过
追踪需求、设计、测试、提交和发布关联完整
