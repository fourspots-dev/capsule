实施原则

本轮坚持

  • Command 是会话变更唯一入口。
  • SessionLifecycle 与 TaskStatus 分离。
  • Runtime 事实先持久化，再返回成功 ACK。
  • Projection 是 UI 唯一会话输入。
  • Fake 先验证控制流，再接真实环境。
  • 现有 0.1 扩展持续可构建，新内核独立演进。

本轮不做

  • 不先接 Side Panel 或重写 UI。
  • 不把 Researcher/Reviewer 写死成角色。
  • 不在没有 BrowserProvider 契约前迁 Chrome 工具。
  • 不先做容器沙盒与写型 Coding Agent。
  • 不以完整模型文本作为测试真值。

首个垂直切片

一条命令从入口一直走到可观测的产品事实，且整个过程可运行于 Node。

01 COMMANDcommandId + revision + payload
02 RUNTIMElifecycle / ledger / FIFO
03 AGENT LOOPfake model → tool → model
04 EVENT LOG连续 seq，快照可恢复
05 PROJECTIONrows / phase / availability
WorkspaceRuntime.command(envelope)
  -> ensureSessionReady
  -> CommandInbox (dedupe + FIFO)
  -> InputLedger.admit
  -> TaskStatus: queued -> running
  -> AgentLoop
       -> ModelTransport.stream
       -> ToolExecutor (schema + policy + signal)
  -> EventLog + rows
  -> ProductProjection
  -> CommandAck
