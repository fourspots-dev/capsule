Portable Workspace Capsule
与跨宿主连续性设计

把项目内容、Agent 会话、任务、版本历史、Artifact、验证证据和应用动作要求封装为一致、可校验、可迁移的 Workspace Capsule。宿主只负责传输字节和提供命名能力；工作区语义、导入编排和恢复对账始终属于 tinyai。

1. 目标与语义

目标是在宿主机 A 导出一个 tinyai Workspace，在宿主机 B 导入后继续同一 Workspace、Session 和 Task 上下文，不丢失已确认文件、对话、任务、版本历史、证据与可恢复 Artifact。

“无缝继续”包括

  • 相同稳定 Workspace ID 与 Session ID。
  • 项目字节、Git 状态、会话树和 TaskGraph 完整迁移。
  • 历史证据可审阅，当前能力和失效证据明确标示。
  • 导入后 Agent 可立即从最后安全边界继续。
  • Host 能力不同会显式降级，不产生隐式行为变化。

“无缝继续”不包括

  • 迁移操作系统内存中的运行进程、PTY、网络连接或 lease。
  • 让 macOS、Linux、Windows 上的任意构建/测试结果必然相同。
  • 迁移明文 Secret、浏览器登录态或其他不可转移凭据。
  • 迁移宿主机绝对路径、用户目录、设备 PID 或 socket。
  • 把 Chrome Tab ID、终端尺寸等客户端 UI 状态当作 Core 真相。
迁移单位是 Workspace Capsule，不是散落的 storage key，也不是一个只有项目文件的 ZIP。Capsule 必须能够独立表达“这个 Workspace 在导出边界上是什么状态”。

领域已有基础缺口
项目文件WorkspaceBundle 与虚拟文件系统只含文件/目录；无 Capsule manifest、分区和完整性根
SessionSessionSnapshot 已是 JSON没有统一导出导入编排；运行中 Task 无跨宿主对账规则
VCSSnapshotVcs、快照和对象Bundle 只有 revision 字符串，未携带 snapshot/object 数据
GitSandbox 可运行 GitNode 项目导入跳过 .git，工作树/index/history 未形成迁移契约

4. 设计原则

一个一致性单位

项目、会话、VCS、Artifact 和环境要求共享同一个 generation，不能各自导出后拼装成不一致状态。

文件字节优先

代码是权威内容。mtime、mode、Git index 等元数据用于行为恢复，但不能替代文件 hash。

安全边界恢复

跨宿主恢复不是进程复制，而是在已终止的最后一个安全边界恢复逻辑任务。

导入先验证

任何写入现有 Workspace 之前完成 schema、hash、路径、版本、空间和能力检查。

环境差异可见

旧证据保留但按 compatibility 标记 current/stale/invalid，模型不能把 stale 当当前测试通过。

客户端状态次级

Tab、面板、光标和 TUI 选择不参与 Agent 正确性，也不能阻止核心恢复。

6. Capsule 格式

interface WorkspaceCapsuleManifest {
  format: 'tinyai.workspace.capsule';
  schemaVersion: 1;
  capsuleId: string;
  workspaceId: string;
  generation: number;
  createdAt: number;
  producer: {
    agentVersion: string;
    hostProfile: string;
    environmentId: string;
  };
  partitions: {
    project: CapsulePartitionRef;
    repository?: CapsulePartitionRef;
    agentState: CapsulePartitionRef;
    artifacts?: CapsulePartitionRef;
    evidence: CapsulePartitionRef;
    environment: CapsulePartitionRef;
    clientState?: CapsulePartitionRef;
  };
  integrity: {
    algorithm: 'sha256';
    rootDigest: string;
  };
}
分区内容策略
project规范路径树、文件对象、目录、symlink 描述、mode hint必须；内容 hash 可独立读取
repositoryPortable VCS 对象、可选 Git refs/index/HEAD存在仓库时应有；不支持时明确 warning
agentState所有 SessionSnapshot、active leaf、TaskGraph、父子关系、审批计划必须；恢复后重新建立 runtime
artifacts测试日志、Diff、截图、大输出及 metadata可转移引用必须闭合；Secret 不进入
evidence命令、退出码、报告、文件 hash、environmentId、status必须；环境变化后可标记 stale
environmenttoolchain 要求、lockfile、测试 recipe、平台映射限制必须；不包含本机绝对路径
clientStateTUI 视图、面板、Chrome Tab binding可选；不保证可恢复

完整性

  • 每个 blob 和分区记录 SHA-256；manifest 再记录根 digest。
  • 导入先校验内容，再做 schema migration；拒绝重复路径、悬空引用和缺分区。
  • JSON 只承载 manifest 与小对象；大文件、Artifact 和 Git object 使用二进制分区。

7. 状态分类与迁移策略

状态处理导入后语义
已提交项目文件完整复制并 hash 校验直接可用
未提交工作树复制当前字节，不依赖 Git mtime 判断继续编辑
Session 对话/树/任务原 ID 导入同一 Session 继续
已完成 ToolResult保留历史并关联 Artifact可作为历史，不自动成为当前环境证据
已接受未完成命令导出为 unknown/interruption record不自动重放危险请求
运行中的模型 Turn取消并记录中断点从最后确认消息重试/继续
运行中应用动作/Job/交互会话导出前终止；保存日志和退出原因标记 interrupted，不恢复应用内部运行资源
待审批不迁移批准；只保留请求描述新宿主重新评估与请求
Secret/Lease不导出按 scope 重新获取
UI binding可选导出无法恢复时回退默认视图

8. WorkspacePath 与跨平台文件语义

WorkspacePath =
  NFC(UTF-8), '/'-separated, relative,
  no leading '/', no drive prefix, no '.'/'..',
  never '.tinyai' control namespace
问题设计规则
大小写导入清单检测 case-fold 冲突；目标 FS 大小写不敏感时预先失败或生成明确 mapping
Unicode路径规范化为 NFC；检测规范化后冲突，不按显示字形合并
Windows 名称拒绝盘符、UNC、控制字符和 CON/NUL/COM1 等保留名对可迁移 Capsule 的污染
Symlink显式记录相对 target；越界、绝对 target 或目标宿主不支持时产生阻断/降级，不静默跳过
Mode/ACLPOSIX mode 是 hint；ACL、owner、xattr 默认不迁移；executable 通过明确字段表达
时间mtime 是可选展示元数据；并发和 Patch 冲突以内容 hash/version 为准
换行文件按字节保存，不自动 CRLF/LF 转换
大小写重命名不得因目标 FS 大小写策略把 rename 静默变成 no-op
Agent 只看到 WorkspacePath。宿主 absolute path 由 Adapter 在边界内解析；文件内容中原有的平台字符串属于项目内容，不做语义清洗。

10. 导出流程

export(workspaceId)
  → validate active session/workspace
  → TransferBarrier.begin()
      → stop command admission
      → cancel execution / PTY / network / running subagents
      → wait for terminal cleanup
      → flush Session / VCS / Artifact / Evidence
      → seal WorkspaceGeneration
  → collect partitions
  → compute blob hashes + manifest rootDigest
  → write temporary capsule
  → verify re-read
  → publish through HostTransportPort
  → send export completion event

导出不是“随便列出当前 storage key”。各领域通过 CapsulePartitionProvider 枚举自己拥有的数据，避免把 Secret 或宿主私有配置误装进 Capsule。

导出失败点行为
仍有不可终止进程失败并返回 blocker；不生成“可能包含运行状态”的 Capsule
Session flush 失败中止导出，Workspace 恢复可写，报告 persistence error
Artifact 引用缺失默认阻断；明确选择 historical-only 时可导出 excluding-artifact warning
传输中断目标 Capsule 不完整；manifest/rootDigest 校验失败

11. 导入流程与原子性

stageImport(capsuleStream)
  → receive to staging blob
  → verify manifest + partition hashes
  → validate schema and migrate metadata
  → preflight WorkspacePath compatibility
  → resolve destination capabilities / available actions
  → materialize project/repository/artifacts into staging
  → load sessions/tasks/evidence into staging
  → build RecoveryPlan
  → present blockers/warnings/required capabilities
  → commitImport(stagingId)
      → atomically switch Workspace generation
      → probe Host capabilities
      → activate available ToolPacks
      → emit host.changed/resume events
      → expose same SessionId
  → cleanup staging
检查阻断条件可降级条件
Capsule 完整性hash、schema、manifest 或 blob 缺失无
路径越界、非法盘符、case collision、目标不可表示且无映射可选提示性元数据差异
Session引用结构损坏或 ID 冲突且不是迁移场景运行中 Task 改为 interrupted
Git/VCS对象缺失、index 损坏回退为工作树 + Portable VCS；PortableGit 可恢复时继续 common subset
ArtifactSession 引用内容缺失用户明确选择仅保留断链历史
工具链无工具/Test 不可用，任务恢复为 degraded
默认 commit 前不修改现有 Workspace。若导入发生崩溃，启动恢复只允许清除 staging 或完成已验证的 generation switch，不能留下半导入状态。

12. 恢复对账

RecoveryReconciler.reconcile(snapshot, capsuleState, capabilityReport)
  → preserve completed messages/results
  → mark accepted-but-unknown commands as unknown
  → mark active task paused/interrupted at tool boundary
  → invalidate pending approvals
  → mark old environment evidence stale when fingerprint changes
  → attach new capability summary
  → select next safe action
  • 同一宿主重启且 environment fingerprint 相同，可以沿用已满足的当前验证证据。
  • 跨宿主或工具链变化时，旧证据保留为历史，但最终完成前必须重新运行相关验证。
  • 中断在执行中的命令不自动重放，尤其 commit、deploy、网络写入、Git push 等危险操作。
  • 子 Agent 若已产出一致性结果，可恢复结果；仅处于运行中的子任务标记 interrupted。
  • 恢复事件进入 SessionTree，确保模型上下文知道已经换宿主以及哪些能力变化。

13. 环境与应用动作抽象

interface EnvironmentManifest {
  manifestVersion: 1;
  requiredActions: Array<{
    id: 'app.python.run-tests' | 'app.xcode.build' | string;
    versionRange?: string;
    required: boolean;
  }>;
  requiredCapabilities: string[];
}
宿主义务Agent 可见结果
注册稳定 Action ID、JSON Schema、版本和 effectsAgent 看到具体动作，不看到 Python/Node/二进制路径
在 Provider 内部将动作映射到 WorkspacePath、运行时或远程服务工具输入保持平台无关
只把授权 scope 和显式上下文传给动作不继承宿主 Secret 或完整 env
返回 actionId、actionVersion、environmentFingerprint用于证据有效性和 stale 判断
动作不可用时报告 unavailable/degraded不尝试猜路径、运行通用 bash 或伪造结果
Capsule 不保存通用命令配方。它保存应用动作的 ID、版本要求和证据契约；宿主应用负责决定该动作在 macOS、iOS、Browser 或 Linux 上如何实现。

14. 安全与隐私

完整性

防篡改、截断、路径逃逸、压缩炸弹、重复条目和悬空引用；所有校验在 materialize 前完成。

Secret

SecretLease、token、cookie、环境凭据和宿主密钥不进 Capsule；导入后按 scope 重取。

路径

WorkspacePath 不会因 symlink、Windows junction、Unicode 或 case-fold 绕过 root fence。

导出策略

默认排除缓存和敏感文件；排除项形成 manifest 诊断，不能静默忽略项目内容。

审批

旧批准不跨 generation 生效；命令、网络、写范围重新评估。

日志

导入导出 Trace 记录 capsule ID、generation 和 hash，不记录完整敏感内容。

16. 对 REQ-HOST-001 的配套修正

REQ-HOST-001 仍是 14 个 Host 功能需求，不新增一套 FR-HOST-015..。需要修改的是已有接口/验收的精确语义：

Git 的默认实现与格式契约由 REQ-GIT-001 单独定义。

Host 需求修正
FR-HOST-001明确 Host workspace import/export 只传输不透明 Capsule bytes；Workspace 语义属于 REQ-WORKSPACE-001
FR-HOST-002Capability report 增加 contractVersion、environmentFingerprint 和不透明 host handle

FR-HOST-006GitBackend 增加 repository/index 导出能力，结果路径使用 WorkspacePath，证据绑定环境
FR-HOST-007TestReport 必须记录 actionId/actionVersion、环境指纹和文件 hash；换环境/动作版本后状态可为 stale
FR-HOST-009Network/Secret 明确为不可迁移能力，Secret 不得进入 Capsule/Session/Artifact
FR-HOST-010Workspace Transfer 不属于模型 ToolPack；它是 runtime service，避免模型自由调用危险迁移

FR-HOST-014兼容迁移不再只表示 VirtualFallback；增加“Capsule transport 与 workspace continuity 分离”
Host 不做 Capsule 解释，Workspace 不直接操纵 OS。两者通过 WorkspacePath、能力图谱、环境指纹和不透明 bytes 这四个窄契约连接。

18. 确认项与完成定义

DECISION-01

Capsule 是唯一跨宿主迁移单位，包含 Project、AgentState、Repository、Artifact、Evidence、Environment 与可选 ClientState。

DECISION-02

跨宿主恢复的是逻辑任务安全边界，不迁移运行中的进程、PTY、网络连接或 Secret。

DECISION-03

Agent 只使用 WorkspacePath 和能力语义；宿主绝对路径、PID 与平台分支不进入 Core/Prompt。

DECISION-04
