1. 测试策略与风险模型

要证明的核心事实

  • 能力只有在 Probe 成功后才会进入可用工具集。
  • 缺失能力会显式降级，不会生成“看起来能运行”的工具。
  • 文件、进程、Git、测试和安全边界在真实宿主上成立。
  • 同一 ToolPack 在不同宿主保持相同协议和结果语义。
  • 取消、超时、宿主断连和故障恢复不会留下孤儿资源。

最高风险失效

  • 只检查字段存在，把不可执行能力标成 available。
  • 文件已写入但项目未运行，模型却宣布任务完成。
  • symlink、cwd、环境变量或 raw shell 绕出 Workspace。
  • 取消只停父进程，孙进程和 PTY 仍在运行。
  • TUI、Chrome、Sandbox 各自解释同名工具，产生行为漂移。
  • Secret、完整命令环境或大输出进入 Session/日志/Artifact。

测试原则

契约先于实现

Memory、Node、Sandbox、Chrome Adapter 运行同一套端口契约，不靠阅读代码确认一致性。

真实性分级

纯逻辑使用确定性 Double；执行、Git、测试、PTY 和 Chrome 用真实依赖完成独立 E2E。

反误报完成

没有 ExecutionResult 或 TestReport 时，完成门禁必须失败，不能以模型文本替代证据。

P0 零容忍：能力假可用、Workspace 逃逸、测试假通过、Secret 泄漏、孤儿进程、Core 依赖具体客户端。任一出现即阻止发布，不能以“已知限制”带入 0.3.0。

5. 测试夹具与确定性控制

MemoryHostFixture

  • 内存 FS、Storage、Clock、Scheduler、Crypto、Clone。
  • 可注入 probe 成功、抛错、超时和晚到结果。
  • 记录声明、探测、工具注册和取消调用顺序。

NodeHostFixture

  • 每个用例创建独立临时项目根和状态根。
  • 使用真实 Node FS、短生命周期 Node 子进程。
  • 测试结束核对文件、FD、timer 和子进程无残留。

GitWorkspaceFixture

  • 干净仓库、脏仓库、untracked、branch、rename、binary。
  • 可通过 PATH 隔离模拟 Git binary 缺失。
  • Portable 生成结果可由真实 Git 读取/检查。

FaultAdapter

  • 在任意 Port 调用前执行 throw/delay/hang/corrupt/partial-write。
  • 支持断连后 reconnect 与能力变化。
  • 故障命中必须带有能力 ID 和请求关联 ID。

ChromeHostFixture

  • 无 Node/Execution 的真实浏览器宿主 Profile。
  • 覆盖 storage、browser provider、reload 和 tab 消失。
  • 不由 Core 直接读取 Chrome API。

EvidenceRecorder

  • 记录 capability report、ToolPackSet、命令、退出码、TestReport、Artifact 引用。
  • 失败用例保留最小诊断，不保存 Secret 或完整受限环境。
  • 供跨宿主比较和提交 Test-Evidence。
所有真实执行用例使用唯一临时目录和随机端口；禁止依赖用户已有仓库、Git 全局配置、固定工作目录或系统安装版本。必须显式设置测试所需的 PATH、HOME/XDG 状态和 Git author。

HOST-060Chrome ↔ 其他宿主Capability Report 解释和 ToolPack 选择规则Browser ToolPack、可用工具数量、UI 呈现

Parity 不是“所有宿主都支持全部工具”，而是“相同的 Capability Graph 在所有宿主产生相同决策；有差异时必须可解释”。

13. 状态空间与属性测试

有界模型：
  hosts ≤ 2
  capability sets ≤ 3: filesystem | execution | git/tests
  probe outcomes = success | timeout | throw | late-success
  connection states = connected | disconnected | reconnecting
  operations = write | execute | test | cancel | reconnect
  event sequences ≤ 8

不变量：
  available(capability) ⇒ 对应 Port 探测成功
  tools ⊆ dependencies(available capabilities)
  completed(write task) ⇒ has ExecutionResult/TestReport or explicit manual verification
  cancelled(request) ⇒ no owned process/pty/network remains
  reconnect ⇒ only latest generation capability report is active
  stale probe cannot downgrade/upgrade a newer generation

Property Tests

  • 随机能力组合产生合法 ToolPackSet。
  • 取消顺序随机时最终资源状态幂等。
  • 任意 Probe 事件交错不产生假 available。
  • Adapter 的路径函数在随机相对路径下不越界。

Mutation Targets

  • 移除 probe 调用。
  • 把 execution 缺失当 optional 成功。
  • 对称链接检查使用 lexical path。
  • 取消只杀父进程。
  • 无 TestReport 时放行 completed。
TLA+ 或等价有界模型用于能力和 generation 状态机，不强行证明 OS/Chrome 行为。模型发现的每个反例必须转为确定性 Vitest 回归。
