1. 核心决策

环境语义属于 Agent 包

Agent 工具只操作虚拟 Workspace。文件、Shell、Patch、Diff、版本快照、搜索和工作目录由包内实现。

宿主只做低层桥接

宿主提供存储、项目导入导出、终端和可选进程/网络桥接，不需要理解 Agent Session、Bash 或 Git。

默认零外部开发工具依赖

MemoryFS、JS Shell 子集、Snapshot VCS 和常用文本工具随 Agent 逻辑提供，不打包 Node、Python、Git 或 Bash 二进制。

真实工具链可选

复杂项目需要的编译器、测试器和原生工具由 Toolchain Provider 提供，可以是宿主进程、远程 Workspace 或 WASM。

单一 Workspace 契约

无论 Memory、macOS、Chrome 还是 Remote，Agent 面对相同的文件、Shell、VCS、Patch 和 Artifact 语义。

确定性优先

时间、ID、调度、Hash、Clone、存储和命令结果可注入；同一 Fixture 应生成一致的 Projection、Trace 和变更。

架构目标：Portable Agent + Virtual Workspace + Minimal Host Bridge。外部工具链不是 Agent 本体的一部分，也不是宿主启动 Agent 的前提。

当前基础

依赖规则

  • Core 不直接访问宿主文件系统、Shell、Git 或 Chrome。
  • Agent Tools 只访问 Virtual Workspace，不直接调用 OS。
  • Virtual Workspace 不依赖 UI；TUI 和 Chrome 只是 Workspace 客户端。
  • Host Bridge 不理解 Agent 工具，只执行受控低层操作。
  • Provider 失败不得破坏虚拟 Workspace 的持久状态。

4. Virtual File System

MemoryFS

完全内存，任何 JS 环境可运行。用于确定性测试、临时任务和模拟。

OverlayFS

只读 Base + 可写 Overlay。适合真实项目：用户文件不被直接修改，变更可审阅后导出。

PersistentFS

通过宿主 Blob/Key-Value 持久化对象、目录和 Manifest。

ArchiveFS

以 ZIP/TAR 或项目 Bundle 作为只读输入。

HostFSBridge

可选把虚拟路径映射到真实目录，仅作为 Provider，不是 Agent 依赖。

RemoteWorkspaceFS

通过 RPC 读取和提交变更，未来客户端共用同一语义。

VFS 能力

read / readRange / writeAtomic / append
list / glob / stat / lstat / realpath
mkdir / remove / rename / copy
open / close / watch
readBinary / writeBinary
hash / diff / patch
snapshot / restore

数据组织

  • 目录树保存路径与元数据；文件内容按 Content Hash 存储，可去重。
  • Overlay 只记录修改、删除和新增，导出时生成变更集。
  • 写入必须原子；失败不得留下半文件。
  • 路径统一使用虚拟绝对路径，禁止 `..` 越界和未授权 Symlink。
  • 大文件延迟读取和分页，不默认载入内存。
  • 文件工具返回路径、Hash、大小、编码和修改版本。

5. Virtual Shell

目标不是完整复制 Bash，而是提供开发任务所需的稳定 Shell 语义，并避免把宿主 Bash 当作运行前提。

首版兼容子集

  • 命令、参数、引号和转义。
  • 环境变量、局部变量和命令替换的可控子集。
  • 管道、重定向、&&、||、;。
  • 工作目录、退出码、stdout/stderr。
  • 后台任务、取消和输出上限。
  • 内建 pwd、cd、ls、cat、mkdir、cp、mv、rm、echo、test。
  • 内建 grep/rg 兼容子集、find/glob、diff、patch。

执行分层

Shell Parser → AST → Executor
Executor
├── VFS Builtins
├── JavaScript Command Implementations
├── Toolchain Provider
└── Optional Host Process Provider
不支持或无法安全解释的 Shell 语法必须明确报错，不能把原始字符串交给不可信 eval。外部命令只能通过 Provider 注册表执行。

命令上下文

  • 每次调用包含 Workspace、Session、cwd、env、stdin 和取消信号。
  • Secret 只在执行时注入，不进入 Shell 历史、Projection 或日志。
  • 命令输出实时流式，超过阈值自动 Artifact 化。
  • 命令和文件修改关联到任务和检查点。

6. Version Control

默认使用 Agent 包内的 Snapshot VCS，不依赖宿主 Git CLI。真实 Git 仓库通过可选 Git Provider 兼容。

Snapshot VCS

  • 文件 Hash、目录树、提交图。
  • 任务检查点、Diff、恢复、分支。
  • 工作区 Fork 和 Merge Preview。
  • 导出 Unified Diff/Patch。

Git Provider

  • 读取真实 Git 状态、索引和忽略规则。
  • 应用 Patch、创建临时分支。
  • 模拟或桥接 Worktree。
  • 默认禁止自动 commit/push。
VCS Operations
status / diff / snapshot / checkpoint
restore / compare / branch / fork
previewMerge / applyPatch / exportPatch

子 Agent 隔离

每个子 Agent 获得 Workspace Fork 或 Overlay。父任务审阅子 Agent Diff 后合并，不依赖宿主 Git Worktree。存在 Git Provider 时可映射到真实 Worktree。

7. Toolchain Provider

复杂项目仍需要真实编译器。Agent 不打包这些工具，而是通过稳定 Provider 调用。

Provider能力适用场景
Built-in JS搜索、Patch、Diff、JSON/YAML、简单命令所有 JS 环境
Host Processspawn、stdout/stderr、exit、signalmacOS 本机工具链
Host PTY交互进程、终端尺寸、后台会话TUI / 长任务

WASM Provider特定语言工具可移植工具链

Provider 只提供“执行能力”，工作目录、命令语义、输出处理、取消、验证和审阅仍由 Agent 包控制。

8. Minimal Host Bridge

HostBridge
├── storage: get / put / list / remove
├── workspace?: import / export / filePicker
├── terminal?: write / input events
├── clock / scheduler / crypto / clone
├── process?: spawn / signal / stream
└── network?: request / proxy / allowlist

宿主不负责

  • 不实现 Session、Task、Agent Loop 或 Tool 语义。
  • 不需要安装 Bash、Git 或固定开发工具链。
  • 不需要理解 Projection 和 UI 状态。
  • 不需要提供完整文件系统；VFS 可完全内存或持久化。

能力发现

Host 启动时上报 Storage、Terminal、Process、Network、Workspace Import/Export 等能力。缺失能力时对应 Provider 和 ToolPack 不注册，UI 明确提示。

9. Agent Core 与 Coding Loop

任务闭环

理解项目 → 搜索 → Patch → 运行验证
             ↑                 ↓
          修复证据 ← 测试失败
             ↓
        最终 Diff / 验证报告 / 风险
  • 测试失败不能标记完成。
  • 外部命令结果和文件修改进入同一 Trace。
  • 上下文压缩保留任务目标、文件 Hash、失败证据和未解决项。
  • 大输出 Artifact 化，模型只读取必要摘要。
  • 完成后生成可审阅的 Diff、测试结果和未覆盖风险。

Prompt Profile

Chrome、TUI、未来 Headless Client 各自提供 PromptProfile。Prompt 不进入 Core 硬编码，也不把 Chrome 工具暴露给 TUI。

10. macOS TUI 交互规范

设计目标：键盘优先、默认单视图、内容优先。默认只常驻一行状态栏与 Composer；多 Session、动态子 Agent 树、审阅、状态详情和扩展能力使用临时主视图。复杂能力必须可发现，但不能长期占用对话空间。

10.0.1 明确非目标

不做常驻多栏 IDE

不设置永久 Session 栏、Agent 栏、文件树或多 pane；这些能力以全屏临时视图出现。

不固定子 Agent 角色

Researcher、Reviewer、Implementer 只是可能的 Profile 实例，不在 TUI 或 Runtime 中做角色枚举。

不在客户端重建事实

TUI 不自行推导任务是否完成、子 Agent 是否仍运行或审批是否已处理，只展示 Runtime 提供的事实。

不要求鼠标或富终端

默认兼容普通 ANSI 终端；鼠标、颜色、动画和超链接均为可选增强。

10.3 多 Session 管理

Ctrl+K
┌ Sessions · 5 · 2 running · 1 needs input ────────────────────┐
│ / [搜索标题、项目、分支、状态]                               │
│                                                              │
│ ● fix-auth        tinyai/main    RUN 02:14    2 queue  2 new  │

│ ! release-check   app/main*      NEEDS INPUT  approval       │

│ Enter 切换 · N 新建 · R 重命名 · D 删除 · Esc 返回          │
└──────────────────────────────────────────────────────────────┘

Session 切换器是 Runtime 会话的只读列表加受控命令入口。每行至少包含明确的选择标记、Session 标题、项目/分支、任务状态、活动/未读摘要和阻塞原因；子 Agent Session 还显示父 Session 标识。

操作交互行为与约束
切换选择后 Enter只改变当前客户端观察目标，不停止旧 Session 的任务。成功后更新 lastActiveSessionId。
新建N建立本地 Draft Session；首次发送时才创建/激活 Runtime Session，避免空会话污染历史。
重命名R只修改显示标题，不改变 Session ID；标题失败不影响对话。
删除D空闲 Session 二次确认后删除。运行中的 Session 先说明任务仍活跃，再由用户确认“停止并删除”或取消。
搜索输入字符匹配标题、项目、分支、任务状态和子 Agent Profile；结果顺序稳定，当前 Session 永远可定位。
恢复选择历史 Session先显示缓存快照，再请求 Runtime hydration；期间保留输入能力并明确显示 LOADING。

每 Session UI 状态

SessionUiState {
  sessionId
  draftText, cursor, attachments, selectedSkill
  scrollAnchor, expandedItemIds, selectionId
  lastSeenEventSeq, unreadMarkers
  routeStack, boardFilter, boardSelection
}

这些状态保存在 TUI Adapter 的持久化命名空间中，按 Session ID 分区；它们不得写入 Session Snapshot、Agent 上下文或跨客户端 Projection。Runtime 侧只提供会话事实。

切换一致性

generation := (sessionId, logEpoch, subscriptionGeneration)

切换：
1. flush 当前草稿和滚动锚点
2. subscriptionGeneration += 1
3. 取消旧 subscription，订阅目标 Session
4. 仅接受 sessionId、logEpoch、generation 三者匹配的 Projection
5. 收到 snapshot/gap 后重建目标时间线
6. 恢复目标 Session 的 Composer 草稿和选择
当前 Runtime 的 Projection 消息只携带 Frame。正式实现 TUI 前必须给事件增加 sessionId（或带同一语义的 envelope），否则多订阅或快速退订时无法可靠排除迟到帧。该字段属于端无关协议，不是 TUI 私有字段。
  • 每个 Session 的后台任务由 Runtime 持续运行；Agent 看板关闭、客户端断线或另一个 Session 获得焦点都不暂停它。
  • 非活动 Session 的运行/失败/审批通过轻量 Session 摘要显示；完整时间线只在打开时 hydrate。
  • 未读位置使用 lastSeenEventSeq，不按“最后一条消息文本”猜测。
  • 快速 A→B→C 切换必须丢弃 A/B 的迟到帧；目标 Session 不存在时回到列表并展示 SESSION_NOT_FOUND。
  • 删除当前 Session 后选择时间上最近的可用 Session；没有历史时创建空 Draft，不自动发送内容。

│ Enter 查看 · S 停止 · R 继续 · D Diff · M Merge · Esc 返回   │

  • 树节点来自 Runtime 的父子关系和 Session 摘要；Profile 名称是数据，不是 TUI 分支逻辑。任意合法 Profile 都可显示。
  • 默认按父子树排列，同层按创建时间稳定排序；过滤只改变可见节点，不改变父子事实或 Runtime 状态。
  • 每行显示 Profile、任务摘要/名称、状态、执行模式、耗时、Workspace/Fork 标识，以及结果数量或冲突摘要。
  • 运行中的 Agent 保持活跃并在看板中周期刷新；失败项进入 ATTENTION，完成项在 DONE 中加入结果和验证摘要。
  • 看板打开时不会额外启动 Agent；R 只对 Runtime 明确允许 resume 的终止任务可用，不把“继续”误解为重复执行原副作用。
  • Enter 进入子 Agent Session；导航栈保存父 Session、当前过滤、选中节点和滚动位置。Esc 返回看板，不直接丢失上下文。
  • 可在子 Session 中补充消息、观察 Reasoning/Tool/命令、停止或继续任务；其状态栏使用子 Session 标识和父 Session breadcrumb。
  • D 打开该子任务的 Diff/证据；M 打开 Merge Preview，展示冲突、测试、风险和待应用 Patch，绝不自动合并。
  • 嵌套层级受 Runtime 的 max depth 约束；超过可视宽度时用缩进和父路径面包屑，不创建横向多栏。

端无关的最小数据契约

type TuiRoute =
  | { kind: 'conversation' }
  | { kind: 'sessions'; query: string; selectedId?: string }
  | { kind: 'agents'; rootSessionId: string; selectedId?: string }
  | { kind: 'review'; targetSessionId: string }
  | { kind: 'status'; targetSessionId: string }
  | { kind: 'commands'; query: string }
  | { kind: 'help' }

interface RuntimeSessionSummary {
  sessionId; parentSessionId?; title; project?; branch?
  taskStatus; lifecycle; revision; eventSeq; updatedAt
  queueLength?; attentionCount?; childCount?; lastError?
}

interface TuiRuntimePort {
  listSessions(): Promise<RuntimeSessionSummary[]>
  loadProjection(sessionId: string): Promise<ProductProjection>
  subscribe(sessionId: string, generation: number,
            listener: (envelope: ProjectionEnvelope) => void): Promise<() => void>
  command(command: CommandEnvelope): Promise<CommandAck>
  stopSession(sessionId: string): Promise<void>
  deleteSession(sessionId: string): Promise<void>
  renameSession(sessionId: string, title: string): Promise<void>
}

TuiRuntimePort 位于 TUI Adapter 与通用 Runtime/Protocol 之间；Core 不导入它。Projection envelope 至少包含 sessionId、logEpoch 和 Frame，TUI 再叠加本地 subscription generation。这样其他客户端可以使用相同的防串话协议。

10.7 关键模块交互

切换 Session

Keymap(Ctrl+K) → RouteController(session-switcher)
选择 Enter → SessionController.switch(target)
  → ViewStateStore.flush(current)
  → generation++
  → unsubscribe(current)
  → load/cached snapshot(target)
  → subscribe(target, generation)
  → ProjectionCache.validate(envelope)
  → ViewStateStore.restore(target)
  → Renderer.render(conversation)

旧任务的 Runtime 执行不受 unsubscribe 或 UI 导航影响。

进入子 Agent Session

Ctrl+G → AgentBoardPresenter.build(current.children)
Enter → RouteController.push(agent-board state)
      → SessionController.switch(childSessionId)
      → conversation(child)
Esc   → SessionController.switch(parentSessionId, from=board)
      → RouteController.pop()
      → restore filter, selectedId, scrollAnchor
Esc   → conversation(parent)

断线重连

Host/Runtime disconnected
  → status segment RECONNECT/OFFLINE
  → Composer 保留草稿但禁止可能重复的发送
  → reconnect
  → get_projection(target)
  → snapshot replaces cache
  → 恢复路由、选择、滚动和待处理用户的输入
  → 对不确定是否提交的 Command 使用 commandId/query ACK 对账

后台 Agent 完成

Runtime child projection changes
  → active Session: 更新 Agent row/board
  → inactive Session: 更新 summary 的 attention/unread
  → status: agents count + attention marker
  → 不抢 Composer 焦点
  → 用户 Ctrl+G 后按需加载完整树
所有用户动作遵循“输入 Intent → 发送 Command/调用 Runtime Port → 等待 ACK/Projection → 更新 UI”。停止、删除、Resume 和 Merge 不做乐观状态翻转；允许在等待期间显示 pending，但不能伪装为成功。

10.8 工作历史与 Review

  • 工具、Reasoning、命令和子 Agent 默认是单行摘要，显示状态、耗时和关键结果；Enter/点击可展开原始参数、输出、Artifact 和 Diff。
  • 运行中的内容保持可见；完成的成功 Work 可折叠为 Worked 2m，失败 Work 默认展开并保留失败证据。
  • 最终回答不因 Work 折叠而消失；状态栏只保留当前运行摘要，不在底部堆叠多个进度条。
  • Ctrl+O 打开 Review 临时主视图：文件数、增删行、验证状态、风险、Diff、测试证据、Artifact 和 Patch 导出。
  • Review 无变更时给出明确说明；大 Diff/10 万行日志采用虚拟滚动与按需加载，不阻塞输入。
  • Review 中的合并或保存操作需要明确确认，并使用 Runtime/Workspace ACK；关闭后恢复原 Session 和滚动位置。

10.11 持久化、恢复与性能

持久化

TUI 只持久化路由、最后活动 Session、每 Session 草稿/附件引用/滚动锚点/展开项/过滤与未读位置；Session 与 Workspace 数据由 Runtime/Store 恢复。

恢复顺序

Host 能力 → Session summary → 最后活动 Session 的 Projection → 本地 UI 状态。任一阶段失败都可回到 Session 列表，不能因布局恢复失败隐藏会话。

渲染性能

流式事件 16–33ms 合并渲染；Transcript 虚拟滚动；只重绘变化区域；大 Artifact 按需读。

交互预算

按键到屏幕反馈 p95 ≤ 50ms；缓存 Session 切换 p95 ≤ 100ms；冷 hydration 先出现明确 loading，输入不被冻结。

  • 高频工具输出必须节流并保留“有更多输出”提示；不能因渲染队列无限增长而阻塞 Composer。
  • Session 切换、看板打开、resize 和 Overlay 关闭都不得重新请求已缓存且 revision 一致的完整历史。
  • 崩溃恢复不重放不确定命令；Command ID、ACK 和 Event Seq 用于对账。
  • 大量 Session 的列表按需分页/虚拟滚动；看板只加载当前父 Session 的直接子树摘要，详情按需 hydrate。

11. Chrome 工作流

  • 页面、选中文本和错误日志作为 Context Artifact 进入虚拟 Workspace。
  • Browser ToolPack 只操作当前浏览器 Workspace。
  • 标签组共享 Session，组外独立；不隐式打开页面。
  • 前端修复生成代码 Diff、测试和页面验证证据。
  • 可在 TUI 和 Chrome 查看同一 Session；任务执行权只属于一个权威 Runtime。
  • 无本地编译工具时通过 Remote Runner 或 WASM Provider 验证。

12. 子 Agent

  • 通用 Profile，不固定 Researcher/Reviewer。
  • 每个子 Agent 获得 Workspace Fork/Overlay 和独立上下文。
  • 支持前台、后台、预算和并发限制。
  • 结果包含摘要、Diff、测试、证据、Artifact 和未解决项。
  • 父 Agent 显式审阅并应用 Patch。
  • 取消向子任务和 Provider 传播。

14. 数据、安全与恢复

Session Data

对话、任务、队列、验证、子 Agent、Trace；跨客户端可读。

Workspace Data

VFS Manifest、内容对象、Overlay、VCS、检查点和 Artifact。

Host Data

持久化存储、项目 Bundle、终端能力；不保存 Agent 私有布局。

安全边界

虚拟路径规范化、Provider 权限、网络 allowlist、Secret 脱敏、命令输出限制。

恢复原则

  • 先恢复 Session，再恢复 Workspace Manifest，最后恢复 UI。
  • 运行中的命令记录可重放性和最后输出；不可重放命令不自动重试。
  • 文件写入与 VCS 检查点必须对应同一 Workspace revision。
  • Provider 崩溃不能损坏 VFS。
