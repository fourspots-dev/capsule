TEST STRATEGY · v1.0

让每条 Agent 行为基线都有可执行证据

本方案把 ZCode 的协议与状态空间测试、Pi 的包级 Harness 与 faux provider、Browser Agent 的真 Chrome smoke 组合起来，形成 tinyai 的分层测试体系。测试目标不是“多写用例”，而是证明权威状态、恢复、权限、子 Agent 和沙盒边界始终正确。

对应设计 Agent 3.0 v0.3 测试层级 L0–L5 首批目标 80–100 个确定性用例 日期 2026-10-30
先做测试基建，再做大功能

当前 tinyai 没有自动化测试，只有类型检查。Runtime、Projection、子 Agent 和 Sandbox 并行开发前，必须先完成 Fake Harness、测试目录、fixture 协议和 CI 门禁。

01

参考系统的测试方法

三个系统的测试重点不同：ZCode 证明产品状态协议，Pi 证明 Agent Harness，Browser Agent 证明真实浏览器行为。

ZCode

协议与状态空间

  • Spec / Case Catalog / Coverage Matrix 先定义行为
  • Command、ACK、Projection、Cold Hydration 契约测试
  • TurnMachine 显式状态迁移测试
  • SSE Capture/Replay 与 FS Fault Injection
  • Docker replay-isolated 与真实 Electron E2E
  • formal-proof 枚举产品状态组合

证据：E2E Workflow、SSE Replay、FS Fault Injection。

  • faux provider 精确产生文本、思考、工具事件
  • 测试 HOME/TMP/Git/NPM 完全隔离
  • 回归用例按 issue 编号固化
  • Provider、Session、Compaction、Extension 分域覆盖

证据：agent e2e.test.ts、test.sh。

Browser Agent

02

测试原则

优先验证系统不变量，而不是模型措辞；优先确定性故障注入，而不是靠重试消除 flaky。

State over text

断言真实副作用

任务终态、工具调用、文件变化、Projection、Artifact 和资源释放优先于模型自然语言。

Determinism

控制时间、网络和随机性

Fake clock、固定 UUID、固定随机种子、model replay 和本地 HTTP replay server。

Boundary

只在边界做 mock

Mock Model、Browser、Sandbox、Storage；核心 Domain/Runtime 尽量跑真实实现。

Recovery

故障必须可恢复

断连、崩溃、超时、重复命令、磁盘失败都必须有终态和证据。

Isolation

不碰真实用户状态

隔离 HOME、DataDir、Chrome Profile、Workspace、Credentials 和网络。

Traceability

每个用例可追溯到基线

测试 ID 必须能映射回 ZC/PI/UP/TL 行为基线和被测模块。

05

分层测试策略

每一层有唯一职责，失败时能快速判断是领域逻辑、协议、集成还是外部环境问题。

层级真实组件Fake / Stub目标
L0 UnitSchema、状态机、纯函数无外部依赖快速验证不变量
L1 Contract接口实现、序列化、工具契约最小依赖防止接口漂移
L2 IntegrationAgentSession、Runtime、CommandInbox、SessionTreeFakeModel / FakeTools / InMemoryStore验证模块协作
L3 Golden真实 Normalizer/Projection/Hydrator持久化与 live facts fixture验证 live/cold 等价
L4 E2EChrome、Sandbox、真实 sidepanel本地模型 stub验证真实环境与资源释放
L5 Live Eval真实模型真实工具 / Fixture workspace验证模型策略和工具选择
不要把 E2E 当单测替代品

ZCode 当前已退役大量 App 业务单测，重点转向正式 E2E 与协议证据；tinyai 的安全、Projection 和 Runtime 内核仍应保留大量快速确定性单测，避免 E2E 成为唯一防线。

先建立一套可创建、驱动、快照和销毁 Agent Runtime 的测试工厂。

Proposed Harness API

FakeModel

脚本化模型流

控制 SSE chunk、tool call、延迟、断流、abort、usage 和模型切换。

FakeTools

可控副作用

控制成功、失败、超时、永不返回、流式进度和取消。

FakeProviders

浏览器与沙盒

不必启动真实 Chrome/Container 即可测 Runtime 集成。

TestClock

时间可控

不依赖 sleep；deadline、retry backoff 和 stop timeout 可快进。

CrashInjector

故障注入

在指定 commit、写入或 lock 后抛错，模拟重启窗口。

Isolation

资源隔离

每个 suite 独立 HOME/TMP/DataDir/Workspace，结束后由 owner 清理。

模型流、重试与录制回放

模型测试必须在 SSE event 级别确定，不能依赖真实网络和自然语言输出。

ID场景期望
MODEL-001一个 SSE event 跨多个 TCP chunk解析结果不变
MODEL-002tool name 先到，arguments 分多段调用完整且 index 稳定
MODEL-003多个 tool calls 乱序结束按 index 排序持久
MODEL-004响应头后立即断流结构化 network fault
MODEL-005部分文本后断流保留 partial，按策略 retry
MODEL-006429 + Retry-After有限退避，usage 不重复
MODEL-007usage 缺失不伪造 0，标记 unknown
MODEL-008模型不可用后切换记录 from/to，task 不断链

安全与故障注入

安全测试应使用可观测的故障等价类，而不是依赖真实权限错误或人工破坏环境。

类别注入期望证据
SSE断流、stall、 malformed event、late eventfault code、retry、task 终态
StorageENOSPC/EACCES、损坏快照、事务失败fail closed、可恢复错误、原数据不丢
Processvendor crash、SIGTERM、hang有界退出、无孤儿、generation 提升
Connectiongap、duplicate、late subscribe、saturated只恢复当前 subscription
Permissionstale approval、hook digest change拒绝且无工具执行
Credential金丝雀 secret 进入 result/env/logtrace/projection/export 均脱敏
Prompt injection网页/仓库要求读密钥或执行命令untrusted 标签和 Policy deny

借鉴 ZCode 的 FS Fault Injection：错误应保留 Node Errno 形状并附带 faultId、operation、path，测试通过故障 ID 定位。

手写 case 覆盖已知问题，属性测试寻找组合型问题。

全局不变量

  • 每个 commandId 最多一个终态
  • 输入只能 queue 或 transcript
  • launch、finish、compaction 至多各一次
  • Projection seq 单调且连续
  • 父取消后无 owned child running
  • child 权限始终为父权限子集
  • Session stop 后无活跃 lease/process/tab
分层采用，不直接上 TLA+

第一阶段用 fast-check 或自建枚举器；只对 Command、Lifecycle、Projection、Subagent 四个核心域做序列生成。第二阶段再把关键协议抽象为形式化模型。
