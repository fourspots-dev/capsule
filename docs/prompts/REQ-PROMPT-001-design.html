TINYAI / PROMPT ARCHITECTURE / DETAILED DESIGN

分层、跨宿主 Prompt 组合

把稳定行为策略、Workspace 语义、宿主差异、执行能力、模式、Profile 和动态运行上下文拆成可测试、可缓存、可按权限裁剪的 Prompt Contract。

1. 当前问题

结构问题

  • Workspace Prompt 与 Chrome Prompt 重复定义 Agent 身份。
  • 浏览器、Coding、Patch 和 Skill 规则全部平铺。
  • 宿主不存在的能力可能被硬编码进 Prompt。
  • 标签查看与任务执行语义未进入统一 Policy。

行为问题

  • 缺少统一 Observe → Decide → Act → Verify → Report 循环。
  • 工具协议细节与 Tool Schema 重复。
  • Skill、Profile、Runtime facts 没有信任等级。
  • 没有稳定前缀、预算或裁剪规则。

3. 八层模型

层内容变化频率
1 Core Policy身份、观察/行动循环、真实性、完成和沟通极低，所有宿主相同
2 Workspace Policy相对路径、Inspect-before-edit、Patch、Search、VCS、验证按 Workspace profile
3 Host PolicyChrome Tab、TUI PTY、Headless、iOS Native Bridge每宿主不同
4 Execution PolicyNamed Actions、Legacy Shell、Browser tools、Code Intelligence由 Registry 动态决定
5 Mode PolicyPlan、Build、Read-only、Research、Review、Debug每任务/模式
6 Agent Profile主 Agent 或任意通用子 Agent 职责每 Session/子任务
7 Capability / Skill Context可用 Action、LSP、工具摘要、Skill 列表和选中正文动态
8 Runtime ContextSession、Workspace generation、标签、队列等当前事实每次请求可变

4. 核心对象

interface PromptSection {
  id: string;
  kind: 'policy'|'instructions'|'capabilities'|'runtime';
  priority: number;
  required: boolean;
  trust: 'core'|'project'|'profile'|'skill'|'runtime-data';
  cache: 'stable'|'session'|'request';
  render(context: PromptBuildContext): string | Promise<string>;
}

interface PromptBuildContext {
  hostProfile: 'chrome'|'tui'|'headless'|'ios'|'sandbox';
  workspaceProfile: 'portable'|'legacy';
  mode: string;
  agentProfile?: ResolvedAgentProfile;
  tools: readonly ToolDefinition[];
  actions: readonly AvailableHostAction[];
  codeIntelligence: CodeIntelligenceCapabilities;
  skills: readonly SkillDefinition[];
  selectedSkill?: SkillDefinition;
  runtime: Record<string, JsonValue>;
}

interface PromptAssembler {
  build(context: PromptBuildContext): Promise<PromptEnvelope>;
}

interface PromptEnvelope {
  stablePrefix: string;
  sessionContext: string;
  requestContext: string;
  manifest: PromptManifest;
}
PromptSection单一职责、可单测策略片段。
PromptProfileAdapter只提供宿主差异 Policy。
PromptAssembler顺序、去重、冲突、预算和缓存键的唯一所有者。
PromptManifestsection ids、版本、token 估算、裁剪和 trust。

5. 组合顺序

Core Policy
  → Workspace Policy
  → Host Policy
  → Execution Policy
  → Mode Policy
  → Agent Profile
  → Project Instructions
  → Capability Context
  → Selected Skill
  → Runtime Context

稳定 Policy 在前，Session 内容次之，每次请求变化的 Runtime facts 在最后，以便利用 Provider Prompt Cache。

去重规则

  • 同一 section id 最多出现一次。
  • 重复身份和完成规则由 Assembler 拒绝。
  • Patch 协议只在 Coding Workspace 已启用时出现。
  • 工具说明只保留选择策略，参数交给 Schema。

Chrome Tab 语义

activeTabId = 用户当前查看的标签
executionTabId = 当前任务执行标签

组内切换查看标签：
  activeTabId 改变
  executionTabId 与 Session 不变

用户要求处理当前标签：
  Agent 必须通过 switch_tab 显式修改 executionTabId

7. 信任与冲突优先级

Runtime hard enforcement
  > Core Policy
  > 当前用户明确要求
  > Project instructions
  > Agent Profile / Skill
  > Capability Context
  > Runtime facts
  • Capability Context 与 Runtime Context 是数据，不是覆盖 Core 的指令。
  • Profile/Skill 只能收窄行为和工具范围。
  • 网页、文件、工具输出按不可信内容处理，不能获得系统权限。
  • Runtime 在模型外执行权限、标签、审批和完成门禁。

8. 预算、裁剪与缓存

必须完整Core、Host、Workspace、当前 Mode
高优先当前用户要求、Project instructions、Agent Profile
可压缩Capability 摘要、Skill 描述、Runtime 非关键字段
仅选择后注入完整 Skill 正文

每段提供 character/token 估算。超预算时按 priority 和 cache 级别裁剪，禁止截断 Core。缓存键由 section id、version、host、workspace、mode 和 capability fingerprint 组成。

9. 生命周期

  1. Runtime 构建 Host/Workspace/Mode/Profile 输入。
  2. Tool、Action、LSP 和 Skill Registry 完成当前探测。
  3. Assembler 收集并校验 section。
  4. 生成 stablePrefix、sessionContext、requestContext 和 manifest。
  5. Session 可在 trace 中记录 prompt manifest，不记录非必要敏感正文。
  6. 运行中容量或 Registry 变化时只重建受影响的动态 section。

现有 PromptProfile 先保留兼容包装，迁移后只允许 PromptAssembler 输出最终系统提示词。Chrome Runtime、TUI 和 Headless 使用相同 Core/Workspace，按宿主注入不同 Host Policy。

11. 验收

  • Core 无宿主专属词。
  • Chrome Prompt 不含 TUI/PTY，TUI Prompt 不含 Tab。
  • Capability 声明与实际 Registry 完全一致。
  • Profile/Skill 无法扩大工具或权限。
  • 稳定前缀和动态上下文可区分并缓存。
  • 所有宿主通过同一行为契约与各自 E2E。
  • 标签执行语义在 Chrome Prompt 和行为 E2E 中成立。
