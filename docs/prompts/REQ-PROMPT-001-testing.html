TINYAI / PROMPT ARCHITECTURE / TEST DESIGN

分层 Prompt 测试方案

验证跨宿主 Policy 一致、宿主差异隔离、动态能力真实、信任边界、预算缓存和实际 Agent 行为。

1. 测试层级

Unit

Section 渲染、去重、优先级、预算、trust、缓存键。

Golden

Chrome/TUI/Headless/iOS/Sandbox 完整 Prompt 快照与互斥词。

Integration

Tool/Action/LSP/Skill/Profile 动态上下文与权限收窄。

Behavior E2E

Chrome 标签执行、页面修改验证；TUI 文件/PTY/取消。

3. Golden 契约

每个 Host 用同一组输入：Workspace profile、Mode、Profile、Tools、Actions、Code Intelligence、Skills、Runtime facts。输出按 section manifest 比较，不只比较最终字符串。

assertCoreHostNeutral()
assertSectionOrder()
assertNoDuplicateIdentity()
assertCapabilitiesMatchRegistry()
assertNoForeignHostTerms()
assertPromptBudget()
assertStablePrefixUnchanged()

互斥词

Chrome允许 tab/tab group/page；禁止 PTY、working directory-only
TUI允许 PTY/process/terminal；禁止 Chrome tab/Side Panel
Headless允许 non-interactive/machine-readable；禁止 UI interaction assumptions
Core禁止所有宿主和具体工具名

4. 行为 E2E

Chrome：借用当前页面开发 Terminal

  1. 读取当前页并识别目标。
  2. 修改 Workspace 文件。
  3. 加载页面并执行关键交互。
  4. 检查控制台/页面错误。
  5. 最终回答列出变更和验证证据。

Chrome：组内标签切换

view A → view B:
Session unchanged
activeTabId = B
executionTabId = A
read_page still reads A

user: "处理当前标签"
switch_tab(B)
executionTabId = B

TUI

  1. 读取仓库。
  2. Patch 文件。
  3. 运行配置的测试 Action。
  4. Evidence 为 current。
  5. 不出现 Browser Policy。
