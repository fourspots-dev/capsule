2. 生产质量目标

属性目标不可接受状态
可靠性中断后 Session 与 Workspace 可恢复；危险操作不重复执行。系统崩溃后重复写文件、重复提交或丢失任务。
正确性所有完成声明都有测试、静态检查或明确证据。测试失败仍显示完成；只描述动作但未执行工具。
可审阅性最终提供文件级 Diff、测试结果、风险和未完成项。只给自然语言总结，没有变更证据。
响应性输入后快速出现状态反馈；长命令持续显示进度。TUI 长时间无输出、无法取消。
隔离性默认在受限 Workspace 内执行；网络和破坏性动作按项目策略处理。越界读取、写入项目外文件或泄露密钥。
通用性支持多语言仓库、不同构建系统和任意目录结构。只识别 Node 项目或固定框架。
扩展性未来客户端可读取 Session 与审阅数据，无需修改 Core。TUI/Chrome 字段进入 Session Snapshot。
可观测性任务、模型、工具、验证、费用和失败都有 Trace。失败后无法判断是模型、环境还是用户中断。

4. 核心状态机

Task

queued → running → verifying
                ├→ waiting_approval → running
                ├→ repairing → verifying
                ├→ completed
                ├→ failed
                └→ cancelled

验证失败不能直接进入 completed。进入 repairing 必须携带失败证据，修复轮次和总预算受任务约束。

Workspace

creating → ready → executing → checkpointing → ready
                     ├→ interrupted → restoring → ready
                     ├→ failed
                     └→ releasing → released

Verification

not_started → running → passed
                    ├→ failed → repair_requested
                    ├→ skipped_with_risk
                    └→ cancelled

Subagent

queued → running → reviewing_merge → merged
                ├→ completed_unmerged
                ├→ failed
                └→ cancelled

5. 核心用户流程

进入仓库并开始任务

  1. 确认 Workspace 根目录和 Git 状态。
  2. 读取项目约定、构建配置和最近状态。
  3. 创建 Session 与任务预算。
  4. 展开展示计划或直接执行。

编码与验证

  1. 搜索相关代码和测试。
  2. 应用增量 Patch。
  3. 运行最小相关验证。
  4. 失败后分析证据并修复。
  5. 运行最终验证并生成 Diff。

中断与恢复

  1. 保存任务、文件检查点与最后成功验证。
  2. TUI 退出不终止后台任务。
  3. 恢复时展示已执行动作和未解决项。
  4. 危险操作需要重新确认执行条件。

浏览器上下文交接

  1. 用户引用网页、日志或选中文本。
  2. 生成明确 Context Artifact。
  3. Mac TUI 中建立或继续 Coding Task。
  4. 浏览器中查看任务状态和结果。

5.1 模型编辑协议与 Patch Tool

Git unified diff 是机器交换格式，不应成为模型的主要编辑输入。模型只表达“改哪里、旧内容是什么、新内容是什么”，Patch Engine 负责定位、校验、事务应用，并生成标准 unified diff 供审阅和外部工具使用。

模型协议

*** Begin Patch
*** Update File: src/math.ts
@@ export function add(
-  return a - b;
+  return a + b;

*** Add File: test/math.test.ts
+import { add } from '../src/math';
+
+assert.equal(add(1, 2), 3);

*** Delete File: obsolete.ts

*** Update File: src/old-name.ts
*** Move to: src/new-name.ts
*** End Patch
元素语义约束
*** Begin Patch / *** End Patch协议边界必须完整；外壳由 Parser 接受，不进入文件内容
*** Update File修改现有文件路径必须已存在且位于 Workspace 内
*** Add File创建文件目标默认不存在；冲突时失败
*** Delete File删除文件必须经过策略和审批
*** Move to移动或重命名源和目标必须安全，目标不得被静默覆盖
@@ anchor每个 Update hunk 的起始行，anchor 文本可选仅用于定位，不包含 old/new 行数
/ - / +上下文、删除、新增模型不得输出行号和 hunk count

应用语义

  1. 读取版本：模型编辑前通过 FileReadResult 获取 revision 或内容哈希。
  2. 解析协议：严格解析 Begin/End、文件操作和 hunk，不接受未声明的混合格式。
  3. 定位上下文：先用锚点和 context/remove 行精确匹配；归一化仅限 CRLF，默认不做忽略空白或模糊匹配。
  4. 唯一性：匹配必须恰好一次；零次返回 CONTEXT_NOT_FOUND，多次返回 CONTEXT_AMBIGUOUS。
  5. 版本检查：文件 revision/hash 已变化时返回 STALE_FILE，要求重新读取，不覆盖外部编辑。
  6. 事务：所有文件先在内存计算新内容；任一失败则不写入任何文件。
  7. 提交：按确定性路径顺序原子写入；失败时恢复原文件、mode 和版本。
  8. 生成证据：成功后用内部 DiffEngine 生成标准 unified diff、增删统计和受影响文件列表。
interface ContextPatch {
  operations: Array<
    | { kind: 'update'; path: string; moveTo?: string; hunks: ContextHunk[] }
    | { kind: 'add'; path: string; lines: string[]; mode?: number }
    | { kind: 'delete'; path: string }
  >;
  expectedVersions?: Record<string, number>;
  expectedHashes?: Record<string, string>;
}

interface PatchResult {
  files: Array<{ path: string; status: 'added'|'modified'|'deleted'|'moved'; beforeVersion: number; afterVersion: number }>;
  unifiedDiff: string;
  additions: number;
  deletions: number;
}

工具边界

Tool输入用途
replace_in_filepath、exact old text、new text、expected hash单处小修改，要求唯一匹配
apply_patchContextPatch DSL模型默认的多行、多文件编辑入口
apply_unified_diff标准 Git unified diff外部补丁、测试 fixture、高级兼容入口
不能再把“名称为 apply_patch、实际只接受 strict unified diff”的接口暴露给模型。工具名称、schema、描述和实际 Parser 必须遵循同一协议。

结构化错误

{
  code: 'PATCH_CONTEXT_AMBIGUOUS',
  operation: 1,
  path: 'src/math.ts',
  anchor: 'export function add(',
  expectedVersion: 17,
  actualVersion: 18,
  candidates: [42, 118],
  suggestion: 'Read the file again and submit a smaller context block'
}
  • 错误必须包含 operation 索引、路径、锚点、匹配次数、版本和可执行修正建议。
  • 解析失败、冲突和权限拒绝必须区分错误码，不能统一返回“Patch failed”。
  • 相同 Patch 原样连续失败达到阈值时，ToolExecutor 阻止重试并进入重规划。
  • 每次 Patch 记录协议版本、文件版本、匹配方式、事务结果、耗时和生成的 diff 引用。

6. 数据、恢复与安全边界

Session

对话、任务、队列、审批、验证、子 Agent、审阅和 Trace 引用。必须可跨客户端读取。

Workspace

项目根目录、Git 状态、Sandbox、PTY、检查点和 Artifact。由 TUI/Mac Runtime 管理。

客户端

草稿、展开状态、滚动、焦点和窗口布局。不得成为任务事实来源。

安全

基础管理即可：安全默认、高风险确认、项目级记住；密钥不入 Session 与日志；网络与路径边界由 Workspace 强制。

恢复原则

  • 先恢复事实，再恢复 UI：Session → Task → Workspace → 客户端布局。
  • 未完成工具先判定是否具有重放安全性。
  • 验证中中断，恢复后重新运行验证，不沿用旧通过结果。
  • 子 Agent 工作树必须可回收，不能遗留进程和锁。

7. 风险与阶段门禁

风险控制
Agent 自认为完成但测试未过Verification Gate；失败进入 Repair Loop
TUI 崩溃导致任务丢失Session/Workspace 持久化与后台任务
Patch 覆盖用户修改文件哈希、原子 Patch、冲突停止
apply_patch 协议与模型行为不一致ContextPatch DSL、工具生成 unified diff、结构化错误和重复失败熔断
长命令无法停止进程树取消、超时、PTY 清理
大仓库上下文溢出搜索优先、分页读取、主动压缩
