REQ-TUI-002 / HOST CAPABILITY INTEGRATION / DESIGN V1

TUI 能力组合与架构完整性

让 TUI 与 Headless Agent 共用 Capability Graph、ToolPack Composer、应用 Action Provider、动态 Prompt 和完成门禁；Portable Profile 默认不暴露通用 shell，Legacy Profile 仅显式选择。

1. 问题与范围

0.3.0 已实现 Action Provider、Portable Git 和 Workspace Capsule，但 TUI 仍使用独立的工具拼接、硬编码 Prompt 和 exec/job_read 完成门禁。它虽然可以启动，却没有完整消费新的架构能力。

本次必须完成

  • TUI 与 Headless 共用一个能力组合模块。
  • TUI 支持注册应用 npm-script Actions。
  • Portable 默认排除通用 VirtualShell。
  • Prompt 根据真实工具集合生成。
  • CompletionGuard 识别 Action 证据。
  • 旧工具模式保留为显式 Legacy Profile。

非目标

  • 新增图形审批弹窗；本轮 auto/deny 策略显式配置。
  • 新增 TUI Capsule 专用按钮；继续复用 transfer CLI。
  • 改变 TUI 的会话、子 Agent 和 Rich Render 布局。

4. Tool Profiles

Profile工具完成证据
portable 默认Workspace 文件、Search、Patch、Portable Git、应用 Actions；无 exec/job最后一次写入之后必须成功执行 Action
legacy 显式Portable Profile + VirtualShell exec/job最后一次写入后成功 exec/job_read，或 Action
通用 Model 不能运行 Python/Node/Git binary。需要真实命令时，由嵌入 TUI 的应用注册 --action-script。

5. 动态 Prompt

  • 只描述 Composition 中实际激活的 ToolPack。
  • 不存在 exec 时不出现 VirtualShell 指令。
  • Git 可用时明确说明 git_* 工具。
  • 列出 Application Action ID，不列宿主机绝对路径和二进制路径。
  • Project 仅显示逻辑项目名，不显示本机 root。

6. 审批与完成门禁

模式行为
--approval auto 默认加载 Session 后显式恢复 sandbox-auto；网络等策略仍由 Policy Engine 决定
--approval deny需要审批的调用被拒绝，UI/Agent 必须看到 denied

CompletionGuard 以行顺序判断，历史 Action 不能验证后续新写入。

7. TUI CLI

tinyai-tui [workspace]
  --tool-profile portable|legacy
  --approval auto|deny
  --action-script id:script:title

example:
  tinyai-tui ./game \
    --action-script app.game.check:check:Run game validation

8. Workspace Capsule 导出

TUI 在空闲状态下使用 Ctrl+X 导出当前 Workspace。导出前 flush 所有 Session，写入 Project、Portable Git、AgentState、Artifact、Evidence 和 Environment；有 queued/running/waiting Session 时拒绝导出，避免把运行中资源伪装成已封存状态。

default:
  <workspace>/.tinyai/exports/workspace-<timestamp>.capsule

fixed:
  --capsule-export /path/to/workspace.capsule

导出成功后状态栏显示完整路径；失败显示结构化状态消息，不终止 TUI。

9. 架构不变量与禁止状态

  • TUI 与 Headless 只能通过共享组合函数生成 Coding ToolPack。
  • Prompt 工具与 ToolRegistry 激活集合一致。
  • Portable Profile 不得注册 exec/job。
  • Action 缺失必须显示 unavailable，不得隐式回退 shell。
  • Action 失败、denied、absent 不得完成需要验证的写入任务。
  • Session 历史证据不能验证当前宿主或后续修改。
禁止只在 Headless 修复能力或只在 TUI 硬编码 Action。任何 Consumer 未接通都视为需求未完成。
