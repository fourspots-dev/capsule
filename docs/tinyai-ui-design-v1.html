DETAILED UI DESIGN · v1.0

老版 tinyai 的视觉，任务式 Agent 的信息层级

保留当前恢复的旧版样式和紧凑感，只吸收 ZCode 已被验证的交互模型：一轮任务由用户输入、可折叠工作过程、最新回答和尾随状态组成；工具、审批和子 Agent 使用语义化摘要，原始事实按需展开。

视觉基线 开发开始时 tinyai UI 交互基线 ZCode 3.17.1 产品边界 Chrome Side Panel 状态 待评审
唯一 UI 入口

Side Panel 只有一套渲染代码。旧视觉是设计语言，不是第二套 Legacy Runtime，也不存在 UI 开关或双入口。

01

设计原则

单一事实

Projection 驱动

消息、任务、队列、审批、子 Agent 和后台资源都来自 Runtime Projection。UI 只维护草稿、展开、滚动、焦点和标签页。

渐进披露

结果优先

最终回答始终可见；过程默认按轮次折叠。正常运行不打断阅读，异常和等待用户时强制展开相关上下文。

语义呈现

不展示原始协议

工具按领域渲染摘要，JSON、命令输出和大图只在需要时展开，不把 Runtime 数据形态直接丢给用户。

可恢复

断线不改事实

连接中断只影响当前 attachment。重连后以 snapshot 重建视图，不能把本地 UI 猜测覆盖到权威状态。

紧凑

默认低干扰

保留旧版白底、轻分隔、圆形按钮和单列布局。避免常驻大面板、重复状态、彩色药丸和持续动画。

可操作

每个阻塞都有出路

错误必须给出原因和恢复动作；审批、问答、接管和断连都要有明确主操作，不能只显示状态词。

02

视觉基线

直接保留

  • 白色页面、浅灰气泡和弱边框
  • 左上圆形新建/历史，右上圆形设置
  • 底部单输入壳、圆形发送按钮
  • 紧凑消息列和无卡片正文
  • Settings/Connections/History 老版行布局

明确不采用

  • 再引入 Leia 的蓝色品牌和 44px 顶栏
  • 复制 ZCode 的桌面三栏和复杂 Header
  • 默认深色主题
  • 每个状态都显示彩色胶囊
  • 把思考链全文常驻展开
视觉回归的判定

以开发开始时 420×900 的原始截图为基线。新增过程组件只能插入既有阅读流，不改变主输入区、顶栏和消息气泡的基础尺寸。

04

轮次渲染模型

Protocol 的 rows 是扁平事实；UI 先构建 TurnRenderUnit，再渲染可见结构。

UserInput→WorkSegment[]→LatestAssistant→TailRows
对象职责不变量
TurnRenderUnit一轮用户任务的视觉边界用户输入与对应过程不得跨轮拆散
WorkSegment一次原始输入或 guided input 的工作段每段独立统计时间与折叠状态
HistoryRowreasoning、tool、subagent、compact 等过程行只影响 UI 可见性，不复制协议事实
LatestAssistant当前轮最新完整回答始终位于折叠过程之外
TailRow验证、fork notice、goal 状态等收尾行位于回答之后，不藏进过程折叠
05

工作过程折叠

运行中

过程展开

顶部不重复显示“工作中”。底部显示 13px 运行指示、稳定状态和计时。

正常完成

默认折叠

过程收为“已工作 N 秒”，最终回答完整保留在折叠区外。

异常

强制展开

失败、中断、拒绝或缺少最终回答时，用户必须看到上下文和恢复动作。

引导输入

独立分段

同一任务中的引导输入保留独立段、独立时间与独立折叠入口。

ZCode 3.17.1 最新行为

整个 product turn 运行期间不显示顶部历史状态或分割线；整轮结束后才显示各段完成状态。TinyAI 直接采用这一降低重复信息的策略。

06

思考展示

允许展示

  • Provider 明确返回的 reasoning / thought 字段
  • 模型自己生成的用户可见计划摘要
  • 本地运行状态、工具阶段和等待原因

禁止展示

  • 把隐藏 chain-of-thought 当作 UI 内容
  • 伪造推理文本
  • 把“Thinking”状态冒充实际 reasoning
  • 默认把长推理全文展开

设置名称为“显示思考过程”。新用户默认开启入口；每个 reasoning 块默认收起。若 Provider 不返回 reasoning，仅显示真实运行状态。轮次完成后保留思考入口，不自动删除历史。

07

工具卡设计

外层统一，内容按 family 注册 Renderer。收起态必须能回答“做了什么、对象是什么、结果如何”。

Family收起摘要展开内容
Explore图标 · 查阅 · 当前查找/读取目标read/snapshot/find/tab 列表等连续只读操作
Browser Action浏览器动作 · 目标元素或 URL参数、结果、截图、错误与重试
Terminal终端 · 命令 · 状态stdout/stderr、退出码、截断或 artifact
Changes更改 · N files · +N -N文件列表、inline diff、打开 Diff Viewer
SubAgentBot · Profile · 当前子活动brief、最新子活动、结果摘要、打开 child session
Artifact文件图标 · 名称 · 类型预览、下载、源数据
Permission风险图标 · 动作 · 等待审批影响范围、规则、一次性/长期选项
状态词规则

运行中显示动作态；终态回到稳定类别词。成功状态不要额外显示“已完成”药丸；失败、拒绝、停止才显示状态。

08

连续工具聚合

Explore

连续只读操作达到 2 个后聚合。最新子动作滚动显示；展开查看全序列。

Changes

连续写文件操作聚合为文件摘要。按路径去重并保留首次顺序。

Terminal

连续命令聚合，保留失败/停止计数；展开后逐条查看输出。

聚合只属于 UI view model。单条工具仍保留原始 identity、状态和 artifact；Visible reasoning、最终回答、审批和其他 family 会切断聚合段。

09

子 Agent

子 Agent 不使用固定 Researcher/Reviewer 白名单。任意 AgentProfile 都由 name、displayName、instructions、tools、permissions、execution 和可选颜色描述。

父会话

  • 一行 Bot · Profile · 当前摘要 · 状态
  • 运行中自动展开，完成后自动收起
  • 不镜像 child 的完整工具日志
  • 点击 View 打开 child session

Child Session

  • 只读完整会话与工具过程
  • 独立 Runtime 事实，不复制父消息
  • 支持 SendMessage、Stop、Resume
  • 后台任务可从状态面板进入
10

Composer

固定结构

  • 输入框本体
  • @ 标签页
  • / Skills 与命令
  • + 附件与引用
  • 模型、审批模式、发送/停止

压缩顺序

  1. 隐藏模型名，保留 Package 图标
  2. 隐藏审批文字，保留盾牌
  3. 隐藏次要技能入口到 / 菜单
  4. 保持输入、附件和发送按钮可用

Composer 只在当前 sessionId/draft scope 内保存草稿。切换会话前先持久化旧 scope，再恢复新 scope；聚焦请求若跨 scope 则失效。

11

队列与引导

输入→startNow / guide / queue→Runtime admission→Projection queue
  • 运行中普通输入由 Runtime 决定立即执行、引导当前轮或入队。
  • UI 不维护第二份 accepted queue，只显示 Projection 事实。
  • 队列项支持立即发送、删除、排序；编辑等同于撤回后恢复草稿。
  • Guide 属于当前轮，不显示为可编辑队列项。
12

审批、问答与接管

风险

审批卡

按工具 family 展示命令、diff、URL 或 Browser action。至少提供拒绝和允许；可按产品范围增加本次/站点/会话规则。

输入

问答卡

在底部 Dock 内显示单选/多选/自定义输入。等待用户时隐藏“正在工作”。

接管

Handoff

显示人工操作原因、继续与取消。继续前必须重新观察页面，不能假设操作成功。

表面隔离

Settings 或 child session 打开时，底层 workspace 保持挂载但必须设置 inert 与 aria-hidden，避免后台审批抢焦点。

13

紧凑状态面板

状态入口默认一行，仅在存在内容时显示。优先级：运行中工作流 → 当前计划/Goal → Git Changes → 后台 Terminal/SubAgent。点击展开为分区摘要。

分区内容操作
Plan / Todo当前进度、待处理项打开计划详情
BackgroundTerminal 与 SubAgent 运行计数停止、打开 child session
Artifacts当前任务产物预览或下载
14

子会话、Artifact 与 Browser

TinyAI 的核心宽度通常低于 ZCode 桌面窗口，因此不做完整三栏常驻布局。

窄屏 ≤ 520px

子会话、Artifact、Plan 详情使用全页覆盖层；返回后恢复原滚动位置和打开来源。

宽屏 > 720px

可使用右侧滑入面板，但主对话不被永久压缩；User 可主动关闭。

15

Settings 与 History

  • 保持旧版全屏页面和列表节奏，不在未完成的新 Dashboard 上继续补丁。
  • 分组：通用、模型、权限、Agent 能力、关于。
  • History 以任务标题、状态、更新时间和消息数展示；删除操作有确认。
  • 模型配置错误必须直接引导到 Connections，不显示笼统的 runtime disconnect。
16

空态、连接与错误

空态

logo、品牌问候和三个任务建议。窄屏建议纵向排列，问题 chips 自动换行。

连接状态

初次断线显示“正在重连”；自动重连两次；失败后才显示重新加载扩展。无模型配置显示配置错误而非断连。

错误区固定在 Composer 上方，可关闭；模型 401/429/5xx 区分展示，并保留原任务和草稿。

17

响应式、主题与无障碍

320px

隐藏非关键标签和工具 secondary text。

390–520px

主目标宽度；单列、紧凑 Composer。

736px

可使用紧凑状态侧栏与更宽工具摘要。

1024px+

可选右侧侧面板；不改变会话事实。

  • 旧版默认浅色，同时完整支持浅/深/跟随系统。
  • 所有可折叠行必须支持 Enter/Space，并提供 aria-expanded。
  • 计时通过 aria-live 以低频状态播报，不逐 100ms 播报。
  • prefers-reduced-motion 下关闭 shimmer、滚动和淡入。

21

验收标准

视觉

  • 420×900 主界面与开发时基线一致
  • 320/390 无横向溢出
  • Settings/History 返回恢复滚动位置
  • 仅一套 UI 入口

过程

  • 运行中过程展开，完成后折叠
  • 失败/中断强制展开
  • 回答与尾随状态不被折叠
  • 引导输入独立分段

工具与审批

  • 工具摘要不暴露原始 JSON
  • 连续工具正确聚合
  • 审批按 family 渲染
  • 等待用户不显示工作中

恢复

  • 断线自动重连
  • 无配置显示真实配置错误
  • snapshot 重建不回放本地猜测
  • 重新加载后任务事实一致
