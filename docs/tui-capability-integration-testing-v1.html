REQ-TUI-002 / TUI INTEGRATION / TEST DESIGN V1

TUI 能力组合与架构完整性测试

证明 TUI 不是单独特例：它与 Headless 共用同一组合逻辑，Portable 默认无 shell，Action、Prompt、Verifier、Session 恢复和伪终端用户旅程全部接通。

1. 策略

必须证明

  • TUI/Headless 使用同一组合函数。
  • Portable 无 exec；Legacy 才保留。
  • Prompt 与 ToolRegistry 一致。
  • Action 成功位于最后写入之后才可完成。
  • denied/absent/failed 都能阻断误完成。

拒绝的假成功

  • 只测 Headless 就认为架构完成。
  • TUI 启动成功但工具集合未迁移。
  • Prompt 描述不存在的工具。
  • 历史 Action 被用来验证新修改。
  • Action 缺失时静默换 exec。

9. 发布门禁

  • npm run check 包含共享组合、Prompt 和 Guard 测试。
  • npm run test:e2e 保持通过。
  • 伪终端 TUI 使用真实模型或固定模型完成输入/响应闭环。
  • Portable 默认工具快照不得含 exec/job。
  • Ctrl+X 导出产生可读取的非空 Capsule。
  • 任何 TUI/Headless 分叉实现阻止发布。
