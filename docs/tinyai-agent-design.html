ARCHITECTURE SPECIFICATION

从一个浏览器循环，走向可靠的 Agent 运行时

tinyai Agent 2.0 的核心目标，是让任务在 UI 关闭、模型异常、工具失败、等待审批和浏览器重启之后仍然拥有明确状态，并能安全恢复。浏览器自动化与未来代码沙盒都只是可替换的执行适配层，不应渗入 Agent 内核。

文档状态 Design Ready 目标版本 Agent Kernel 1.0 当前基线 tinyai 0.1.0 适用范围 Chrome MV3 → 服务化 Runtime
核心判断

先完善 Agent 内核，再增加沙盒工具。第一阶段不追求复杂 Planner 或无限层级多 Agent；优先建立持久状态、结构化工具协议、上下文预算、真实取消和可重复评测。

01

范围与设计原则

目标不是单纯增加工具数量，而是把当前“侧栏中的一个 Promise 循环”升级为可承载浏览器控制、代码工作区和子 Agent 的通用任务引擎。

01

任务优先

任务状态是事实来源。聊天消息只是任务的一部分，不能代替生命周期、检查点和工具审计。

02

副作用可恢复

写操作前先记录意图，执行后记录结果。恢复必须避免重复点击、重复执行命令或重复修改文件。

03

上下文隔离

父 Agent、子 Agent、网页内容和仓库内容各有独立上下文与信任标签，不共享可变全局状态。

04

能力授权

审批依据是文件、进程、网络、浏览器和子任务等能力，而不是简单的“工具安全/不安全”二分法。

05

执行适配层

Agent 只依赖 ToolProvider 与 WorkspaceProvider；浏览器、容器、WASM 运行时可以替换。

06

先验证再宣告

模型输出不等于任务完成。必须由确定性验证器、测试结果或独立审查员确认结果。

现状保留

已有能力

  • OpenAI 兼容流式对话与工具调用
  • 30 个浏览器工具与基础审批卡
  • 按标签页管理会话和历史
  • 手动 /compact 与基础输出截断
  • 工具、模型超时与停止按钮
本期边界

Agent Kernel 1.0

  • 持久化任务状态机与事件日志
  • 结构化工具协议和真实取消
  • 自动上下文预算与压缩
  • 只读研究员、审查员子 Agent
  • 确定性假模型 / 假工具评测
明确不做

本期不开放子 Agent 直接写共享工作区，不实现无限层级自治，不把网页 evaluate 当作 shell，不依赖 MV3 Service Worker 中一个长生命周期 Promise 来保存任务。

02

系统划分为控制面、Agent 内核、策略与持久层、执行适配层四个边界。任何副作用都必须经过 ToolExecutor 与 PolicyEngine。

边界职责禁止事项
控制面展示状态、接收用户命令、收集审批、审阅 diff 与产物不得直接修改任务状态或调用执行器

03

核心模块

模块之间通过明确接口通信。第一版建议单活任务，但模块边界必须允许后续独立任务和子 Agent 并行。

AR核心

AgentRuntime

任务状态机与执行编排

领取任务、推进状态、调用模型或工具、处理等待、预算、恢复和终止。所有状态迁移必须经过统一转移函数。

start(task) · resume(id) · pause(id)
cancel(id) · step(id)
MG已有基础

ModelGateway

模型协议归一化

把不同供应商的文本增量、工具调用、usage、finish reason 和错误归一成统一事件，处理有限重试和速率限制。

stream(request, signal)
→ AsyncIterable<ModelEvent>
CM已有雏形

ContextManager

上下文预算与压缩

构建模型输入、估算 token、保留固定事实、压缩历史和将大结果转为 artifact 引用。

build(task) · measure()
compact() · pin(fact)
PL新增

Planner

轻量任务状态与重规划

维护目标、约束、短计划、观察和未解决问题。检测无进展与计划偏离，不持久化冗长推理。

init(goal) · update(observation)
replan(reason) · progress()
TE已有雏形

ToolExecutor

工具校验、调度与生命周期

解析调用、验证参数、查询策略、执行、取消、重试并将结构化结果写回事件日志。

validate(call) · authorize(call)
execute(call) · cancel(callId)
PE重构

PolicyEngine

能力级权限与审批

依据执行位置、能力、风险、任务来源和已授权 profile 做决定；审批绑定具体参数摘要与有效期。

decide(action, context)
→ allow | ask | deny
SC第二阶段

SubagentCoordinator

子任务树与结果汇总

创建独立上下文的子任务、继承收窄后的权限、控制并发与预算、聚合结果并传播取消。

spawn(brief) · send(id)
wait(id) · cancelTree(id)
TR新增

TaskRepository

持久任务与检查点

保存任务快照和 append-only 事件。通过适配器支持 chrome.storage.local、IndexedDB 或远端任务服务。

create() · saveSnapshot()
append(event) · replay(id)
AD已有工具层

ExecutionProviders

浏览器与未来沙盒适配

封装 chrome.tabs、chrome.debugger、文件、PTY 和网络。Agent 内核不直接依赖具体 CDP 调用。

BrowserProvider · WorkspaceProvider
SandboxProvider · ArtifactStore
OB新增

TraceRecorder

可观测性与审计

记录模型请求摘要、工具调用、审批、预算、耗时、错误和子任务关系，支持任务回放和指标聚合。

record(event) · span(name)
redact(secret) · export()
04

运行循环与状态机

运行循环必须可暂停、可恢复、可取消，并在每一步之后拥有明确的持久状态。

01 / CLAIM领取任务与预算，确认版本和检查点。
02 / CONTEXT构建带来源标签的模型上下文。
03 / MODEL流式调用模型并归一化事件。
04 / DECIDE得到最终文本、工具调用或等待指令。
05 / TOOL验证参数、授权、执行并记录副作用。
06 / UPDATE更新计划、预算和滚动摘要；循环或结束。

状态定义

queued已创建但尚未获得执行槽位；可跨进程重启保留。
running正在内部编排；模型和工具阶段有独立等待状态。
waiting_model请求已发出，保存请求摘要、尝试次数和取消句柄。
waiting_tool工具已开始，记录调用 ID、幂等键与取消句柄。
waiting_approval等待用户授权，审批绑定 exact action digest。
waiting_user登录、验证码或补充信息等人工步骤。
paused用户暂停或预算冻结；保留恢复入口。
completed目标已验证，所有子任务与工具调用均已收敛。
failed不可恢复错误或预算耗尽，包含结构化恢复建议。
cancelled所有后代任务和后台副作用已经终止。

强制不变量

  • 状态迁移先写事件，再写快照。
  • 同一任务只有一个写入租约。
  • 每个副作用调用都有稳定幂等键。
  • 审批不可跨任务、跨参数复用。
  • 取消必须传播到模型、工具和子任务。
  • 预算耗尽先暂停，再决定失败或续期。

05

交互设计

交互采用命令 / 事件模型：UI 只发送意图，Runtime 负责状态变化，UI 订阅事件重新投影。切换场景查看主要流程。

01
UI
提交任务发送 StartTask，包含目标、附件引用、会话和当前工作区。
02
AgentRuntime
创建持久任务分配 taskId，保存目标、约束、预算、策略 profile 和 revision=0。
03
ContextManager
组装上下文加入规则、计划、相关消息、观察和工具 schema，并估算 token。
04
ModelGateway
流式响应输出文本增量或完整工具调用；记录 usage、延迟和 provider request ID。
05
ToolExecutor
执行工具验证参数与策略，发出 tool.started，再写入 tool.completed 或 tool.failed。
06
Planner
更新进度吸收观察结果，必要时重规划；检测重复调用、无进展和预算消耗。
07
Verifier
完成前验证运行确定性检查或独立审查；只有验证通过才迁移到 completed。
01
Parent
识别可拆分任务确认子任务边界清楚、可独立验证，且收益大于额外 token 和延迟。
02
Coordinator
生成任务简报只传目标、事实、artifact 引用、工具白名单、预算和结果 schema。
03
Child Agent
独立执行拥有独立上下文、事件日志和 revision；权限为父任务权限的子集。
04
Child Agent
结构化回传返回摘要、证据、artifacts、发现和未解决问题；不返回完整 transcript。
05
Parent
验证与合并检查证据和权限边界，决定采纳、补问或取消。写操作仍由父任务控制。
01
ToolExecutor
生成动作摘要规范化工具名、参数、目标资源、执行位置和幂等键。
02
PolicyEngine
返回 ask动作超出自动授权范围，创建 approval.requested 和过期时间。
03
UI
展示审批卡显示动作、影响范围、风险、预计副作用和“允许一次/拒绝”。
04
PolicyEngine
验证审批检查 taskId、action digest、revision 和 TTL；参数变化后旧批准失效。
05
ToolExecutor
执行一次写入 approval.consumed 后再开始执行，恢复时不复用已消费审批。
01
Host
进程中断侧栏关闭、worker 回收或 Runtime 重启；持久事件日志仍然保留。
02
TaskRepository
读取快照获取最后确认的 revision、未完成动作和取消状态。
03
AgentRuntime
获取写入租约使用 fencing token 阻止旧进程和新进程同时写同一任务。
04
RecoveryPlanner
判断动作状态未开始则重试，已成功则吸收结果，未知则进入人工确认。
05
AgentRuntime
从检查点继续恢复 waiting 状态或执行下一步，并发出 task.resumed 供 UI 重放。

数据模型与事件日志

使用“当前快照 + append-only 事件”的组合。快照用于快速恢复，事件用于审计、UI 重放和故障定位。

存储分层

  • chrome.storage.local：设置、连接索引和当前任务指针。
  • IndexedDB：任务快照、消息、事件日志、审批与 trace。
  • ArtifactStore：截图、长工具输出、测试日志、PDF。
  • Sandbox volume：仓库与代码工作区，不进入浏览器消息历史。

版本与一致性

  • 任务快照带单调递增 revision。
  • 事件带任务内单调 seq，重复 eventId 幂等。
  • 执行租约带 fencing token，旧执行者写入会被拒绝。
  • 事件不可修改；修正通过补偿事件表达。
  • UI 可以从快照和缩略事件流重建。
08

工具协议与审批

工具不是“函数名字符串”，而是一份可供校验、授权、取消、重试和审计的契约。

字段用途示例
capabilities声明能力边界browser.read / fs.write / process.exec
effects标识是否改变外部状态read / write / execute / network
risk决定默认审批行为low / medium / high / critical
idempotent是否允许安全重试true / false
inputSchema模型参数校验JSON Schema
timeoutMs服务端硬超时120000
cancellable超时是否真正停止工作true
outputSchema结构化结果与 artifact 引用{ text, artifactId?, metadata }

能力级策略

通常自动

低风险只读

当前工作区读取、快照、只读搜索、状态查询。仍受资源范围与速率限制。

默认询问

有副作用

工作区写入、浏览器点击提交、下载、子任务创建、外部网络连接。

默认拒绝

高风险 / 越界

宿主敏感目录、任意 shell、凭据读取、私网、生产部署和不可恢复删除。

审批不是一次永久授权

审批必须绑定 taskId、revision、规范化参数摘要、执行位置和有效期。动作参数或目标资源变化后，旧审批自动失效。

09

上下文管理

上下文不是一段不断增长的消息数组，而是有预算、有来源、有优先级的结构化输入。

规则 15%
计划 15%
对话 35%
观察 25%
预留 10%

比例是初始默认值，按模型窗口和任务类型可配置。

上下文层级

  1. 固定系统规则、安全边界和输出协议
  2. 目标、约束、计划及不可丢失的事实
  3. 近期用户消息和 Agent 决策摘要
  4. 工具观察、artifact 摘要与 source 标签
  5. 按需检索的完整文件或网页片段

压缩触发

  • 70%：提示接近上限并准备 artifact 化。
  • 85%：自动进行结构化摘要。
  • 95%：停止新模型调用，等待压缩或人工处理。
  • 压缩失败不得删除原始事件。
  • 摘要保留决策、URL、路径、测试状态和未完成任务。

子 Agent 设计

子 Agent 是真实子任务，不是模型角色扮演。第一阶段只开放只读研究与独立审查。

研究员

Researcher

代码或网页搜索、事实收集、方案比较。输出 claim + evidence，不允许修改。

审查员

Reviewer

独立复现问题、检查需求和测试结果。不能依赖实现者自己的结论。

沙盒后

Implementer

在独立 worktree 或工作区产出 patch/commit，由父 Agent 负责验收合并。

治理项约束原因
最大深度2（父 → 子）控制成本、延迟与不可解释的递归。
默认并发2 个只读子 Agent先验证并行收益，避免资源争抢。
权限继承子权限 = 父权限 ∩ 角色白名单子任务不能提升授权。
共享写禁止写任务必须使用隔离工作区。
结果大小结构化摘要 + artifact 引用避免回传整个 transcript。
取消父取消递归传播防止孤儿任务继续产生副作用。

宿主逃逸

失败处理与恢复

错误必须分类处理。模型不应靠不断重试来“猜”系统是否已经产生副作用。

场景处理是否重试
模型 429 / 5xx / 网络中断指数退避，记录 provider request ID有限次、仅未收到有效输出时
工具参数 JSON 无效拒绝调用，反馈结构化 schema 错误由模型修正，不盲目执行空参数
工具超时触发真实取消；查询幂等账本仅 idempotent 且状态可确认时
瞬时工具错误分类为 retryable / permanent按工具策略限次重试
审批等待持久化 waiting_approval，可跨重启审批过期后重新询问
进程或浏览器重启恢复快照并重放未完成事件按动作状态继续或人工确认
重复副作用风险使用幂等键和动作结果查询未知状态禁止直接重复执行
子 Agent 失败父 Agent 收到结构化失败，可放弃或重派新子任务必须使用新预算
预算耗尽进入 paused，展示消耗和继续所需预算等待用户显式续期
恢复原则

“没有观察到失败”不等于“操作成功”。对于点击、提交、文件写入和命令执行等有副作用动作，恢复时必须查询幂等账本或适配层状态；无法确认时进入人工确认。

安全与信任边界

网页、仓库、工具输出和子 Agent 报告都可能是不可信数据。系统指令、用户意图和执行策略必须分层处理。

信任标签

  • system：平台规则，最高优先级。
  • user：当前用户输入。
  • derived：Agent 生成的摘要与计划。
  • untrusted：网页正文、仓库文件、第三方 API、工具输出。

数据保护

  • 模型 key、Cookie、token 和环境变量不可进入普通日志。
  • 网络响应体默认摘要化，完整内容作为受限 artifact。
  • artifact、任务和事件按 workspace 与用户隔离。
  • 导出、下载和外部网络访问分别授权。
  • 子 Agent 继承收窄权限，无法自我提升。
威胁控制验证方式
网页或仓库提示注入来源标签、指令隔离、能力审批、危险动作默认询问恶意 fixture 不应触发未授权工具
路径穿越与符号链接canonical path、工作区根约束、openat 风格检查../、绝对路径、symlink 逃逸测试
凭据泄漏SecretBroker、日志脱敏、禁止 artifact 搜索密钥金丝雀 token 全链路扫描
审批重放action digest + task revision + TTL修改参数后旧批准必须失效
子 Agent 越权父权限与角色白名单求交集子任务无法调用父任务未授权的工具
14

可观测性与评测

没有确定性测试和结构化 trace，就无法判断 Agent 变聪明了还是只是变复杂了。

Trace

执行轨迹

模型、工具、审批、子任务、恢复与取消组成一张任务时间线。

Eval

可重复场景

假模型按脚本返回调用，假工具提供可控成功、失败和延迟。

Metric

核心指标

成功率、恢复率、工具错误恢复、步骤数、延迟、token 与费用。

Audit

安全审计

每次授权、取消、拒绝、沙盒越界尝试和子任务树变化。

首批评测场景

  • 模型返回非法工具参数后可自恢复
  • 工具超时后底层操作确实停止
  • 审批卡出现、拒绝、允许和过期
  • 任务运行中关闭 UI 后重新打开
  • worker 回收后从检查点恢复
  • 重复工具调用被检测并抑制
  • 上下文达到阈值自动压缩
  • 截图和长输出转为 artifact 引用
  • 子 Agent 无法扩大父任务权限
  • 父任务取消会终止全部子任务
  • 恶意页面不能诱导越狱执行
  • 同一事件日志回放得到同一 UI 状态

实施路线

每个阶段必须有可以独立验收的产物。不要在状态与权限还没稳定时提前堆更多执行工具。

P0

建立可重复基线

先让 Agent 在没有真实模型和浏览器时也能被测试。

  • 抽取 ModelGateway 与 ToolExecutor 接口
  • 增加脚本化假模型和假工具
  • 建立事件、状态和任务快照类型
  • 记录现有行为作为回归基线
P1

持久任务内核

任务离开侧栏内存，拥有可恢复的生命周期。

  • 状态机、事件日志和 revision
  • 写入租约与 fencing token
  • 审批和人工等待持久化
  • 真实取消模型流与工具
  • UI 改为订阅事件投影
P2

上下文与工具契约

让长任务、失败恢复和不同模型都变得可预测。

  • token 预算和结构化自动压缩
  • 大输出 artifact 化
  • 工具 schema、风险、幂等和取消
  • 模型重试、usage 和速率限制
  • 能力级审批 profile
P3

只读子 Agent

在单任务内核稳定后验证上下文隔离和独立审查价值。

  • Researcher / Reviewer 角色
  • 父子任务树与预算隔离
  • 权限求交集与递归取消
  • 结构化结果和证据聚合
  • 并发最多 2 个只读子任务
P4

沙盒与写任务

接入隔离执行层后，再开放代码修改和工具执行。

  • WorkspaceProvider 与 SandboxProvider
  • 文件、patch、PTY、测试和 artifact
  • 独立 worktree 与网络策略
  • 写任务的 diff、验证和合并协议
  • Implementer 子 Agent

验收标准

完成以下标准后，才算具备“可靠 Agent 内核”，而不只是拥有一个工具很多的聊天框。

功能验收

  • 关闭侧栏或 worker 回收后任务可恢复
  • 任务可被模型、工具、审批或用户暂停
  • 停止操作真正取消模型流和工具
  • 非法工具调用会产生可恢复错误
  • 上下文超过阈值时会自动压缩
  • 大输出以 artifact 引用参与后续上下文
  • 只读子 Agent 能独立执行并结构化回传

质量与安全验收

  • 所有副作用都有幂等键和审计事件
  • 恢复不会重复点击、提交或写文件
  • 审批与具体动作摘要、revision 绑定
  • 子 Agent 无法提升父任务权限
  • 不可信页面内容不能绕过策略
  • 事件回放可重建相同 UI 状态
  • 核心评测场景全部通过并持续运行
关键设计决策记录
  • 为什么事件日志与快照并存？ 快照恢复快，事件流提供审计和回放；聊天消息不足以表达审批与工具生命周期。
  • 为什么先不开放写子 Agent？ 没有工作区隔离和合并协议时，多个 Agent 共享写入会引入不可追踪竞争。
  • 为什么不一开始做复杂 Planner？ 可靠状态与上下文收益更确定；复杂规划应通过评测逐步引入。
  • 为什么将来需要沙盒服务？ Chrome 扩展不是宿主文件系统执行边界；代码执行需要独立进程、资源限制和网络策略。
  • 为什么审批按能力而不是按工具名？ 同一工具会因参数、目标和执行位置具有不同风险。
