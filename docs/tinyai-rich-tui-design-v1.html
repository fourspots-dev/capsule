styled.ts 已提供主题 token、色彩深度与 ANSI span；render.ts 使用 StyledLine 构图，并保留纯文本 render 供测试与降级。

Composer/Search 已使用绝对 CursorTarget、原生闪烁与显隐控制；User/Assistant/Reasoning/Tool/Result 已采用 0/2/4 列 gutter，并对中间消息、超长输出和活动回合做差异化处理。

目标不是把每一个元素都装进彩色盒子，而是建立一套“语义样式 → Block → Panel → ScreenBuffer → ANSI”的渲染体系。

非目标

不做像素级 GUI

TUI 不模拟网页布局，不依赖图片、鼠标 hover 或浏览器 CSS。

不默认常驻三栏

Panel 是上下文容器，不是永久 IDE 侧栏。

不展示隐藏 Chain-of-Thought

只展示 Provider 实际返回且允许展示的 reasoning 字段。

不允许内容直接着色

外部文本先解析为安全 styled span，不能携带任意终端控制序列。

3. 设计原则

语义先于颜色

先定义这个元素是什么，再决定主题色。扩展和主题变化不能改变状态含义。

内容优先

最终回答、用户目标和输入区优先级最高。Panel 边界不能压缩到无法阅读。

渐进披露

摘要始终可见，原始参数、完整 Reasoning、日志和 Diff 按需展开。

真实状态

Waiting、Reasoning、Running、Verifying、Failed 是不同状态，不使用一个模糊的 Thinking 文案代替。

稳定布局

流式文本到达时，Panel 不跳位；用户手动向上滚动后暂停自动跟随。

可测试渲染

布局和样式先生成 ScreenBuffer，再生成 ANSI。测试可直接断言二维网格。

4.2 主题与能力降级

Theme =
  tiny-dark | tiny-light | mono

ColorDepth =
  truecolor | ansi256 | ansi16 | none

检测顺序：
  NO_COLOR / TERM=dumb → none
  COLORTERM=truecolor/24bit → truecolor
  TERM 包含 256color → ansi256
  其他 TTY → ansi16
  非 TTY → none
  • 主题切换不改变布局和状态词。
  • Diff 颜色必须有 +/- 前缀；成功/失败必须带图标或文字。

  • 颜色值通过 ThemeResolver 解析，业务 ViewModel 不直接包含 ANSI。

5.4 留白与内容预算

  • Turn gap：用户回合之间固定 1 行；同一回合的连续工具调用之间为 0 行。
  • Result priority：最终回答优先于运行历史；历史只能向上滚动，不把结果挤出屏幕。
  • Detail budget：Reasoning 默认最多 6 行，Tool 成功摘要 1 行，失败/运行中 Tool 最多 4 行，详情通过 Enter 打开。
  • Long output：超过预算时显示首尾摘要与 ▸ N more lines，不把整段 stdout 混入对话正文。
  • 窄屏：gutter 可缩为 1 列，但正文和从属层级仍必须保持可辨识的缩进差。
布局使用 Rect 计算：{x, y, width, height}。每个 Panel 在独立 Surface 上绘制后再裁剪合成，禁止内容越过 Panel 边界。

6.3 Panel 焦点

  • 焦点 token 只影响边框、标题和选中行，不改变内容本身状态颜色。
  • 内联 Panel 默认不抢焦点；Enter 展开后视图滚动。
  • Overlay 关闭时必须恢复进入前的焦点、Composer 光标和草稿。
  • 滚动遵循“手动滚动后暂停自动跟随”，到顶部/底部才恢复可选 auto-follow。

6.4 多会话与通用 Agent Board

视图信息层级交互与状态归属
Sessions overlay当前标记、任务状态、标题、项目/分支、活动、未读/注意、更新时间按会话保存草稿和滚动锚点；切换只替换 Projection 订阅，不停止旧 Session 的后台任务。
Agents overlay任意 Profile 名、层级缩进、foreground/background 模式、运行状态、摘要和 attention树形结构来自 Parent Task，不预设固定角色；过滤命中子项时保留祖先路径；Enter 进入子 Session，Esc 回到父 Session 的原看板位置。
Agent 详情 / Merge任务摘要、变更量、验证结果、风险、工作区合并入口详情是受控 overlay；合并必须先 preview 再 apply，默认不改父 Working Copy。
Session 与 Agent 导航共享同一套 Route 栈和焦点恢复规则。背景事件只能更新状态和摘要；除非用户主动进入，不能改变当前 Session、选中项或 Composer 焦点。

7.3 Work Group

同一用户任务下的 Reasoning、Tool、Command 和子 Agent 事件合并成 Work Group。运行中展示关键活动；完成后折叠为 Worked 2m 14s · 6 tools · 2 agents，失败时保持关键证据展开。

8. Reasoning 展示

只展示 Provider 实际返回且允许展示的 reasoning_content、reasoning 或 thinking。本地“等待模型”动画不能被描述成真实推理，更不能伪造 Chain-of-Thought。

8.1 状态模型

ReasoningState =
  unavailable   Provider 不返回可见 reasoning
  waiting       请求已发出，尚未收到首个 token
  streaming     正在接收 reasoning_delta
  complete      正常完成
  failed        Reasoning 流错误或中断

ReasoningMode =
  hidden | preview | full

waitingWaiting for model · 00:03不明示为推理内容。

8.2 展示模式

hidden

只显示“Thought for 14s”入口；适合不关注推理的用户。

preview

live 显示最近 4–6 行，完成后折叠。默认推荐。

full

live 展示完整 reasoning，高度最多为屏幕的 30%，其余滚动。

8.3 交互

  • Ctrl+T 循环切换 hidden/preview/full，并在状态栏短暂显示当前模式。
  • 在 Reasoning 行或摘要上按 Enter 展开/折叠。
  • Ctrl+T 在全屏 Reasoning Inspector 中打开时，可搜索、复制和跳到最新。
  • Reasoning 与通用 Activity 行去重：存在真实 Reasoning 时，不再重复显示“Thinking”占位。
  • 默认 live 跟随底部；用户通过 PageUp/滚轮离开底部后显示“New reasoning below”，不强行拉回。

9.1 原生光标、闪烁与 IME 锚点

输入框显示静态 ▌ 字符不是完整的光标实现。真实光标必须由终端定位并显示，否则用户无法可靠判断焦点、字符插入点和 IME 组合文本位置。
CursorTarget {
  sessionId: string
  field: 'composer' | 'search' | 'confirmation'
  row: number
  column: number
  graphemeOffset: number
}

CursorState =
  hidden          overlay 打开、Panel 聚焦或失焦
  visible         Composer/Search 聚焦，等待输入
  composing       IME 正在组合，不移动锚点
  fallback        Host 不支持原生光标时的安全降级
阶段行为约束
绘制 Frame先隐藏光标并完成脏区更新，避免光标在旧位置闪烁流式正文更新不能抢走输入光标
定位根据 Composer 的实际 grapheme offset、wrap 和 Panel Rect 计算绝对 row/column中文、Emoji、组合字符和软换行不能产生列漂移
显示发送绝对定位 CSI，然后显示原生闪烁块状光标；与提示符 > 之间保留一个空格 cell默认使用终端闪烁，不由 UI 高频定时器驱动
IME组合输入期间保持光标锚点与输入法候选框位置一致Composition 事件不能误触快捷键或换行
失焦/Overlay发送隐藏光标；关闭后恢复目标 input、草稿、selection 与锚点Session 快速切换不得复用旧 Session 坐标

9.2 光标对象接口

interface TerminalCursorController {
  hide(): void
  place(target: CursorTarget): void
  show(shape?: 'bar' | 'block'): void
  capture(sessionId: string): CursorTarget
  restore(sessionId: string): void
  dispose(): void
}
  • Frame 更新顺序固定为：hide cursor → diff rows → place cursor → show cursor。
  • 光标目标保存在客户端 UI State，不进入 Session Snapshot；Session 只保存 draft 和逻辑 cursor offset。
  • 不支持 DECSCUSR 的终端使用 Host 默认闪烁；只有非标准 Host 才使用受控的手动闪烁回退。
  • 非 TTY/pipe 模式不输出任何光标控制序列。
Panel 不是一个新模式系统。用户不需要学习“普通模式 / Panel 模式”；只根据当前焦点执行同一组语义动作。

10.5 流式背压与持久化合并

Reasoning/Answer 的 Delta 可能远高于屏幕刷新频率。Projection 事件、UI Frame 和 Session Snapshot 必须分别节流，不能把每个 token 同时转换成一次全量渲染和一次全量写入。

路径合并策略一致性约束
Projection 读取Runtime 产生新对象后按不可变值传递；UI 读取不 structuredClone 全历史。消费者只读；Session 切换仍按 generation/epoch 拒绝迟到帧。
屏幕渲染RenderScheduler 约 33ms 合并，最多 30fps；resize 强制重算。最终 Frame 必须包含最后一次 Projection 状态。
会话持久化约 50ms debounce；最多一个 Snapshot 写入在途，新事件只标记 dirty。命令 ACK 前必须 flush；退出/停止时 flush 最后一次快照。
长内容解析只解析可视预算内的尾部与分段摘要，完整内容保留在 Projection/详情视图。不得丢失 Session 数据，只限制 Frame 工作量。
性能问题必须在数据流水线层解决。仅降低 TUI 刷新率但保留每 token 全量 Snapshot，仍会造成无界内存增长。

15. 完成定义

维度验收标准
视觉深/浅/mono 主题可用；正文、Reasoning、工具、成功、警告、错误、Diff 有稳定语义色。
Panel内联 Work、Reasoning、Tool、Diff、Context 和 overlay 可由同一模型渲染；resize/scroll/focus 正确。
格式化Markdown、代码、列表、表格、命令和 Diff 可读，异常输入安全降级。
ReasoningProvider 可见 reasoning 实时展示、完成后折叠、可展开搜索；不伪造、不重复 Thinking。
层级User、Assistant、Reasoning、Tool 和 Result 有稳定的 gutter/缩进/留白差异；连续内容不表现为同一列日志。
光标Composer 聚焦时原生闪烁块状光标可见，并与 > 保留一个空格；行列与 IME 锚点正确；overlay 和 Session 切换后安全恢复。
紧凑80×24 下无需侧栏，Composer 和 P0/P1 状态始终可见。
性能流式 10k 事件下按键到画面 p95 ≤ 50ms；不全屏反复 clear；内存有界。
背压高频 Delta 不产生逐事件全量渲染或 Snapshot 队列；最终文本与持久化内容完整。
安全模型/工具/扩展不能注入控制序列或越界覆盖 Panel。
测试Theme、Block、Panel、Format、Reasoning、PTY Golden、状态空间、性能和故障注入全部通过。
最终视觉目标：像成熟的终端工作台，而不是在终端里打印普通日志。紧凑时保持对话优先；需要时 Panel 提供结构化上下文；Reasoning 可观察但不抢占回答。
