Execution Debug Hub

通过出站事件上报和只读 cursor API，让外部服务实时观察 Agent 执行，同时保持 Chrome 沙盒、Runtime 权威性和安全边界。

1. 目标与非目标

目标

  • Chrome 仅通过出站 HTTP 上报执行事件。
  • 外部服务可通过 cursor 增量拉取，并通过 SSE 实时订阅。
  • 记录思考展示、工具、子 Agent、审批、Evidence、Artifact 引用和错误。
  • 服务可持久化、去重、限流、轮转和导出 NDJSON。
  • 设置页提供 Debug Service 配置和连通测试。

非目标

  • 不让 Chrome 扩展监听端口。
  • 不提供远程控制、审批或停止接口。
  • 不导出模型内部隐藏的 chain-of-thought。
  • 不把 Debug Hub 作为 Session 状态事实源。
  • 第一版不实现云端多租户 Relay。

4. 事件协议

interface ExecutionEvent {
  schemaVersion: 1;
  eventId: string;
  clientEventId: string;
  sequence: number;
  cursor: string;
  timestamp: number;
  sessionId: string;
  taskId?: string;
  productTurnId?: string;
  callId?: string;
  traceId?: string;
  parentId?: string;
  kind: 'session'|'user'|'assistant'|'reasoning'|'tool'|
        'approval'|'handoff'|'child-agent'|'evidence'|
        'artifact'|'error'|'status';
  phase: 'started'|'updated'|'completed'|'failed'|'cancelled';
  actor: 'user'|'agent'|'tool'|'child-agent'|'system';
  visibility?: 'public'|'displayed-reasoning'|'summary';
  payload: JsonValue;
}

Projection tracker 对新增 Row 发出 started，对流式文本发出 updated/delta，对终态发出 completed/failed/cancelled。子 Agent 和 Session 状态分别形成 child-agent 与 status 事件。

5. Debug Service

tinyai debug serve \
  --host 127.0.0.1 \
  --port 4399 \
  --data-dir .tinyai/debug \
  --token <pairing-token>

POST /v1/ingest
GET  /v1/sessions
GET  /v1/sessions/:id/events?after=<cursor>&limit=500
GET  /v1/sessions/:id/stream?after=<cursor>
GET  /v1/sessions/:id/export
GET  /healthz

Hub 分配全局单调 sequence；cursor 为不透明 Base64URL 数据，包含 version、epoch 和 sequence。Ingest 按 clientEventId/eventId 去重。Retention 默认 100,000 事件，超过时从最旧事件淘汰并让旧 cursor 返回 expired 或 truncated 语义。

NDJSON 第 1 版采用单目录分段文件；写入先进入内存 Hub，再异步 durable append。慢 SSE 客户端不阻塞 ingest，队列满时断开并允许 cursor 重连。

6. Chrome 集成

createChromeRuntimeBundle 读取独立 tinyai-debug-service 配置，创建 transport 和 tracker，并将 observer 注入主/子 WorkspaceRuntime。Projection observer 只观察，不改变 Runtime。

Runtime emit projection
  → tracker produces events
  → transport.enqueue
  → 100ms / 批量 flush
  → POST /v1/ingest with Bearer token
  → ACK

fetch 失败:
  queue retained
  → exponential retry
  → bounded capacity
  → status visible in Settings

关闭或未配置 transport 时，行为与当前版本完全一致。service worker 重启后丢失的内存队列不阻止 Agent；后续事件重新开始上报。

7. Settings UI

在 Runtime 设置组新增 “Debug Service” 子页，遵循 docs/ui/tinyai-sidepanel-ui-contract.md。字段为 endpoint、token、enabled；操作为 Save、Test、Disable。首页只显示 Configured/Not configured，不占用会话空间。

UI impact: yes。复用 settingsSubpage、settingsGroup、settingsForm、settingsField，不新增视觉原语。

8. 安全与脱敏

监听地址默认 127.0.0.1，非 loopback 需显式配置。
认证Ingest 与 Query 要求 Bearer Token；constant-time compare。
写入能力HTTP API 无 stop/approve/command 路由。
脱敏key 名匹配 token/apiKey/authorization/cookie/secret/password；字符串 Bearer/sk- 模式也替换。
Artifact第一版只记录引用和 metadata，不自动上传二进制。
Reasoningvisibility=displayed-reasoning；不包含内部隐藏推理。
CORS允许扩展 Origin 的 Authorization preflight；不启用 credentials。

9. 失败恢复与兼容

  • Debug Service 离线：Agent 正常执行，transport 保持有界队列。
  • ACK 丢失：重试相同 eventId，服务端去重。
  • 服务重启：读取 NDJSON、恢复 sequence 和 cursor epoch。
  • 旧 cursor 被 retention 淘汰：返回明确 CURSOR_EXPIRED 与当前 earliest cursor。
  • 事件过大：拒绝单批，不阻塞后续小事件。
  • Schema 升级：事件包含 schemaVersion，未知版本拒绝并报告。

11. 验收

  • 外部服务可先拉历史再通过 SSE 接收实时事件。
  • cursor 断线续传、eventId 去重、retention 行为可测试。
  • Chrome 不监听端口且不直接读扩展 storage。
  • 设置页可配置并测试 Debug Service。
  • 调试 API 无写控制能力。
  • 真实 Chrome E2E 中，Agent 事件到达外部 Hub。
