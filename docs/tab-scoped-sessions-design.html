TINYAI / BROWSER CONTEXT / V1

标签级独立会话
方案设计

目标是把“一个 Side Panel 对话可以切换多个标签页”改成“每个浏览器标签拥有独立 Agent Session，激活标签时自动恢复对应对话”。

状态：已实现并通过 Chrome E2E
语义模型架构启动与切换协议历史清理边界实现映射

1. 核心语义

Tab 是会话边界

以 windowId + tabId 作为浏览器会话内的标签身份。首次激活标签时惰性创建 Session，同一标签往返切换时复用。

Session 是唯一对话事实

消息、任务、队列、审批、子 Agent、草稿和运行状态都属于 Session。UI 不复制第二份会话状态。

Browser target 固定

工具默认只操作该 Session 绑定的标签。标签级模式下禁止 Agent 用 switch_tab 改变工作目标。

历史仍可恢复

History 中的旧会话可重新绑定到当前标签；原来绑定该 Session 的标签解除映射。

与旧行为对比

行为旧实现新实现
打开 Side Panel加载最近一条 Session加载当前标签对应 Session
切换标签对话不变自动切换为该标签对话
@ 选择标签只重绑工具目标切换标签并切换对话
新标签沿用当前对话创建独立空白会话
点击 +当前标签换新 Session当前标签换新 Session，旧会话保留在 History

查看标签与执行标签

TabSessionBinding
├── activeTabId       当前用户正在查看的标签
├── executionTabId    任务实际执行的发起标签
├── memberTabIds      当前工作区成员
└── sessionId         共享的会话
标签组共享 Session，但任务仍固定在 executionTabId。在组内切换查看标签只更新 activeTabId，不得调用 setWorkingTab 偷换 BrowserProvider 的目标。只有显式 switch_tab、创建新任务、绑定历史/子 Agent Session，或原执行标签已关闭时才改变执行标签。

3. 启动、切换与并发

打开 Side Panel

  1. 查询当前 Window 和 active Tab。
  2. 调用 resolve_tab_session。
  3. Registry 命中已有映射则恢复；未命中则创建新 Session。
  4. Session 完成生命周期启动并绑定工作标签。
  5. Side Panel 订阅 Projection，恢复该 Session 的草稿。

切换标签

  1. tabs.onActivated 过滤当前窗口。
  2. 保存旧 Session 的草稿、附件和 Skill 选择。
  3. 用切换代次取消过期异步结果。
  4. 解除旧 Projection 订阅。
  5. 订阅新 Session，恢复缓存草稿并渲染。
关键约束：绑定工作标签时必须传 activate:false。否则 setWorkingTab 内部的再次激活会触发 tabs.onActivated，形成切换递归。

同一组内 A→B 切换时，Session ID 与 executionTabId=A 保持不变，仅 activeTabId=B。从组外切换到组内时，显示的 Session 变为该组 Session，但执行目标仍为该 Session 原任务标签。用户明确说“处理当前标签”时，Agent 必须通过 switch_tab 显式设置 executionTabId=B。

运行中的旧标签

切走不会停止任务。旧 Session 继续在 Runtime 中运行；切回时通过 Projection 恢复最新状态。审批和接管事件按 Session 缓存，不被新标签清空。

4. Runtime 协议

请求输入输出 / 语义
resolve_tab_sessionwindowId, tabId复用或创建标签 Session，返回 Session 与 Projection
create_tab_sessionwindowId, tabId强制替换当前标签的 Session
bind_tab_sessionwindowId, tabId, sessionId把历史 Session 绑定到当前标签
forget_tab_sessionwindowId, tabId标签关闭或移出窗口时删除映射，不删除 Session
clear_history无停止并删除全部 Session、Snapshot 和标签映射

持久化

标签映射写入 chrome.storage.session，可以在 MV3 Service Worker 和 Offscreen Runtime 重建时保留。完整浏览器重启后映射清空，恢复的标签从新会话开始；历史快照仍保存在 chrome.storage.local。

5. 历史清理

Settings 提供“清除全部聊天历史”。执行顺序：停止运行中 Session → flush 持久化 → 清空 SessionStore 前缀 → 清理所有标签映射 → 释放浏览器 Debugger / 标签分组 → 在当前标签创建新 Session。

只删除 tinyai:session:v1:* 与标签映射，不删除模型连接、API Key、Skills 或用户网页标签。

Chrome Tab Group 标题不再使用内部 Session ID，而使用网页标题，例如 tinyai · GitHub，不再泄漏 legacy_* 或 session_*。

6. 边界情况

场景行为
标签关闭删除映射；若它是当前标签，自动切到同窗口的下一条 active Tab
标签跨窗口移动删除旧 windowId 映射；进入新窗口后按新标签身份创建或恢复
标签导航/刷新tabId 不变，Session 不变
标签复制新 tabId，新 Session；不复制历史
快速连续切换Registry 与 UI 都使用串行/代次控制，旧请求不得覆盖新标签
History 打开旧会话旧会话移动绑定到当前标签，原标签解除映射
非网页标签Session 可以创建，但浏览器工具会按 Chrome 可访问性规则报错

非目标

本版不通过 URL 猜测标签身份，不支持一个 Session 同时控制多个标签，也不在完整浏览器重启后尝试复用过期 tabId。
