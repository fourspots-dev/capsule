TINYAI / WORKSPACE SCOPE / V2

双作用域 Workspace 会话设计

Chrome 中，标签组共享 Workspace Session，组外标签保持独立 Session。浏览器适配器负责标签与分组；Agent Core 只处理抽象 Session 与 Workspace 生命周期。

实现状态：双作用域 Registry、Chrome 多标签 ToolPack、Agent 建组、组外隔离、Side Panel 作用域提示与 Core 边界检查已实现；TUI Adapter 只完成了接口边界与独立 CLI 构建验证。

2. 作用域模型

ScopeChrome 身份Session 规则
Grouped WorkspacewindowId + groupId组成员共享一个 Session；切换成员只改变 active target
Standalone TabwindowId + tabId每个组外标签一个独立 Session
  • 切到同一标签组内其他标签：保持 Session，只切换活动页面。
  • 切到组外标签：自动进入或创建该标签自己的 Session。
  • Agent 从组外标签打开新标签：两个标签组队，原 Session 提升为 Group Workspace。
  • Agent 在已有组内打开新标签：加入当前组，继续使用同一个 Session。
  • 成员、active target、Chrome groupId 都只是 BrowserAdapter 状态。

4. 关键流程

Chrome tabs.onActivated
  → ChromeWorkspacePort.capture(windowId, tabId)
  → tab.groupId 有效 ?
      yes → resolve group scope → sessionId
      no  → resolve tab scope   → sessionId
  → SessionManager.acquire(sessionId)
  → ChromeBrowserProvider.setActiveTarget(adapterTargetId)
  → Side Panel subscribe(sessionId)

Agent 打开新标签

  1. 当前为 Standalone Tab 时，创建新标签。
  2. Chrome Adapter 将两个标签加入同一 Tab Group。
  3. 将 Standalone Binding 提升为 Group Binding，Session 不复制。
  4. 新标签加入成员列表并设为 active target。
  5. 工具结果返回抽象 targetId，不要求模型理解 Chrome groupId。

组外与成员变化

组外标签不会进入当前 WorkspacePort。Agent 无法用工具切换到它；用户切过去时，Adapter 发出新的 WorkspaceActivation，Side Panel 才切换 Session。已有 Group Session 时新成员采用组会话；组无 Session 时提升 active member 的会话；成员移出组后下次激活获得独立 Session。

5. 工具与并发边界

工具规则
list_workspace_targets只列当前抽象 Workspace 的 targets
new_tab仅 Chrome Browser ToolPack 提供；通过 WorkspacePort 创建同 Scope target
switch_tab目标必须属于当前 Workspace；组外返回 TARGET_OUTSIDE_WORKSPACE
read / snapshot可指定 target；多个只读 target 可受限并行
click / fill / navigate目标成员校验；同 target 写入串行，高风险仍审批

只读并行

不同 target 的读取可并行，结果携带 target/session 标识。

写入隔离

同一 target 单锁；跨 target 写入默认顺序执行。

“同时操作多个标签”是浏览器 Workspace 能力，不是取消权限控制。TUI 不注册这些浏览器工具。

6. 跨端接口

interface WorkspacePort {
  capture(request: UnknownJson): Promise<WorkspaceActivation>;
  create(sessionId: string, target?: UnknownJson): Promise<WorkspaceActivation>;
  listTargets(sessionId: string): Promise<WorkspaceTarget[]>;
  activateTarget(sessionId: string, targetId: string): Promise<void>;
  assertTarget(sessionId: string, targetId: string): Promise<void>;
  release(sessionId: string): Promise<void>;
}
interface WorkspaceActivation {
  sessionId: string; workspaceKey: string;
  activeTargetId?: string; revision: number;
}

协议只使用不透明 workspaceKey 和 targetId。Chrome 可映射为 tabId，TUI 可映射为 paneId，Web 可映射为 viewportId。

与现有代码的关系

  • 保留 SessionRuntime、WorkspaceRuntime 的会话与 Projection 能力。
  • 移动现有 TabSessionRegistry 到 adapters/chrome/workspace。
  • 把 RuntimeGateway 的 tab 专用请求拆到 Browser Gateway。
  • Chrome Browser Tools 独立注册，TUI/CLI 不加载。
  • Session Snapshot 不增加 Chrome tab/groupId 字段。

7. 持久化与错误边界

数据归属存储
Session SnapshotCoretinyai:session:v1:*
WorkspaceBindingChrome Adapterchrome.storage.session
TUI pane bindingTUI AdapterTUI 自身状态文件
Chrome membershipChrome Adapterchrome.tabs/groupId + 临时绑定表

Chrome 重启后 tab/group ID 可能失效，Adapter 只清理自身映射；Session 仍可从 History 打开。TUI 和其他端不受影响。

  • Agent 操作组外标签：TARGET_OUTSIDE_WORKSPACE，不触发页面访问。
  • Chrome group 失效：清理 Chrome binding，不删除 Session。
  • TUI 启动：只生成 Standalone Workspace，不加载 Chrome Gateway。
  • 多端同时读取同一 Session 禁止同时写入，写操作使用 lease/fencing。
