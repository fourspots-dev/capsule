TINYAI / PRODUCTION CODING AGENT / ROADMAP

生产级 Coding Agent
分阶段产品设计

面向 macOS TUI、iOS 控制端和 Chrome 浏览器三端。重点不是继续堆功能，而是把 Coding Agent 做成可靠、可恢复、可审阅、跨端连续的日常开发工具。

macOS：执行与 TUIiOS：控制与审阅Chrome：页面与浏览器工作区基础权限管理
范围现状原则路线P1P2P3P4P5P6P7成功指标

1. 产品范围与端职责

macOS

权威执行端。提供 TUI、代码工作区、本地沙箱、长任务、Git、测试和子 Agent 运行能力。

iOS

连接已配对的 Mac 或远程 Workspace，查看进度、继续对话、审阅 diff、处理必要确认和接收通知。iOS 不在设备内执行任意代码。

Chrome

浏览网页、捕获页面上下文、运行浏览器 Workspace，并可把上下文交给同一 Session 继续处理。

统一体验

  • 同一个 Session 可以在 Mac TUI、iOS 和浏览器之间继续查看与操作。
  • 任务只由一个权威 Runtime 执行，其他端是客户端，不产生分离状态。
  • 终端、页面和移动端只是入口不同，历史、任务状态、审阅结果保持一致。
产品边界：只面向 macOS、iOS 和浏览器；不投入 Linux/Windows 原生客户端。权限采用“安全默认 + 高风险确认 + 项目级记住”，不做企业级 RBAC。

3. 产品原则

完成必须可证明

没有测试、静态检查或明确验证证据，不显示“已完成”。

执行必须可见

用户能看到当前任务、工具、命令、耗时、失败和下一步。

中断必须可恢复

关闭 TUI、断网或应用崩溃后，Session 和 Workspace 可以恢复。

修改必须可审阅

最终呈现文件级 diff、测试结果和未解决风险，默认不自动 commit。

跨端不复制真相

Mac、iOS、Chrome 都消费同一个 Runtime 状态，不各自维护任务历史。

默认安全但不繁琐

沙箱内常规操作自动执行；删除、网络、提交等高风险动作才要求确认。

P1

可信赖的 macOS TUI

下一阶段

F1.1 交互式 Coding Session

目标：用户可以在终端内连续对话和开发，而不是每次提交一条命令等待最终答案。
  • 流式显示回答、Reasoning 和工具状态。
  • 支持多行输入、中断、继续、补充目标和排队消息。
  • 保持代码块、diff、命令输出可读。

验收：不使用旁路编辑器，可完成一次完整的多轮开发任务。

F1.2 实时执行视图

目标：长任务始终可观察。
  • 展示当前文件、命令、测试和耗时。
  • 命令输出可滚动、可折叠、可中断。
  • 失败时明确显示失败位置和后续动作。

验收：测试运行超过 30 秒时，用户清楚知道系统正在做什么。

F1.3 会话恢复

目标：关闭终端或程序崩溃后继续上次工作。
  • Session 自动保存。
  • 支持列出、恢复、重命名和删除。
  • 恢复后展示未完成任务和最后验证状态。

验收：终止进程后重新打开，历史与工作区可继续使用。

F1.4 基础工作模式

目标：在自主执行与用户可管理之间取得平衡。
  • Plan、Build、Review 三种工作方式。
  • 高风险操作按项目确认。
  • 可停止、回滚未提交修改。

验收：普通沙箱操作无需反复确认，高风险动作有明确提示。

P2

编码质量与完成闭环

下一阶段

F2.1 项目理解

目标：Agent 进入仓库后能快速理解结构、约定和工作区状态。
  • 读取项目说明、构建配置和约定。
  • 识别干净/脏工作区、分支和未提交修改。
  • 自动选择合理测试入口。

验收：进入陌生仓库后能说明关键入口、修改范围和验证方式。

F2.2 代码搜索与编辑

目标：精确修改而不是整文件覆盖。
  • 文本搜索、文件匹配和行范围读取。
  • 增量补丁和冲突检测。
  • 保留用户并行修改，不静默覆盖。

验收：多文件修改以 diff 审阅，冲突会停止并提示。

F2.3 测试驱动修复

目标：失败结果自动进入下一轮修复，而不是直接结束。
  • Test → Failure Analysis → Patch → Retest。
  • 达到预算仍失败时明确报告。
  • 最终回答必须附验证证据。

验收：测试失败时 Agent 不会宣称完成，并至少尝试一次基于证据的修复。

F2.4 变更审阅

目标：用户可以在结束前做最终判断。
  • 文件级和行级 diff。
  • 测试、类型检查、Lint 结果统一展示。
  • 未解决风险和未覆盖场景。
  • 默认不自动 commit。

验收：用户能从最终视图判断改了什么、为何改、验证了什么。

F2.5 上下文管理

目标：大型仓库和长会话中保持有效上下文。
  • 按模型预算管理上下文。
  • 主动摘要、文件记忆和任务检查点。
  • 不重复读取未变化文件。

验收：长任务不因上下文溢出丢失目标，关键文件与决策可追溯。

P3

Workspace 与执行可靠性

P1/P2 并行推进

F3.1 macOS 本地 Workspace

面向日常开发的一等执行环境。
  • 项目目录授权、路径边界和网络限制。
  • 长命令、PTY、构建缓存和进程清理。
  • 项目级工具与沙箱配置。

验收：在真实项目连续运行构建、测试、热更新数小时，无越界和资源泄漏。

F3.2 检查点与回滚

实验失败可以恢复。
  • 自动记录会话和文件状态。
  • 按轮次回滚代码。
  • 保留用户手工修改。

验收：任务中断后可恢复到最后验证点或开始点。

F3.3 运行恢复

前台关闭不影响后台任务。
  • 后台任务与日志持久化。
  • 客户端重连恢复进度。
  • 不允许恢复已失去执行条件的危险操作。

验收：关闭 TUI 再重开，后台任务状态连续且无重复副作用。

F3.4 产物与诊断

便于审阅和排障。
  • 测试报告、截图、日志、diff 和 Trace。
  • 失败可导出诊断包。
  • 敏感信息自动脱敏。

验收：失败任务可在不泄露密钥的情况下定位问题。

P4

Chrome 能力对齐

桌面稳定后

F4.1 页面上下文交接

网页内容可以自然进入 Coding Session。
  • 把页面、选中文本、日志或文档交给当前 Workspace。
  • 明确显示引用的页面。
  • 避免把网页指令误当用户指令。

验收：从浏览器引用需求或 Bug 到开始代码任务无需手动复制。

F4.2 浏览器 Workspace

保留现有标签组能力并支持跨端。
  • 组内共享会话、组外独立会话。
  • 不隐式打开标签。
  • 浏览器任务可在 Mac TUI 查看。

验收：Chrome 中发起的任务可在 Mac 继续查看和补充。

F4.3 Web 开发闭环

页面问题可完成“定位 → 修改 → 验证”。
  • 页面快照、DevTools 信息、截图与代码修改关联。
  • 修复后重新打开页面验证。
  • 前端测试和视觉证据。

验收：可从页面 Bug 到代码 diff、测试和再次验证形成闭环。

P5

iOS 控制与审阅端

桌面 Runtime 稳定后

iOS 不本地执行任意代码。它是 Mac/远程 Workspace 的安全客户端，用于发起、查看、继续和审阅任务。

F5.1 设备配对

安全连接用户自己的 Mac Workspace。
  • 扫码或同账号配对。
  • 连接状态和撤销。
  • 不要求在 iOS 本地保存代码仓库。

验收：无需配置开发环境即可连接已运行的 Mac Agent。

F5.2 会话控制

在手机上掌握长任务。
  • 查看任务、工具、测试和耗时。
  • 继续对话、停止任务、排队补充。
  • 后台通知任务完成或需要处理。

验收：离开 Mac 后仍可判断任务状态并做基本控制。

F5.3 移动审阅

利用碎片时间审阅代码。
  • 文件级 diff、测试结果和风险摘要。
  • 逐文件查看、标记问题和要求修改。
  • 不在 iOS 自动 commit/push。

验收：手机上能完成一次完整变更审阅并发送修改要求。

F5.4 连续会话

Mac 与 iPhone 是同一任务的两个视图。
  • Mac 发起、iPhone 查看、回到 Mac 继续。
  • 断线重连和状态收敛。
  • 通知与未读状态。

验收：切换设备不产生重复任务和历史分叉。

P6

子 Agent 与并行开发

核心 Coding 闭环之后

F6.1 通用子 Agent

不是固定 Researcher/Reviewer，而是由任务动态定义。
  • 任意 Profile、目标和工具子集。
  • 前台与后台任务。
  • 结果、证据、未解决项和预算。

验收：用户可定义“迁移模块”“补测试”“调查构建失败”等任意子任务。

F6.2 隔离 Workspace

并行修改不互相污染。
  • 独立分支或工作树。
  • 文件所有权与冲突提示。
  • 显式合并和审阅。

验收：两个子 Agent 并行修改后，主 Agent 能安全审阅并合并。

F6.3 跨端子 Agent 可视化

用户能看见每个子任务的进展和影响范围。
  • TUI 树状任务视图。
  • iOS 任务摘要与通知。
  • 停止、继续和查看子任务。

验收：并行任务不隐藏失败，不混淆父子上下文。

P7

生产加固

发布前阶段

F7.1 可观测性

问题可定位、成本可解释。
  • 模型、工具、审批、测试和失败 Trace。
  • Token、耗时、重试和成本统计。
  • 隐私安全的诊断导出。

验收：任何失败任务都有足够证据定位是模型、工具、环境还是用户中断。

F7.2 质量评测

持续衡量真实 Coding 能力。
  • 多语言仓库任务集。
  • Bug 修复、测试补齐、重构和大仓库检索。
  • 误完成率、恢复率、成本和安全回归。

验收：每次发布都有可比较的质量报告。

F7.3 发布与升级

Mac、浏览器、iOS 三端持续可用。
  • 版本兼容和 Session 迁移。
  • 签名、公证、安装和回滚。
  • 服务端连接与 iOS 审核要求。

验收：升级不丢 Session，旧版本客户端有明确兼容策略。

F7.4 性能与体验

大型仓库仍保持响应。
  • 启动、搜索、索引、流式渲染和大 diff 性能。
  • 低资源模式。
  • 终端无障碍和不同屏幕尺寸。

验收：大型仓库操作不阻塞输入，内存和 CPU 有明确上限。

6. 成功指标

可靠性

任务中断恢复成功；崩溃后无重复危险操作；测试失败不会误报完成。

开发效率

常见修复任务减少人工复制、切窗和手动测试次数；从输入到首个可见动作时间稳定。

质量

内置评测上的任务完成率、测试通过率、回归率、误改率和平均修复轮次持续改善。

跨端

Mac→iOS→Chrome 连续会话无分叉；断网重连后状态一致。

安全

无越界文件访问；无未请求网络；无未确认破坏性操作；密钥不进入日志。

体验

长任务可中断、可恢复、可审阅；用户不必阅读原始内部日志才能判断状态。

建议下一开发顺序：P1.1 交互式 TUI + P1.3 会话恢复 + P2.2 精确编辑 + P2.3 测试修复闭环。完成这四项后，才值得把体验扩展到 iOS。

明确非目标

  • Linux/Windows 原生客户端。
  • 企业级 RBAC、复杂审批矩阵和合规工作流。
  • iOS 本地执行任意代码。
  • 默认自动 commit、push 或发布。
  • 为并行而并行的大规模 Agent 集群。
