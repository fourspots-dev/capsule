PortableGitBackend
纯 TS 常用 Git 语义与格式兼容

PortableGitBackend 是 tinyai 的默认 Git 后端，建立在 WorkspaceFileSystem 之上，不要求宿主安装 git。它实现 Agent 必需的常用本地 Git 子集，并读写 Git-compatible objects、refs、index 和 HEAD；CLI 后端仅作为可选加速与高级兼容性校验。

1. 目标与定位

默认后端

  • Browser、iOS、Node、Sandbox 都默认使用 PortableGitBackend。
  • Agent 的工具 Schema 和行为不随宿主改变。
  • 宿主没有 git binary 是正常状态，不是降级错误。

CLI 定位

  • 可选后端，不是运行前提。
  • 用于高级命令、真实 Git 兼容性校验和性能对照。
  • CLI 不可用时不得影响常用本地 Git 子集。
PortableGitBackend 不追求实现全部 Git，而是让 Agent 完成“查看状态、比较、暂存、提交、查看历史、切分支”等常用本地工作，并保证生成结果能被标准 Git 读取。

6. Git-compatible 文件格式

.git/
  HEAD
  refs/heads/*
  refs/tags/*
  packed-refs
  objects/ab/cdef...
  objects/pack/*.idx
  objects/pack/*.pack
  index
  config.sanitized
  .gitignore
  .gitattributes

Object

  • 对象头为 <type> <size>\0<content>，SHA-1 OID，loose object 使用 zlib。
  • 读取 pack v2 常见 object 与 OFS_DELTA/REF_DELTA；写入 loose objects，标准 Git 可直接读取。
  • 对象解码后必须重新计算 OID；不允许自定义对象格式冒充 Git。

Refs 与 Index

  • 支持 HEAD、loose refs、packed-refs；ref 使用 staging + rename 写入。
  • Index 读取 v2/v3/v4，写入 canonical v2；保持 path 字节、mode、OID、stage 与 flags。
  • stat cache 是可刷新 hint，正确性以 OID 和 worktree content hash 为准。
Git-compatible 不等于复用宿主 Git。Portable 必须自己解析和写入这些格式；CLI 只用于外部互操作验证。

7. 命令语义

命令v1 行为关键边界
init创建 HEAD、objects、refs；默认 branch 可配置已有 repo 不覆盖；不执行 template/hooks
status比较 HEAD tree、Index、worktree 和 ignore区分 staged/unstaged/untracked/ignored
add写 blob、tree 所需 objects，更新 index不自动 resolve conflict；路径必须 WorkspacePath
commit根据 index 生成 tree/commit，移动 HEAD/refmessage 必填；空 commit 默认拒绝；不执行 hooks
log从 HEAD/ref 遍历 parents；支持 max count不依赖 reflog；不可达历史不伪造
showcommit/tree/blob/tag 的结构化内容大内容 Artifact 化
diffworktree/index/HEAD/commit 比较二进制、rename、截断显式
branchlist/create/delete safe branch当前分支删除拒绝
checkout切 branch/commit，更新 worktree/index有覆盖风险时拒绝；不做 merge
rev-parseHEAD、branch、短 OID、tag 解析歧义明确失败

8. Status、Index 与 Ignore

HEAD tree
  | compare oid
  v
Git Index -- compare oid/content hash --> Working Tree
  |                                           |
  +-- staged                                  +-- unstaged
  +-- untracked/ignored via .gitignore        +-- deleted

Result:
  staged[] | unstaged[] | untracked[] | ignored[] | conflicted[]
  • 不依赖 Index stat cache 判定内容变化；必要时读取文件并计算 blob OID。
  • 忽略规则支持常见 `.gitignore` 语法和目录规则；无法解析的 pattern 明确提示。
  • 文件换行保持字节；Portable 不自动应用 core.autocrlf、smudge/clean filter。
  • rename 默认通过 diff 检测，不改变工作树文件。

9. 安全、并发与原子性

锁

Index/ref 写入使用 Workspace 内 lock + staging + rename；超时和崩溃后可清理。

Hooks

不执行任何 hook、filter、external diff 或 textconv，避免 Capsule 成为代码执行入口。

对象校验

解码后重新计算 OID，拒绝 hash 不符、循环 delta、越界长度和过大对象。

Checkout

覆盖未保存修改时拒绝；先完成可验证 staging，再原子替换 worktree/index。

路径

Tree/index path 必须是 WorkspacePath；拒绝绝对路径、盘符、NUL、重复规范化路径。

凭据

v1 不实现 remote push/pull；config 中 URL 凭据必须移除或拒绝导入。

14. 确认项与完成定义

DECISION-01

PortableGitBackend 是 Browser/iOS/Node/Sandbox 的默认 Git 后端。

DECISION-02

实现 common local Git 子集，不追求完整远端、merge/rebase/submodule 递归。

DECISION-03

写入 Git-compatible loose objects、refs、HEAD 和 Index v2，真实 Git 可读取。

DECISION-04

CLI 后端仅可选，用于高级操作、性能和兼容性对照。

维度完成标准
无宿主依赖Browser/iOS JS 环境无 git/node process 仍通过 common subset 测试
格式标准 Git 可读取 Portable 生成的 objects/refs/index
读取兼容Portable 可读取常见真实 clean/dirty Git repo
语义status/diff/log/show/add/commit/branch/checkout 通过 CLI oracle
安全不执行 hooks/filter/远端凭据；恶意 pack/index fail closed
迁移repository partition 在同一 Capsule 中可恢复
诊断所有不支持项有稳定 limitations，不静默降级
