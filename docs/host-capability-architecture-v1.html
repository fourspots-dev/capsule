REQ-HOST-001 / HOST CAPABILITY + CODING WORKSPACE / DESIGN V1

宿主能力与 Coding Workspace
统一架构设计

把文件、应用动作、Git、交互会话、网络与密钥拆成可探测、可组合、可替换的宿主端口；TUI、Chrome、CLI、Sandbox 和未来客户端通过同一套能力语义装配工具，而不是各自维护一套实现。通用 shell/Python/二进制执行不是基线能力。

1. 当前实现与问题

已有 HostBridge

声明了 storage、workspace import/export、terminal、process、pty、network、clock、scheduler、crypto、clone 等能力；Memory/Node/Chrome 有部分实现。

文件系统未进入能力模型

TUI host 模式通过独立的 NodeHostFileSystem 注入真实文件系统，但 HostCapability 没有 filesystem。

应用动作尚未建模

TUI 的 exec 仍走 VirtualShell，Sandbox 则通过通用进程桥运行命令；两者都没有把应用提供的具名能力注册为可发现 Action。

Git/测试仍依赖底层执行

Sandbox 可以通过通用 exec 运行 Git/测试，TUI 不能；GitToolPack、测试动作和证据语义还没有统一。

能力声明不等于可用

目前 capability 只检查桥是否存在，没有探针、版本、降级原因或限制集合。

宿主知识可能泄漏

不同组合根直接决定工具，缺少统一的 Capability Graph；未来客户端容易复制宿主判断。

本设计不要求所有宿主提供全部能力，而要求每个宿主准确声明、探测并组合自己真正支持的能力；缺失能力必须显式降级。

非目标

  • 不抽象所有操作系统 API，不实现通用虚拟机。
  • 不要求浏览器宿主提供 Node 或 Bash。
  • 不要求所有 Git 高级能力；以 common local Git 子集为基线。
  • 不把 UI 布局、审批卡样式或 Chrome Tab 语义放进 Host Port。
本设计不内置通用 exec、Python、Node、Bash 或任意二进制运行器。嵌入应用需要什么能力，就注册对应的具名 Action；Agent 只看到经过声明的动作及其 JSON Schema。

3. 设计原则

窄端口

Host 只提供事实和副作用原语，不包含 Patch、Git merge、测试策略等 Agent 业务。

探测优先

声明只是意图，Probe 结果才决定工具是否可用。

组合优先

能力图谱生成 ToolPack，客户端类型不参与业务分支。

显式降级

缺失执行能力时保留可用的文件/Patch，但明确禁用真实测试和 Git。

真实证据

没有 ExecutionResult/TestReport/Projection 证据，不允许声称命令或测试成功。

可移植回退

Memory/Virtual 实现必须存在，支撑浏览器、测试和离线环境。

5. Capability 模型

type CapabilityState = 'available' | 'degraded' | 'unavailable';

interface CapabilityDescriptor {
  id: string;
  version: number;
  state: CapabilityState;
  limitations?: string[];
  probe(): Promise<CapabilityProbeResult>;
}

interface CapabilityProbeResult {
  state: CapabilityState;
  reason?: string;
  details?: JsonValue;
  latencyMs?: number;
}

能力 ID

storage、filesystem、actions、interactiveActions、git、testEvidence、search、watch、network、secrets、terminal、browser、clock、scheduler、crypto、clone。具体应用动作使用稳定子 ID，如 actions:app.python.run-tests。

状态示例工具行为
availableFS + 应用动作 Probe 成功注册基础 Workspace ToolPack 和声明过的具体动作
degradedFS 可写但没有应用测试动作注册 read/write/patch；Git 使用 Portable 子集；不出现 run_tests
unavailable没有网络或秘密不注册对应工具；Prompt 中明确不存在
Capability Probe 必须实际调用端口的最小操作，不能只检查字段存在。应用动作 Probe 应验证 Provider 的 schema/health/version；git probe 使用 CLI 自检或 portable backend self-check。

6. 核心端口

6.1 StoragePort / 基础端口

interface StoragePort {
  get(key: string): Promise<unknown>;
  set(key: string, value: unknown): Promise<void>;
  remove(key: string): Promise<void>;
  list(prefix?: string): Promise<string[]>;
}

interface ClockPort { now(): number; setTimeout(...): unknown; clearTimeout(...): void; }
interface CryptoPort { digest(algorithm: 'SHA-256', data: Uint8Array): Promise<Uint8Array>; randomBytes?(n: number): Uint8Array; }

6.2 FileSystemPort

interface FileSystemPort {
  stat(path: string, signal?: AbortSignal): Promise<FileInfo | undefined>;
  list(path: string, options?: ListOptions): Promise<FileInfo[]>;
  read(path: string, options?: ReadOptions): Promise<Uint8Array>;
  writeAtomic(path: string, data: Uint8Array, options?: WriteOptions): Promise<FileInfo>;
  mkdir(path: string, options?: { recursive?: boolean }): Promise<void>;
  rename(from: string, to: string): Promise<void>;
  remove(path: string, options?: { recursive?: boolean }): Promise<boolean>;
  watch?(path: string, listener: FileWatchListener): () => void;
}
  • 所有路径为 Workspace 相对路径；Adapter 负责 realpath/根目录检查。
  • FileInfo 包含 kind、size、mode、version/hash、modifiedAt、symlink metadata。
  • Patch 使用 expectedVersion/expectedHash；不支持版本时 Adapter 提供内容 hash。
  • 大文件读取支持 offset/limit；写入默认原子。

6.3 ActionProviderPort

interface ActionProviderPort {
  describe(): Promise<HostActionDescriptor[]>;
  invoke(
    actionId: string,
    input: JsonValue,
    context: ActionContext
  ): Promise<ActionResult>;
}

interface HostActionDescriptor {
  id: string;                    // app.python.run-tests
  version: string;
  title: string;
  description: string;
  inputSchema: JsonValue;
  outputSchema?: JsonValue;
  effects: Array<'read' | 'write' | 'execute' | 'network'>;
  risk: 'read' | 'write' | 'dangerous';
  limitations?: string[];
  probe(): Promise<CapabilityProbeResult>;
}
  • 每个动作拥有稳定命名空间和独立版本；冲突、Schema 不合法或 Probe 失败的动作不会注册。
  • Agent 看到的是具体动作工具，例如 app_python_run_tests，而不是通用 exec。
  • 应用可以在内部实现 Python、Xcode、浏览器、云 API 或本地进程调用，但这些实现细节不进入 Core。
  • 如需通用命令能力，宿主可显式注册 local.exec.argv；它是可选高风险动作，不是 tinyai 内置工具。
  • 动作结果可以流式返回，也可以通过 Artifact 引用大输出。

6.4 InteractiveActionPort

interface InteractiveActionPort {
  open(
    actionId: string,
    input: JsonValue,
    context: ActionContext
  ): Promise<InteractiveSession>;
}

交互动作适用于应用需要长期会话的特定能力，例如调试器、终端或远程进程。它不是通用 PTY 基线；没有注册动作时对应工具不出现。

6.5 NetworkPort / SecretPort

interface NetworkPort {
  request(request: NetworkRequest): Promise<NetworkResponse>;
  stream?(request: NetworkRequest): AsyncIterable<Uint8Array>;
}

interface SecretPort {
  get(scope: SecretScope, name: string): Promise<SecretLease>;
}
  • Network 由 PolicyEngine 或 Adapter 强制 allowlist；模型 API 也应通过可替换 transport。
  • Secret 只允许按名称/scope 获取，不可 list，不可持久化，使用后撤销。

6.6 Workspace 迁移边界

本需求不定义 Capsule 内部语义，只定义 Host 与 Workspace Continuity 之间的窄连接。配套设计见 REQ-WORKSPACE-001。

interface HostBlobTransferPort {
  openImport?(): Promise<ReadableBinary | undefined>;
  openExport?(meta: {
    suggestedName: string;
    contentLength?: number;
  }): Promise<WritableBinary>;
}
Host 契约修正后的语义
workspace.import/export仅表示不透明 Capsule bytes 的输入/输出；Host 不解析 Project、Session、Git 或 Artifact
FileSystemPort所有模型可见路径为 WorkspacePath；Adapter 提供 content hash、symlink/lstat 语义、case/Unicode probe，并以 barrier 支持一致读取
ActionProviderPort动作使用具名 ID 和 JSON Schema；Context 只含授权的 WorkspacePath/scope；不向模型暴露 PID、二进制路径或宿主环境
Git/Test结果路径使用 WorkspacePath；Git repository/index 与 TestReport 可被 Continuity Service 分区导出，证据绑定文件 hash 和环境指纹
PTY/Network/Secret均为 ephemeral 或不可转移能力；导出屏障负责终止/记录，导入后重新 Probe/获取
HostDescriptor.platform只供 Adapter 诊断，Core、Prompt、ToolPack 不据此分支
Host 不提供“导出整个 Agent 状态”这样的高层方法。Capsule 的分区选择、引用闭包、状态对账、原子激活和环境证据失效由 Workspace Continuity Service 统一负责。

8.1 Git 后端

interface GitBackend {
  kind: 'cli' | 'portable' | 'virtual';
  status(workspace: WorkspaceRef, signal?: AbortSignal): Promise<GitStatus>;
  diff(workspace: WorkspaceRef, spec: DiffSpec, signal?: AbortSignal): Promise<GitDiff>;
  stage(workspace: WorkspaceRef, paths: string[], signal?: AbortSignal): Promise<void>;
  commit(workspace: WorkspaceRef, input: CommitInput, signal?: AbortSignal): Promise<GitCommit>;
  show(...): Promise<GitObject>;
}
  • PortableGitBackend 是默认实现，直接读写 Git-compatible objects/refs/HEAD/index，不依赖 Git binary。
  • CliGitBackend 仅作为显式注册的高级操作和 real-Git conformance oracle。
  • UI 看到的 Git 工具语义相同；无 Git binary 是正常 Portable Profile，不是降级错误。

详细契约见 REQ-GIT-001。

8.2 TestEvidence

interface TestDiscovery {
  discover(workspace: WorkspaceRef, signal?: AbortSignal): Promise<TestPlan[]>;
}

interface TestRunner {
  run(plan: TestPlan, signal?: AbortSignal): Promise<TestReport>;
}

默认没有通用 TestRunner。应用可以注册 app.*.run_tests 动作，返回标准 TestReport；Core 负责校验 actionId、版本、文件 hash、environment fingerprint 和报告。没有测试动作时不可用，不能返回伪通过。

      → GitBackend.status
      → GitStatus

Application test action unavailable
  → run_tests not registered

11. 失败、取消与降级

场景行为
Probe 失败Capability 标记 unavailable/degraded，禁止对应 ToolPack，记录诊断
动作超时AbortSignal → Provider.cancel → 应用回收内部资源 → ACTION_TIMEOUT
输出超限保留尾部/摘要，完整输出进入 Artifact，工具结果标记 truncated
文件版本变化Patch 返回 PATCH_STALE_FILE，要求重读，不覆盖
Git binary 缺失降级 Portable Git 或明确禁用 Git 写操作
应用动作失败保留结构化错误/退出状态，不标记 completed
Session 取消取消模型、应用动作、交互会话、网络、Git 和子 Agent
宿主断开Session 保留最后确认状态；恢复前重新 probe 能力
禁止把“文件已写”当成“项目可运行”，也不允许在没有应用测试动作返回的 TestReport 时由模型自行宣布测试通过。

12. 安全边界

路径

FileSystemPort 必须限制 Workspace root；realpath、symlink 和 rename target 均需检查。

动作

使用具名 actionId 和 JSON Schema；不内置 raw shell。宿主自行注册通用命令动作时必须声明高风险和完整执行限制。

网络

默认拒绝；通过 allowlist proxy 或 Host NetworkPolicy；DNS/IP rebinding 防护。

秘密

SecretLease 短时有效，不进入 Prompt、Session、日志和 Artifact。

审批

按能力、路径、命令、网络和写入范围评估，不只按工具名。

应用动作

稳定 actionId、输入/输出 Schema、effects、timeout、取消和版本；底层进程由应用自行收口。

13. 分阶段实施

M1

能力模型与端口骨架

  • 新增 CapabilityRegistry、probe、版本、限制与诊断。
  • 正式定义 FileSystemPort、ActionProviderPort；保持现有接口适配。
  • 建立 Portable Profile 与契约测试。
M2

TUI Local Coding

  • 启用 Node FS 和 Portable Workspace 工具。
  • 增加应用 Action Provider；测试、构建或本地命令由嵌入应用按需注册。
  • 实现 PortableGitBackend 作为默认 Git，CLI 仅可选注册。
  • 保留 virtual profile 作为 fallback。
M3

ToolPack 统一

  • Patch/Search/Git/Test 全部由 Capability Graph 注册。
  • Sandbox、TUI、Chrome 使用同一 ToolPack 描述。
  • UI/Prompt 显示 degraded reason。
M4

PTY、Secret、Network

  • PTY session 生命周期和取消。
  • SecretLease 与网络 allowlist。
  • Soak、恶意命令和网络故障测试。
M5

跨端与未来客户端

  • Remote/Web 使用 Headless Profile。
  • Capability report 进入 client protocol。
  • 完成端无关工具可见性和审阅。

14. 确认项与完成定义

DECISION-01

是否接受“Host 提供原始端口，Git/Test 通过 ToolPack 组合”的分层？

DECISION-02

是否接受 TUI 默认 Local Coding，并保留 Portable Virtual 作为显式 fallback？

DECISION-03

PortableGitBackend 是否作为默认 Git 实现，CLI 仅作为可选高级后端？

DECISION-04

是否接受应用注册具名 Action 作为基线，不内置通用 exec/Python/Bash？

维度完成标准
能力所有 capability 有 probe、版本、状态、限制和诊断。
文件FileSystemPort 契约在 Memory/Node/Sandbox/Chrome 适配器通过。
应用动作宿主注册的动作可发现、可调用、可取消、可诊断；通用 exec 不是默认工具。
Git/TestPortableGitBackend 无需 CLI；测试执行必须来自应用 Action；不支持项明确诊断。
隔离Core 不出现 Chrome/Node/TUI 分支；Capability Graph 驱动工具。
安全路径、命令、网络、秘密和审批边界有测试证据。
恢复宿主断开、重连、取消和 Session 恢复不丢状态。
验证相关测试全部通过并满足 REQ-HOST-001 注册表状态。
最终目标不是“所有宿主功能一样多”，而是“能力差异被准确描述，工具组合可预测，缺失能力不会伪装为成功”。Workspace 能否跨宿主继续由独立 Capsule 层定义，Host 只负责准确执行和传输。
