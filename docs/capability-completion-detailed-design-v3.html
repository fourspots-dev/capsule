1. 四层架构与总边界

第一层：Host Backend
  Storage、FileSystem、Clock、Scheduler、Crypto、
  Network、Secret、Browser、Native Bridge
                    ↓
第二层：Portable Runtime
  Workspace VFS、Patch、Search、Diff、Portable Git、
  Session、Artifact、Capsule
                    ↓
第三层：Application Actions
  Python tests、Xcode build、Playwright、
  DB migration、部署等具体应用能力
                    ↓
第四层：ToolPack
  Agent 实际看到的工具、Prompt、Risk、Approval

Host 底座

提供资源访问、系统副作用和安全边界；不能由 Application Action 代理。

Portable 语义

由 tinyai 包内实现，不依赖宿主是否安装 Git、Node 或 Python。

Action 叶子能力

只承接具体应用注册的真实操作，不是新的基础设施层。

ToolPack 是模型视角的组合层，不是第四种底层实现：它从 Host Ports、Portable Runtime 和 Application Actions 组装工具、Prompt、Risk 与 Approval。
本设计仍不提供通用 exec。设计批准不等于实现授权；当前所有章节状态为 Review。

接口

type BaselineTier = 'core' | 'workspace' | 'portable-coding' | 'real-execution';
type CapabilityState = 'available' | 'degraded' | 'unavailable';

interface HostBaselineProfile {
  id: 'tui-local' | 'chrome' | 'ios' | 'sandbox' | 'memory';
  requiredTiers: BaselineTier[];
  allowedOptional: HostCapability[];
  forbiddenAsAction: HostCapability[];
}

interface BaselineProbeReport {
  profileId: string;
  tierState: Record<BaselineTier, CapabilityState>;
  capabilities: ProbedHostCapability[];
  diagnostics: Array<{ code: string; capability: string; message: string }>;
}

Baseline

CoreStorage、Clock、Scheduler、Crypto
WorkspaceFileSystemPort，或 Storage-backed PersistentVFS；WorkspacePath 和迁移 BlobTransport
Portable Coding包内 VFS/Patch/Search/Git/Session/Artifact/Capsule
Real Execution至少一个 Action/Native/Remote Provider；缺失则明确 degraded

流程与失败

load profile
  → probe host ports
  → validate forbidden action substitutions
  → resolve required tiers
  → compute optional action availability
  → startup failure if Core/Workspace missing
  → degraded if only execution missing

错误：HOST_BASELINE_MISSING、HOST_PROFILE_UNKNOWN、HOST_ACTION_SUBSTITUTION_FORBIDDEN、HOST_PROFILE_INCOMPATIBLE。TUI Local、Chrome、iOS、Sandbox、Memory 的 required/optional matrix 由单一 profile 数据表生成。

验收

  • FileSystem 正式进入 capability/probe。
  • 无 Action 时 Portable Coding 仍可用。
  • 无 Process/Action 不会被误判为 Core 失败。
  • Action 不能提供 Storage/FS/Clock/Session。

实现证据

src/host/profile-matrix.ts、src/host/baseline.ts、src/host/types.ts；启动接入 TUI、Headless 与 Chrome。证据：tests/host/host-baseline.test.ts、tests/node/node-host.test.ts，并通过 npm run check 与 Chrome E2E。

核心接口

interface ActionProviderModule {
  apiVersion: 1;
  id: string;
  create(context: ProviderHostContext): Promise<HostActionProvider>;
}

interface HostActionDescriptor {
  id: string;
  version: string;
  inputSchema: JsonValue;
  outputSchema?: JsonValue;
  effects: Array<'read'|'write'|'execute'|'network'>;
  risk: 'read'|'write'|'dangerous';
  timeoutMs?: number;
  workspaceBinding: 'root'|'fork'|'remote';
  probe(): Promise<ActionProbe>;
}

interface HostActionProvider {
  describe(signal?: AbortSignal): Promise<HostActionDescriptor[]>;
  invoke(actionId: string, input: JsonValue, context: ActionContext): Promise<ActionResult>;
  cancel?(requestId: string): Promise<void>;
  dispose?(): Promise<void>;
}

状态机

registered → discovering → probing
  → available | degraded | unavailable
available → requested → authorized → running
  → succeeded | failed | cancelled | unknown
unavailable -X→ requested
denied → terminal for this request
host/generation/version change → rediscover

本地调用序列

Model tool call
→ schema validation
→ policy
→ approval ticket
→ ActionInvoker
→ LocalExecutor spawn(argv)
→ stream/log + artifact
→ ActionResult
→ ToolResult / Session row

TestReport conversion and current/stale evidence lifecycle:
→ REQ-TEST-001

信任

Provider module 必须来自 embedded host、absolute allowlist 或 configured remote endpoint。Workspace 内代码默认不可加载。Loader 校验 realpath、文件 hash、apiVersion、Provider ID 和允许的 Action ID。

错误

ACTION_UNAVAILABLE、ACTION_INPUT_INVALID、ACTION_APPROVAL_DENIED、ACTION_TIMEOUT、ACTION_CANCELLED、ACTION_PROVIDER_CRASHED、ACTION_RESULT_INVALID、ACTION_VERSION_MISMATCH。

验收

  • Provider 生命周期幂等。
  • Local/Remote/Native 同 Schema。
  • ask/auto/deny 生效。
  • 没有 Action 或 denied 时无 exec 回退。
  • 进程树和输出资源可回收。

实现证据

src/platform/host-action.ts、src/node/actions/trusted-module-loader.ts、local-action-executor.ts、src/adapters/remote-action-provider.ts、host-action-tools.ts 和 TUI approval overlay。证据：tests/action/*、tests/platform/host-action.test.ts、tests/tui/app.test.ts、npm run verify:tui。

接口

interface TestReport {
  runner: string;
  total: number;
  passed: number;
  failed: number;
  skipped: number;
  failures: FailureCase[];
  fileHashes: Record<string,string>;
  environmentId: string;
  action: { id: string; version: string };
}

interface EvidenceRecord {
  id: string;
  workspaceGeneration: number;
  taskId: string;
  status: 'current'|'stale'|'failed'|'invalid';
  report: TestReport;
  artifactIds: string[];
}

计算规则

current =
  action succeeded
  AND report valid
  AND total > 0
  AND every fileHash matches
  AND environmentId matches
  AND action/version matches
  AND report occurred after last write
  AND workspace generation matches

任一 mismatch 分别转 stale/failed/invalid；Verifier 只有 current 才放行 completed。

验收

  • 0 tests 不通过。
  • 报告计数闭合。
  • 环境/文件/版本变化产生 stale。
  • TUI 显示失败用例 Artifact。
  • Capsule 导入环境变化旧证据失效。

实现证据

src/core/test-report.ts、evidence-store.ts、src/evidence/test-evidence.ts、test-discovery.ts、Host/Chrome evidence stores。证据：tests/evidence/*、真实 TUI 完成门禁和 Capsule 导入验证。

8. REQ-SUBAGENT-001：Action Isolation

interface ForkWorkspaceRef {
  workspaceId: string;
  generation: number;
  parentGeneration: number;
  contentHash: string;
  binding: 'fork';
}

Action call allowed if:
  descriptor.workspaceBinding contains child binding
  AND child generation hash matches provider input
  AND evidence is emitted under child session/task

合并流程

child finishes
→ child Evidence current
→ parent changes detected by fork base hashes
→ conflict preview
→ apply child changes
→ new parent generation
→ child evidence becomes historical; parent verifier reruns as configured

root-only Action 在 child tool set 中不存在。Remote Action 必须携带 child workspace ID/generation。取消父 Task 会取消所有 child requests/processes/artifacts。

验收

  • 并行 child 不串文件、Action、证据。
  • 父修改导致冲突。
  • merge 只接受 child 最终 diff 证据。
  • 取消后无资源残留。

实现证据

Action ToolPack 支持 per-invocation Session/Workspace binding；root-only Action 在 child 被拒绝，审批后 generation 改变会使批准失效，ChildResult 回传自己的 Artifact/Evidence ID。证据：tests/platform/host-action.test.ts、tests/evidence/action-evidence-integration.test.ts、tests/adapters/workspace-subagent-driver.test.ts。

9. REQ-CHROME-001：Chrome Composition

Target 0.10.0 Verified

模块

修改runtime/chrome-runtime.ts、Chrome Browser Provider registration、Capsule UI、RemoteActionProvider
不得感知src/node/actions/*、本地绝对路径、Node child_process
Chrome composition:
  ChromeHostBridge
  → baseline probe
  → WorkspaceCapabilityComposition(profile=browser)
  → BrowserToolPack (optional)
  → RemoteActionProvider (optional)
  → Capsule import/export UI

No Action:
  Portable Coding available
  exec unavailable
  TestEvidence unavailable

Remote provider 接受允许的 action IDs，workspace ID/generation，requestId，deadline；流事件和取消协议与 Action Runtime 保持一致。Browser DOM 工具不混入通用 Coding ToolPack。

Tab discovery 只在当前 Workspace/Session 内搜索；没有匹配项是正常的 { found: false } 结果，不是工具故障。Provider 的 Session 绑定属于可重建缓存：Runtime 或 service worker 恢复后，添加新标签时从持久化的 Session 基准标签惰性恢复，不能把内部缓存缺失暴露成 BROWSER_SESSION_NOT_FOUND。Chrome 尚未提交导航时使用 pendingUrl 生成稳定标签描述。

Settings interaction

设置首页只展示“Capabilities”和“Remote Actions”紧凑入口，并沿用现有设置行的无边框、分组卡片和行高。能力详情进入独立子页展示探测状态、证据与最近调用结果；Remote Action 配置进入独立表单子页，复用模型连接编辑页的字段、按钮和焦点样式。两个子页均先返回 Settings，再由 Settings 返回会话，避免新增页面形成独立的视觉与导航体系。

验收

  • TUI/Headless/Chrome Tool Golden 一致。
  • Chrome 不出现 exec/job。
  • Remote disconnect 不假完成。
  • Capsule UI 恢复 Session。

实现证据

chrome-runtime.ts 先探测 Host 与 Remote Action，再以 profile=portable 构建共享 Coding ToolPack；Browser ToolPack、主 Runtime 与子 Agent Runtime 保持分离。Runtime Gateway 只暴露可序列化的能力快照、当前 Session 最近 Action 结果、Capsule 字节和导入结果，Side Panel 不读取 Workspace 或 Provider 内部状态。证据：tests/integration/runtime-gateway.test.ts、tests/runtime/workspace-capability-composition.test.ts、tests/action/remote-provider.test.ts、tests/e2e/kernel-extension.e2e.ts。
