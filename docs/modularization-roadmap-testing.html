TINYAI / MODULARIZATION / TEST PLAN

模块化完善测试方案

验证 7 项模块化工作的契约、兼容性、跨端隔离和组合行为。测试不仅验证“功能可用”，还要证明各模块确实可以替换，且浏览器实现没有重新泄漏到 Core。

7工作项
60+建议用例
5测试层级
1跨端门禁
层级WorkspaceBrowser拆分ToolPackPromptTUI组合根门禁

1. 测试层级

Contract

同一个接口分别运行 Chrome、TUI、Fake 实现，验证行为契约一致。

Unit

Workspace 状态机、ToolPack 注册、Prompt 生成、Factory 分支。

Integration

SessionAccess、RuntimeExtension、ToolRegistry、Subagent、Gateway 组合。

Boundary

tsconfig.core、import scanner、构建产物扫描，防止 Chrome 依赖回流。

Chrome E2E

标签组、Browser ToolPack、Side Panel、审批和真实 Tab 行为。

Golden / Snapshot

Session Snapshot、Prompt、Tool schema 和 Projection 兼容。

8. 发布门禁

门禁必须通过
Core boundarytsconfig.core + import scanner + Core 测试
Chrome regression标签组、组外独立、审批、清理、Runtime 重建 E2E
TUI smoke独立启动、文件/Exec 工具、单 Terminal Workspace、无 Browser 依赖
Contract所有 Workspace/ToolPack/Prompt 实现通过共享契约套件
Migrationv1 binding、旧 Session Snapshot、旧 ToolPack 装配可兼容或明确拒绝
Resources无 Debugger、PTY、MCP、tab 和 timer 泄漏

建议执行顺序

1. Contract + Unit
2. Core boundary and dependency scanner
3. Runtime integration
4. Chrome E2E
5. TUI smoke
6. migration/resource soak
如果 Core 测试依赖 Chrome 类型、ToolPack 测试必须启动浏览器、或 TUI 构建出现 BrowserProvider，任一出现都应阻断发布。

完成定义

  • 7 项工作均有显式接口、至少两个实现或一个实现加 Fake。
  • Chrome 和 TUI 可通过不同 ToolPack/Prompt/Workspace 组合启动。
  • Session Snapshot 不包含宿主 UI 字段。
  • 全部确定性测试、Core 边界检查、Chrome E2E 和 TUI smoke 通过。
